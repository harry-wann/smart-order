01 · 先把名稱放回正確位置

名稱角色在本教材裡
Jakarta EE（Jakarta Enterprise Edition，Jakarta 企業版）一組企業 Java 規格使用其中的 Servlet、Persistence、Validation 規格
Tomcat實作 Servlet 等 Web 規格的容器，不是完整 Jakarta EE 平台主線 Boot 4 使用 Tomcat 11
Servlet處理請求／回應的 Java 規格Spring MVC 的 DispatcherServlet 仍建立在它之上
JSP（JavaServer Pages；現稱 Jakarta Server Pages）伺服器產生網頁的技術本教材改回傳資料給前端；JSP 不是必要
Spring Framework提供物件管理、Web 與交易等能力Boot 3.5 使用 Framework 6.2；Boot 4 使用 Framework 7
Spring Boot把相容套件、設定與啟動流程整合主線 Boot 4.1.1，Java 21
截至 2026-09-22 查閱的官方版本索引，沒有列出 Spring Boot 5。Spring Tools 5 是開發工具版本；它支援 Boot 4。Spring Framework 5 則是核心框架的舊版本，三者不可混為一談。

02 · 同一個請求，舊流程怎麼換？

@GetMapping 把 GET 請求對應到方法；@RestController 讓回傳值寫到回應內容。DispatcherServlet 是統一接收請求、再分派到 Controller 的 Servlet；你的 Controller 本身不必繼承 HttpServlet。

請求順序：Tomcat → DispatcherServlet → Controller → Service。HTTP 是 Hypertext Transfer Protocol（超文字傳輸協定），就是這些請求與回應使用的通訊規則。

03 · JSP 與資料 API 的差別

record 是 Java 的簡潔資料型別，會自動提供建構子與讀取方法。回傳物件由 Jackson（物件與 JSON 互轉的套件）轉成資料。JSON 是 JavaScript Object Notation（JavaScript 物件表示法）；這裡的內容是 {"id":1,"productName":"Chai"}。

API 是 Application Programming Interface（應用程式介面）。JSP 路線由伺服器產生畫面；資料 API 路線由前端拿資料後決定怎麼顯示。Spring MVC 仍可回傳頁面，並不等於只能做 API。

Boot 搭配 JSP 有封裝限制：不要把傳統 JSP 專案直接當作可執行 JAR 使用。要沿用 JSP 時需確認 WAR 封裝與容器支援；本教材使用 JSON API。

04 · 一個 main 方法如何啟動？

@SpringBootApplication 結合設定類別、自動設定與元件掃描。自動設定會依據依賴、設定值與既有 Bean 決定要提供哪些功能；你自行提供對應 Bean 時，部分預設設定會退讓。

同一次啟動會建立 Spring 容器、組裝 Bean 並啟動內嵌 Tomcat。開發時執行 main，部署時可以執行 java -jar；也能另外設定成傳統 WAR 部署。

05 · 主線 Boot 4／Boot 3 對照

項目主線 Boot 4對照 Boot 3.5
Web starterspring-boot-starter-webmvcspring-boot-starter-web
底層Framework 7／Tomcat 11／Servlet 6.1Framework 6.2／Tomcat 10.1／Servlet 6.0
JSON 工具預設 Jackson 3；ObjectMapper 在 tools.jackson.databindJackson 2；ObjectMapper 在 com.fasterxml.jackson.databind
Persistence 與 Servlet importsjakarta.persistence／jakarta.servlet同樣是 jakarta.*，不改回 javax.*

本教材讓 Spring 自動轉換 JSON，不需要自己建立 ObjectMapper。Jackson 的部分註解仍保留 com.fasterxml.jackson.annotation，不能盲目全域取代 package。
