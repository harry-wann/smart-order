01 · 先對照 Servlet 的觀念

Authentication（身分驗證）回答「你是誰」；Authorization（授權）回答「你可以做什麼」。Servlet Filter（過濾器）能在請求到 Servlet 前處理它，Spring Security 也是透過過濾器鏈套用身分與安全檢查。

Northwind 的 Employees 是員工資料，不等於可直接登入的帳號表；不能拿 EmployeeID 當密碼。本課安全示例用獨立的練習管理員帳號。

02 · Session 與 Token 都是選項

方式如何維持身分重點
Session（伺服器端登入狀態）瀏覽器帶登入 Cookie，伺服器查狀態延續 Servlet 課的概念，容易撤銷登入
Bearer Token（持有者憑證）請求用 Authorization 標頭帶憑證伺服器必須驗證簽章或查憑證有效性

JWT 是 JSON Web Token（一種 JSON 格式的權杖）；JSON 是 JavaScript Object Notation（JavaScript 物件表示法）。JWT 通常簽章而不加密，內容可被讀取；不是所有 API 都必須使用 JWT。

SecurityFilterChain 是安全過濾器鏈。permitAll 表示可公開存取；hasRole 限制角色；roles("ADMIN") 會建立 ROLE_ADMIN 權限。PasswordEncoder 是密碼編碼介面，BCrypt 是適合密碼的慢速雜湊演算法，不是一般可逆加密。

04 · 別把 403 誤認成 Controller 壞掉

CSRF 是 Cross-Site Request Forgery（跨站請求偽造）。使用 Cookie 維持登入時，瀏覽器可能自動帶上憑證，因此寫入操作需要 CSRF 防護；不要為了讓 POST 通過就直接關掉它。

先在瀏覽器 /login 登入，再用相同 Cookie 請求 /csrf；寫入時在回傳的 headerName 指定標頭填入 token。重點是同一個登入狀態加上有效 token。登入前取得的 token 不應在登入後繼續沿用。

這份 formLogin 設定服務瀏覽器，未登入時可能導向登入頁，而不是一律回 401。正式純資料 API 可以另外設定 AuthenticationEntryPoint（未通過身分驗證時的處理器）統一回應格式。

05 · 面試與實務練習

先說清楚權限在哪裡判斷，再說用什麼憑證。伺服器端一定要檢查角色與資料擁有者；前端隱藏按鈕只影響畫面。查詢別人的訂單，即使已登入也可能不允許。

Boot 3 對照

本例的 SecurityFilterChain 與 Lambda DSL 在 Boot 3.5／4 都可用。DSL 是 Domain-Specific Language（領域專用語法）。更舊的 WebSecurityConfigurerAdapter 不適用此教材；Boot 4 所用 Security 7 進一步要求新的 Lambda 設定方式。
