01 · 看懂新增的 201

沿用單元 06 的新增合約：成功要回 201、商品資料和 Location。ResponseEntity 是可同時指定狀態碼、標頭、本文的回應物件；created(...) 設定 201 與 Location，body(...) 放入商品。URI 是 Uniform Resource Identifier（統一資源識別碼），這裡用來表示新商品路徑。

HTTP 是 Hypertext Transfer Protocol（超文字傳輸協定）。ResponseEntity 可指定回應狀態、標頭與本文；created 產生 201。URI 是 Uniform Resource Identifier（統一資源識別碼），這裡用相對路徑放進 Location，告訴呼叫端新商品的位置。

02 · 完整 Controller

展開完整範例 · ProductController.java
註解呼叫的 Service合約
@GetMappinglist／get200，回資料
@PostMappingcreate201，回資料與 Location
@PutMappingreplace200，五個欄位全部必填
@PatchMappingpatchPrice200，只接受 unitPrice
@DeleteMappingdelete204，沒有本文

ResponseEntity<Void> 表示沒有回應內容。框架會替 GET 提供 HEAD，並處理 OPTIONS，因此不用再複製兩份查詢方法。

03 · 完整例外處理

展開完整範例 · ApiErrors.java

ProblemDetail 提供標準錯誤資料形狀，格式是 application/problem+json。驗證錯誤加上 errors 清單；本課處理的格式錯誤、業務不存在與資料限制衝突都不暴露原始 SQL。

DataIntegrityViolationException 代表資料完整性限制失敗，不只可能是訂單外鍵；因此訊息保留「可能」並請呼叫端確認關聯。未列出的框架錯誤，如錯誤 HTTP 方法的 405，仍依框架預設處理。

04 · 寫入流程再走一次

JSON → @RequestBody 轉成 DTO → @Valid 檢查 → Service 交易 → Repository／Hibernate → SQL Server → DTO → JSON。JSON 是 JavaScript Object Notation（JavaScript 物件表示法）；DTO 是 Data Transfer Object（資料傳輸物件）。

例如輸入 -1 元會在驗證階段停下來；分類不存在會在 Service 被擋下；商品已被訂單引用則會由資料庫拒絕刪除。這三種錯誤發生的層次不一樣。
