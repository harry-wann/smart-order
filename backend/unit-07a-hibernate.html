01 · 一次查詢經過哪些角色

Hibernate 是 ORM（Object–Relational Mapping，物件關聯對映）工具，也是 Jakarta Persistence 的實作。Spring Data JPA 的 Repository 通常透過 EntityManager，交給 Hibernate 產生 SQL，再由 JDBC（Java Database Connectivity，Java 資料庫連線介面）送到 SQL Server。

Spring Data JPA → EntityManager → Hibernate → JDBC → SQL Server。Repository 減少樣板程式；Hibernate 負責映射與追蹤物件，兩者不是同一層。

Boot 3 對照

主線 Boot 4.1.1 管理 Hibernate 7.4.5.Final；Boot 3.5 為 Hibernate 6.6 系列。不要因為看到新版 Hibernate 就另外指定版本覆蓋 Boot。

02 · 先定義交易，再看物件狀態

Transaction（交易）是一起成功或回復的一組資料操作。例如建立訂單和扣庫存，不能只成功其中一半。Commit（提交）表示完成這一組操作；Rollback（回滾）表示取消這組未完成的操作。

@Transactional 表示讓 Spring 在方法執行前後安排交易。這頁先假設由另一個 Spring 管理的物件呼叫這個公開方法；稍後才解釋這個前提為什麼重要。

EntityManager 管理目前載入的資料實體。Persistence Context（持久化上下文）就是它追蹤這些實體與變更的工作範圍，不是整個網站永久共享的資料。

03 · 物件的四種狀態

以下四個詞只是在描述同一個商品物件目前與資料管理環境的關係。先讀例子，再記英文。

狀態Northwind 商品例子
Transient（暫態）new Product()，尚未交給持久化管理
Managed（受管理）在目前持久化環境中查到或 persist 的 Product
Detached（脫離管理）交易相關的管理環境結束或 clear 後留下的物件
Removed（標記移除）呼叫 remove，等待刪除同步到資料庫

Persistence Context（持久化上下文）是追蹤實體的工作範圍，不是整個網站的永久快取。Spring 常把它和一次 Service 交易配合使用。

Spring Bean 的「受容器管理」，與這裡 Product 的 Managed 狀態不同。服務物件可長期由 Spring 管理；商品實體是否受 JPA 管理，要看當下的持久化上下文。

04 · 沒有 save 的更新，為什麼成立？

先有交易、再查商品、最後改單價。下面直接使用前頁介紹的 EntityManager，省去還沒需要的 Optional 和 Lambda 寫法。

em.find 的第一個參數是實體型別，第二個是主鍵值；找不到回 null。本例先用普通 Java 例外表達找不到，單元 08 才把它接到 HTTP 錯誤回應。changePrice 是前頁 Product 完整類別裡的修改方法。

Dirty Checking（變更檢查，常譯髒資料檢查）是 Hibernate 追蹤受管理物件的修改。方法在有效交易中取得 managed 的 Product，改單價後，交易提交前會同步到資料庫，不必再次呼叫 save。

Flush（同步）是把待處理修改送往資料庫，但尚不等於 Commit；之後仍可能回滾。若物件已脫離管理，單純改欄位不會自動寫回。

05 · 理解交易後，再看新增與刪除

使用前頁 Product 的 replace、changePrice 方法。category 是用 em.find(Category.class, 分類編號) 查到、並已確認不為 null 的分類。下列操作各自位於自己的交易方法中，不是依序對同一筆資料全做一次。

persist 是要求保存新實體；remove 是要求刪除受管理實體。兩者仍受交易與資料庫限制約束，例如被訂單引用的商品可能不能刪除。標準 JPQL 沒有一般 INSERT VALUES，新增通常走物件保存。

選讀：很多商品一起更新時，才考慮批次語句

@Modifying 表示這是異動而非查詢；回傳值是影響筆數。批次語句直接改資料庫，不會逐一改好已載入的物件，因此範例先 flush 待處理修改，再 clear（清除持久化上下文）以避免繼續使用舊狀態。單筆修改先採上一節的 managed 物件方式即可。

06 · @Transactional 的邊界

交易讓一組資料異動共同成功或回復。交易通常放在公開的 Service 方法上，由另一個 Spring Bean 呼叫。Spring 透過 Proxy（代理物件，包住原物件並補上交易行為）攔截方法。

在預設代理模式下，若 outer 本來沒有交易，這樣的內部呼叫不會靠註解啟動交易。讓外部呼叫帶 @Transactional 的公開 Service 方法更清楚。預設對 RuntimeException 與 Error 回滾；受檢例外的回滾需求要另外設定。

07 · LAZY 與 N+1

LAZY（延遲載入）表示關聯資料可以等到存取時才查。如果先查一批 N 個商品，再逐筆讀分類，可能額外發生多次查詢，稱為 N+1 問題。同一分類可能被快取重用，因此實際筆數要看紀錄。

FETCH JOIN（擷取關聯的連接）讓關聯一起載入；left 保留沒有分類的商品。不要因此把所有關聯改為 EAGER（立即載入）。一對多集合的 fetch join 搭配分頁容易放大列數，應另行設計；本例只示範多對一分類。

08 · 在 Service 轉成 DTO

open-in-view=false 讓網頁層不依賴持久化環境繼續查資料；在交易內把需要欄位轉成 DTO（Data Transfer Object，資料傳輸物件）。否則關閉環境後再讀 LAZY 關聯，可能發生 LazyInitializationException（延遲載入環境已不可用）。

DDL 是 Data Definition Language（資料定義語言），用來改表格結構。Northwind 已有表格，none 表示不讓 Hibernate 自動建／改表；不是免除映射檢查。正式團隊用版本化的資料庫變更腳本。SQL 日誌適合本機觀察，避免把敏感參數寫進正式紀錄。
