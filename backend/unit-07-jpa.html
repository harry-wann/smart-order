01 · 固定 Northwind 版本，才不會查錯表

本教材使用 Microsoft SQL Server 經典 Northwind。它模擬食品貿易公司的客戶、商品與訂單。不同移植版可能叫 products 或 order_details；這裡固定使用 dbo.Products 與 dbo.[Order Details]。dbo 是 SQL Server 的資料表命名空間，稱為 Schema（結構描述）。

資料表用途／關係
Categories商品分類；CategoryID 是主鍵
Products商品；ProductID 是主鍵，CategoryID 參考分類
Customers客戶；CustomerID 是文字，例如 ALFKI
Orders訂單；CustomerID 參考客戶
[Order Details]訂單明細；OrderID + ProductID 組成複合主鍵

主鍵（Primary Key）用來辨認每一筆資料；外鍵（Foreign Key）讓資料參考另一張表；複合主鍵就是用多個欄位共同辨認。Products 與 Orders 透過訂單明細連接。

後面的新增／更新範例只在你自己準備的練習副本執行。官方安裝腳本含重建物件的動作，不要直接套到正在使用的資料庫。

02 · JPA、Hibernate、Spring Data 分別做什麼

先回想單元 05：我們自己寫 ProductRepository 回傳固定資料。現在把來源換成資料庫，需要解決兩件事：把資料列變成 Java 物件，以及把查詢要求送進資料庫。

名稱全名與用途
JPA歷史全名 Java Persistence API，現行規格稱 Jakarta Persistence；定義 Java 持久化標準。API 是 Application Programming Interface（應用程式介面）
Hibernate ORMORM 是 Object–Relational Mapping（物件關聯對映）；Hibernate 是 JPA 的一種實作
Spring Data JPA在 JPA 上提供 Repository，減少重複資料存取程式
SQLStructured Query Language（結構化查詢語言）；查資料表
JPQLJakarta Persistence Query Language（舊稱 Java Persistence Query Language）；查 Entity 與 Java 屬性

所以「JPA 的 SQL」可能有兩種意思：JPQL，或 JPA 呼叫的原生 SQL。兩者都會教，但不可混用表名與實體名。

Entity（實體）是用來對應資料表的 Java 類別／物件，例如 Product。Persistence（持久化）指把資料保存到資料庫，讓應用關閉後仍可取得。DTO 則描述要傳給呼叫端的資料；兩者的用途不同。

@Entity 表示持久化實體；@Table 指定表；@Column 指定欄位；@Id 指定主鍵。@GeneratedValue 的 IDENTITY 對應資料庫產生編號。BigDecimal 是適合金額的精確十進位型別，Short 對應本例的 smallint 庫存欄位。

@ManyToOne 表示多項商品可以對應同一分類，@JoinColumn 指定外鍵。LAZY（延遲載入）是需要時才可能查關聯資料，下一頁 Hibernate 再觀察實際效果。

04 · 同一需求：SQL 對照 JPQL

查詢方法要放在哪裡？先把單元 05 的固定資料來源換成下面這個 Repository 介面。extends 表示介面繼承；JpaRepository<Product, Integer> 的兩個型別是操作的實體與主鍵型別。Spring Data 會為它提供實作，所以這次不用自己寫查詢類別。

下方 @Query 指定查詢文字，@Param 把方法參數綁到查詢的同名位置；它們分別來自 org.springframework.data.jpa.repository 與 org.springframework.data.repository.query。List<Product> 表示商品清單，需匯入 java.util.List；價格型別 BigDecimal 來自 java.math。三個雙引號是 Java 的 Text Block（多行文字區塊），用來存放查詢文字。

現在只做一件事：「查出未停產、價格至少 20 元的商品，最貴排前面」。SQL 的 SELECT 決定要哪些欄位，FROM 指定資料表，WHERE 篩選列，ORDER BY 排序；DESC 是降冪、ASC 是升冪。

p 是別名；:minimum 是命名參數。使用 @Param 綁定值，不把使用者輸入直接拼接進查詢。SQL 的 bit 欄位以 0／1 表示；Java 的 Boolean 屬性用 false／true。select p 回傳完整 Product 物件，不是只回三個欄位。

在 JPQL 中，@Query 告訴 Spring Data 要使用這段查詢；@Param 把方法的 minimum 參數交給 :minimum。Java 的三個雙引號是 Text Block（多行文字區塊），只用來放查詢文字，不是另一種查詢語言。

05 · 最短的方法名稱查詢

看過 SQL 與 JPQL 後，再看 Spring Data 的簡寫。JpaRepository<Product, Integer> 的兩個型別，分別是要操作的實體、主鍵型別；Spring Data 會提供這個介面的實作，因此不用自己寫每個基本查詢。

Spring Data 解析方法名稱：找出未停產、且價格大於等於 minimum 的商品。它不是 SQL 或 JPQL 字串；適合短條件。條件太長時改用 @Query，閱讀比較清楚。

注意這與單元 05 的手寫 ProductRepository 類別是替代版本，不是要兩個同名型別一起保留。

06 · 篩選、關聯與統計

先練 LIKE 的文字篩選，再看 JOIN 關聯與 GROUP BY 統計，不要四段一起執行。lower 把文字轉成小寫，% 代表任意長度文字；例如 pattern = "%Tea%" 表示名稱包含 Tea。

JOIN 是關聯查詢；GROUP BY 分組；HAVING 篩選分組結果。上述多欄位統計會回傳每列的值組合，可用 Object[] 接收，或改為 DTO 投影（Projection，只選需要的資料）。範例中的 -- 是教材說明；放入 JPQL 時只複製各段查詢本體。

07 · 實際把 JPQL 跑起來

前面的 Repository 已能替你執行查詢。這一節是另一種做法：直接使用 EntityManager（JPA 管理實體與執行查詢的介面）。@PersistenceContext 讓框架把這個管理介面提供給查詢類別，不是自己 new 一個資料庫連線。

EntityManager 是 JPA 管理實體與執行查詢的介面。Product.class 指定結果型別；setFirstResult 是略過筆數，setMaxResults 是上限。綁定參數能防止把輸入當 SQL 指令，但 % 和 _ 在 LIKE 中仍是萬用字元；如果要按字面搜尋它們，需另外跳脫。

08 · 原生 SQL：查 Northwind 訂單總額

下面是報表例子：輸入一張訂單的編號，算出所有明細的合計。這次直接用資料表與欄位，因此設定 nativeQuery=true。

nativeQuery = true 表示原生 SQL，不再是 JPQL。訂單金額要用明細的成交單價，不用 Products 的目前單價。Discount 是折扣比例，例如 0.1 代表九折。沒有明細時 SUM 可能回 null；正式計價還要明確定義貨幣與捨入規則。

這個示例可宣告在資料存取 Repository；若你想建立 OrderRepository，必須先補 Order 的 Entity。本課先放在自訂報表 Repository 或現有 JpaRepository 練習，不假設已存在 Order 類別。
