01 · 先分辨語言與執行方式

HQL 是 Hibernate Query Language（Hibernate 查詢語言）。它查 Java 實體與屬性，不直接查表格。Hibernate 支援 JPQL，HQL 還提供額外能力；相同查詢文字可能同時符合兩者。

語言查什麼例子
SQL（Structured Query Language）表格／欄位FROM dbo.Products
JPQL（Jakarta Persistence Query Language）實體／屬性；標準可攜範圍select p from Product p
HQL實體／屬性；Hibernate 擴充可省略 select；另有視窗函式等能力

下面的基本 SELECT、WHERE、JOIN、GROUP BY 與 UPDATE 多半同時是 JPQL。選 HQL 擴充前，先確認團隊接受依賴 Hibernate。

02 · 第一個真的有綁參數的查詢

Hibernate 的 Session 是它自己的實體與查詢管理介面；不是 Servlet 用來記錄登入的 HttpSession。unwrap 是從 JPA 的 EntityManager 取得底層介面。下面做的仍是「帶入最低價格，查未停產商品」。

05 · DTO 投影：直接查你要的欄位

DTO 是 Data Transfer Object（資料傳輸物件）。建構子參數順序與型別需一致，這裡 id 是 Integer，價格是 BigDecimal。只要名稱與價格時，不必把整個商品及關聯全部載入。

06 · HQL 擴充：同分類價格排名

選讀：先完成前五節，再學分類內排名

Window Function（視窗函式）保留每筆商品，同時在分類內計算排名；partition by 決定分組，order by 決定名次。同價並列時 rank 會跳號。主線 Hibernate 7 與對照 Hibernate 6.6 都有這類能力；本例以 SQL Server 為情境，不當作所有 JPA 實作都支援。

07 · 修改與刪除，也要交易

createMutationQuery 用於異動；executeUpdate 回傳筆數。批次更新／刪除會繞過已載入物件的狀態追蹤，也不等同逐一呼叫實體回呼。先 flush、後 clear 是處理舊狀態的一種方式；清除後原有物件就脫離管理。外鍵限制仍然有效，不能靠 HQL 刪掉被引用商品。

08 · INSERT 為什麼不當成 JPQL 教？

選讀：HQL 新增擴充，一般新增先用前頁的 persist

這是 Hibernate HQL 的 INSERT VALUES 擴充，ProductID 由資料庫 IDENTITY 產生，category 可為 null。標準 JPQL 沒有這種一般新增語句；日常業務新增優先使用 persist 或 Repository.save，比較容易處理關聯與實體行為。
