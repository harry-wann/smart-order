技術亮點、報告與履歷

用到的技術與設計模式

全隊共用的技術

  • 後端：Java 21、Spring Boot 4.1（Spring MVC REST API：用網址和 HTTP 方法讓前端讀寫資料，例如 MenuController、KitchenTicketsController）
  • Spring Data JPA／Hibernate 7（用 Java 物件存取資料庫）、MySQL 5.7、Lombok（MenuItemEntity 的 getter／setter）、Maven
  • Bean Validation（請求欄位驗證：SaveMenuItemRequest 的 @NotBlank、@Min、@Max）、統一錯誤格式（ApiException 加 @RestControllerAdvice）
  • 前端：React 19、React Router 8、Vite 8、Tailwind CSS 4、TanStack Query 5（伺服器資料快取：KitchenOverview.jsx、OrderHistory.jsx）、axios、JavaScript／TypeScript 混用
  • 工具：Git 分支與 merge、oxlint

這個工作包特有的

  • Spring Security 角色權限：菜單管理 /api/order/admin/** 只給店長，報廢只給廚房與店長（SecurityConfig）
  • Spring WebSocket／STOMP（Simple Text Oriented Messaging Protocol）即時推播：看板 /topic/kitchen、菜單 /topic/menu、同桌客人的個人信箱；前端 @stomp/stompjs（useKitchenSocket、useMenuWebSocket、useOrderProgressSocket）
  • JdbcTemplate 原生 SQL 與 SELECT … FOR UPDATE（KitchenTicketService、OrderTicketStatusUpdater）
  • JPA LEFT JOIN FETCH 解決 N+1 查詢（顧客菜單 125 次 → 3 次）
  • 可重複執行的升級腳本（migrate_order_item_waste.sql、migrate_menu_category_guards.sql、migrate_order_item_waste_staff.sql）
  • 前端：深色看板色票（kds.colors.css）、ResizeObserver 與 requestAnimationFrame 做捲動高亮、sticky 頂欄、淡出動畫與 prefers-reduced-motion

設計模式

  • 分層架構（Controller–Service–Repository）與 DTO（Data Transfer Object，資料傳輸物件）：CustomerMenuItemDto、KitchenTicketResponse
  • 單一真相來源／狀態推導：點餐單狀態一律由品項算出來（OrderTicketStatusUpdater）
  • 悲觀鎖與固定鎖順序：同一桌先鎖用餐場次再鎖單與品項；分類用排他鎖、送單用共享鎖排隊
  • 樂觀並發控制：排序帶 expectedCategoryIds，畫面過期就回 409
  • 唯一索引當最後防線：uk_menu_category_name 擋住同時新增同名分類
  • 交易提交後才發布事件（afterCommit，發布／訂閱）：KitchenNotificationService、MenuStatusNotifier
  • 冪等：整單出完、報廢重送都回成功、不重複寫入
  • 樂觀更新：看板勾選先改畫面再送 API，失敗就還原
  • 批次查詢取代逐筆查詢（N+1）、捲動監聽（scroll spy）

報告與履歷

  • 報告①：用修正前的版本示範「沒登入也能刪菜單」，再示範修正後回 401、櫃檯回 403。
  • 報告②：左邊廚房看板、右邊客人手機，廚師一勾，客人約 0.1 秒內變「已出餐」；全部勾完卡片淡出；報廢一道菜，帳單自動扣掉。
  • 報告③：手機菜單點頁籤捲到該分類、[+] 直接加入；用資料庫紀錄展示一次載入從 125 次查詢降到 3 次。
  • 履歷：「參與餐廳點餐系統的菜單與出菜看板（KDS）：以 Spring Security 角色規則修正後台菜單 API 可被匿名呼叫的問題；點餐單狀態改由品項推導，並以固定鎖順序處理多人同時操作；以 WebSocket 在交易提交後推送出餐進度；以 JOIN FETCH 把菜單查詢從 125 次降到 3 次。」
