為什麼重構不代表所有行為都驗證完成？

打包與編譯能確認程式結構可建置；有限數量的畫面與請求檢查能確認那些已操作的路徑。它們不能自動涵蓋未執行的輸入、權限、錯誤情境或商務規則。

04 · 本次審查建議

技術前輩角度建議

團隊統一使用 Java，有助新手閱讀、交接與共用維護。轉換時要保留原本的 null（空值）、default（預設值）、transaction（資料交易）和 clock（時間來源）等語義，不能只追求語法改寫成功。

檔案數不是成果價值；主要價值是用證據說明行為維持一致，並讓程式更容易交接。原作者個人的技術亮點需由工作包 E 主審另行整理。

07 · 名詞說明

專有名詞

Kotlin
一種常用於 Java 虛擬機器環境的程式語言；.kt 是常見檔案副檔名。
Java
一種程式語言；.java 是 Java 原始程式檔的常見副檔名。
重構
整理程式內部結構或表達方式，目標是不改變原本對外行為；仍需用檢查證據確認。
HTTP — Hypertext Transfer Protocol（超文字傳輸協定）
瀏覽器、應用程式與伺服器傳送請求及回應時使用的通訊規則。
UI — User Interface（使用者介面）
人可以看到並操作的畫面，例如頁面、按鈕和欄位。
單元測試
針對一小段程式行為寫出的自動檢查；只確認測試程式可編譯，不等於執行並通過測試。
Commit（版本提交）
記錄一組程式變更的版本歷史項目，可用識別碼對照修改內容。
