工作包紀錄

桌位保留、開桌與清潔整合 →

含 101 項 HTTP 與 36 項瀏覽器驗收紀錄；範圍只涵蓋桌位生命週期整合。

候位取號、叫號與入座 →

同一組候位只能有一個結局：資料列鎖、不重號的取號、10 分鐘過號、叫號螢幕即時推播；含 128 項 HTTP 與 26 項瀏覽器候位專項驗收。

用餐超時與待清理提醒 →

每分鐘／每 5 分鐘的排程把超時與待清理的桌推到桌況總覽，並附店長手動觸發；含 16 項 HTTP 與 12 項瀏覽器驗收。

座位設定與桌位啟用 →

桌號不可改以保護桌上 QR、改小座位數不能弄壞訂位、停用與重新啟用，以及「遺失更新」的實際重現與修正；含 83 項 HTTP 與 11 項瀏覽器驗收。

技術亮點、報告與履歷

用到的技術與設計模式

全隊共用的技術

  • 後端：Java 21、Spring Boot 4.1（Spring MVC REST API）、Spring Data JPA／Hibernate 7、MySQL 5.7、Lombok、Maven、統一錯誤格式（ApiException 加 @RestControllerAdvice）
  • 前端：React 19、React Router 8、Vite 8、Tailwind CSS 4、TanStack Query 5（伺服器資料快取）、axios、JavaScript／TypeScript 混用
  • 工具：Git 分支與 merge、oxlint（程式碼檢查）

這個工作包特有的

  • Spring WebSocket／STOMP 即時推播：後端 WaitlistNotifier、TableStatusNotifier；前端 @stomp/stompjs（useWaitlistSocket.ts、useTableStatusSocket.js）
  • Spring Security 角色權限：COUNTER（櫃檯）與 MANAGER（店長），依 API 路徑與 HTTP 方法授權（SecurityConfig.java）
  • @Scheduled 排程（cron 加 Asia/Taipei 時區）與手動觸發 API：候位過號、用餐超時與待清理提醒
  • 原生 SQL SELECT ... FOR UPDATE（JPA 的 @Query nativeQuery）加 @Transactional(isolation = READ_COMMITTED)
  • JPQL 分組查詢（GROUP BY／HAVING）與投影介面（DiningSessionRepository.java）
  • HikariCP 連線池用盡問題的除錯（候位取號，見候位文章）
  • 資料庫唯一索引與不破壞舊資料的升級腳本（schema.sql、migrate_waitlist_flow.sql）
  • 前端：桌位 QR 圖片以 Blob／Object URL 列印（qrPrint.js）、請求世代防舊回應（TableOpen.jsx）、Tailwind motion-safe:
  • 請求欄位檢查在 Service 手寫（ApiException.badRequest），沒有用 Bean Validation
  • 驗證工具：Python 同時送請求的併發測試、Playwright 多視窗瀏覽器自動化

設計模式

  • 分層架構（Controller–Service–Repository）：例如 WaitlistController、WaitlistService、WaitlistRepository
  • DTO（Data Transfer Object，資料傳輸物件）：TableOverviewResponse、WaitlistTodaySummary、SeatResponse
  • 悲觀鎖與固定鎖順序：入座一律先鎖候位、再鎖桌位（WaitlistService）；取號鎖只有一列的序號表
  • 唯一索引當最後防線：uk_waitlist_ticket_no、uk_dining_session_waitlist
  • 狀態機與終態保護：候位 WAITING→CALLED→SEATED／EXPIRED／ABANDONED
  • 交易提交後才發布事件（afterCommit，發布／訂閱）加單一背景執行緒依序推播（WaitlistNotifier）
  • 冪等：提醒排程每次重算、不存狀態（TableReminderService）
  • 狀態推導：桌子實體 status 不動，畫面另算 displayStatus（TableHoldService）
  • 不可變欄位與軟刪除：桌號建立後不能改、停用不刪資料（SeatService）

報告與履歷

報告

  • 候位：用「兩台櫃檯同時讓 A13 入座」的時間線開場，demo 兩個櫃檯視窗加叫號螢幕同步；數字收尾：20 筆同時取號約 3 秒完成、號碼連續（修正前卡 30 秒）、128 項 HTTP 加 26 項瀏覽器候位專項驗收。
  • 連線池用光的除錯過程：20 個同時取號卡 30 秒，看 HikariCP 逾時紀錄，找到提交後回呼又借連線，改單一背景執行緒推播。
  • 桌位與座位設定：「清潔拿著舊資料把新開的桌改回空桌」與「兩個請求都回 200、桌子卻沒被停用」的遺失更新，分別以 101 項 HTTP 加 36 項瀏覽器、83 項 HTTP 加 11 項瀏覽器證明；店家端版面以 1024px 為驗收範圍。

履歷：「參與餐廳桌位與候位流程開發：以資料列鎖與唯一索引解決並行取號重號、同一組候位重複入座與開桌／清潔競態，設計候位狀態機與 10 分鐘過號排程，並以 WebSocket（STOMP）在交易提交後推播叫號到候位螢幕與多台櫃檯，以併發 HTTP 測試與 Playwright 多視窗測試驗證。」請寫「參與、協作」，這些是在既有程式上的修正與補齊，不寫成獨立完成整個工作包。
