櫃檯代客加點

櫃檯可在桌位詳情選餐點、規格、數量與備註，組成待送清單後直接送廚房。這份清單屬於櫃檯本次操作，同桌客人手機上的購物車內容會保留。

程式提交 de2a129 沿用送單時的商品檢查、現價快照與庫存扣除。快照是把當時的名稱、選項與價格保存下來，日後菜單改價也不會改寫舊帳單。庫存不足時整筆不成立，畫面保留待送清單，讓櫃檯調整後重試。

108 項 HTTP（Hypertext Transfer Protocol，超文字傳輸協定）／資料庫檢查與 25 項瀏覽器檢查通過。涵蓋員工權限、兩種身分同時送單的單號與帳單、保留同桌購物車，以及手機寬度的對話框操作。

技術亮點、報告與履歷

用到的技術與設計模式

全隊共用的技術

  • 後端：Java 21、Spring Boot 4.1（Spring MVC REST API：用網址和 HTTP 方法讓前端讀寫資料，例如 OrderSubmitController）
  • Spring Data JPA／Hibernate 7（用 Java 物件存取資料庫）、MySQL 5.7（訂單、購物車的資料表與查詢）
  • Lombok（自動產生 getter／setter，用在 OrderItemEntity 等資料類別）、Maven（Java 專案建置工具）
  • 統一錯誤格式：ApiException、@RestControllerAdvice
  • 前端：React 19、React Router 8（換頁）、Vite 8（建置工具）、Tailwind CSS 4（用 class 名稱寫樣式）
  • axios（前端呼叫 API 的工具；customerClient、employeeClient）
  • JavaScript／TypeScript 混用（.jsx 與 .ts）
  • 工具：Git 分支與 merge、oxlint（JavaScript 程式碼檢查）

這個工作包特有的

  • Spring Security 角色權限（COUNTER／MANAGER／KITCHEN）＋ SessionTokenFilter 驗證顧客 JWT（JSON Web Token，jjwt）
  • Spring WebSocket／STOMP（Simple Text Oriented Messaging Protocol，簡單文字導向訊息協定） 即時推播（@stomp/stompjs）：伺服器主動通知，購物車、帳單即時更新
  • JdbcTemplate 原生 SQL（Structured Query Language，結構化查詢語言）：送單時鎖定品項與選項
  • BigDecimal＋HALF_UP：金額精確到小數兩位
  • 資料庫升級腳本：migrate_order_item_stock_deducted.sql 可重複執行

設計模式

  • 分層架構（Controller–Service–Repository）：OrderSubmitController、OrderSubmitService、CartItemRepository
  • DTO（Data Transfer Object，資料傳輸物件）：OrderSubmittedResponse、StaffOrderRequest
  • 悲觀鎖（SELECT … FOR UPDATE）與固定鎖順序：先鎖用餐場次，再依品項編號鎖
  • 樂觀並發控制：decreaseIfEnough 庫存夠才扣；結帳帶 expectedTotal 比對
  • 快照：送單當下存單價、品名、選項與是否扣過庫存
  • 單一真相來源：BillingCalculator 從有效明細重算帳單，送單、取消、結帳共用
  • 交易提交後才發布事件（afterCommit）：帳單、訂單、取消通知
  • 擁有者檢查：購物車列只有加入者能改，後端每次驗證
  • 忽略過期回應（世代編號、流水號）：切桌與帳單刷新時舊回應不能蓋新畫面

報告與履歷

  • 報告：示範兩位客人各加品項，A 看得到 B 的品項但改、刪都回 403，A 送單後 B 的購物車仍在（56 項 HTTP、23 項瀏覽器檢查）。
  • 報告：示範資料一致性，改價後再送單仍用送單當時的價格，取消後帳單由有效明細重算（214 項後端與資料庫冒煙核對）；結帳時帳單被改會收到 BILL_CHANGED（156 項 HTTP、27 項瀏覽器檢查）。
  • 報告：「顧客手機點餐」與「櫃檯代客加點」共用驗證與快照、各自保存待送內容，再匯入同一桌帳單（108 項 HTTP／資料庫、25 項瀏覽器檢查）。
  • 履歷：「參與點餐交易與櫃檯結帳的資料一致性修正：以快照保存送單當下價格與選項，金額由單一規則重算，用資料列鎖與條件式更新處理同時送單、搶庫存，並以 HTTP 與瀏覽器案例驗證。」
  • 通知份數、代客加點等協作收尾的部分，請寫「參與整合」，不要寫成獨立完成。
