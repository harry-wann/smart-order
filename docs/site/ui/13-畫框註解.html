13 畫框註解

這份是 Figma 上每個畫框右側那塊說明的唯一來源。 tools/figma_prep.py 讀它、逐一對上 dist/frames.json 的畫框名， 漏寫一個畫框 lint 就會擋下來；extract_layout.py 把它塞進 layout.json， 外掛在每個畫框右邊排成一塊說明卡。

這裡只寫「看著那張圖會想問的事」。完整規格在 10-UI-UX規格.md， 視覺樣式在 11-設計系統.md，不要在這裡複製一份。

每一則控制在 4～6 條規格、2～4 條注意，寫太長在 Figma 上會比畫框還高。

「基礎必做／進階有空才做」不在這份文件裡設定，來源是 10-UI-UX規格.md 兩張頁面表的「級別」欄；figma_prep.py 直接讀那兩張表，兩邊對不起來會擋下來。

C-00｜入口頁

/ ・LINE、官網、Google 的連結都指到這裡

規格

  • 上半是店門口形象照，店名疊在照片上
  • 三列大按鈕：線上訂位 → C-16、我的預約 → C-19、會員登入 → C-12
  • 每列是圖示＋標題＋一行說明＋箭頭
  • 底部一句提醒：已經坐在店裡就掃桌上的 QR code

注意

  • 店裡的客人不會經過這一頁，掃碼直接進 C-01
  • 訂位入口不能掛在 C-01 上——那是人已經坐下來之後的畫面

C-01｜掃碼進入

/t/A03 ・桌位狀態＝用餐中

規格

  • 上半形象照佔螢幕 40%，中間大字顯示桌號
  • 下半依桌位狀態分三種：空桌「請洽櫃檯帶位」、用餐中直接進菜單、待清理「整理中，請稍候」
  • 底部小字「有訂位？查詢我的預約」

注意

  • 桌上的 QR code 固定是 /t/{桌號}，印一次貼著就好，永遠不用換
  • 開桌權在櫃檯，這一頁永遠沒有開桌按鈕
  • 結帳後再掃同一個 QR：「本次用餐已結束，感謝光臨」

C-04｜菜單主頁

/order/menu ・正常態・全站最重要的一頁

規格

  • 固定頂欄：桌號、人數、入座時間，右上角一顆服務鈴
  • 搜尋列、分類頁籤固定在頂部，捲動時自動高亮目前分類
  • 品項列左圖右文，高度至少 96px、照片 80×80、圓角 12px
  • 無選項的品項按 + 直接加入購物車；有必選選項的點整列進 C-05
  • 底部購物車列有東西才出現

注意

  • 售完要照片灰階＋價格劃線＋「售完」文字標籤，不能只靠變灰
  • 售完是庫存扣減算出來的，那段是基礎；進階拿掉的只有 S-09 那一頁
  • 鍋底只是分類之一，「每桌至少一份」改在送單時擋（400 SOUP_BASE_REQUIRED）
  • 服務鈴不掛紅點——要講同桌動態就用通知條，直接說清楚誰做了什麼

C-04｜載入中

三態之一・骨架屏＋火鍋冒泡

規格

  • 頂欄與搜尋列照常顯示，內容區換成灰色骨架方塊
  • 中央一句「正在準備今天的菜單」

注意

  • 不要用轉圈圈。骨架的形狀要跟真實內容對得上，不然載完會跳動
  • 每個會打 API 的頁面都要處理三態，這是驗收項目

C-04｜空資料

三態之一・插圖＋一句話＋一個行動

規格

  • 保留分類頁籤，讓客人看得出是「這一區沒有」而不是整個菜單壞了
  • 一句話說明原因（今天的漁貨還沒進來），再給一顆「看看肉品」

注意

  • 空狀態一定要給出口，不能只有一張圖
  • 文案講人話、講原因，不要寫「查無資料」

C-04｜錯誤

三態之一・中文訊息＋重試

規格

  • 中文訊息說明可能原因，兩顆按鈕：重新載入、按服務鈴找店員
  • 底部一條細提示「連線不穩，請再試一次」

注意

  • 絕對不要顯示英文錯誤碼或 HTTP status 給客人看
  • 重試要真的重打 API，不是叫客人重新整理整頁

C-04｜已送出結帳

鎖定態・按下結帳後整桌不能再加點

規格

  • 菜單內容整個壓淡、分類頁籤停用
  • 底部購物車列換成一行說明：想加點請按服務鈴，請服務生取消結帳

注意

  • 服務鈴仍然可以按——叫得到人才取消得了
  • 鎖定是整桌的，靠 WebSocket SESSION_LOCKED 推給所有裝置

C-04b｜同桌通知・有人加購物車

覆蓋層，不是獨立路由

規格

  • 通知條從上方滑下、蓋在 appbar 上，停 4 秒自己收回
  • 內容寫清楚是誰加了什麼

注意

  • 不用客人關掉；後來的蓋掉前一則，不堆疊
  • C-04、C-05、C-06、C-08 共用同一個元件，設計稿只畫這兩張

C-04c｜同桌通知・有人送出訂單

覆蓋層・同一個元件換文案

規格

  • 內容換成第幾單、幾項、多少錢

注意

  • 進了結帳（C-09）之後不再出現——那時已經不能加點了
  • 共鍋是好幾支手機同時點，別人做了什麼不能只靠自己去翻購物車

C-05｜品項詳情與選項

/order/items/:id ・份量已選「全份」→ 底部按鈕可按

規格

  • 頂部 16:9 大圖，可左右滑
  • 每個選項群組一個區塊，標題列標「必選」或「可選 最多 5 項」
  • 單選用大型 radio 卡片、複選用大型 checkbox 卡片，右側標價差 +$80（0 元不顯示）
  • 數量步進器、備註 50 字上限（顯示剩餘字數）
  • 固定底欄「加入購物車 · $740」

注意

  • 必選還沒選完時底欄停用，而且要寫出還差什麼（「請選擇份量」）
  • 鴛鴦鍋在資料上就是掛了兩個必選群組的品項，不另外做畫面

C-06｜購物車

/order/cart ・6 項・NT$ 1,420

規格

  • 每列：品項名、已選選項（小字灰色）、備註、數量步進器、小計
  • 底部合計＋主按鈕「送出點餐」

注意

  • 左滑刪除一定要配一顆看得見的刪除鈕——長輩不會左滑
  • 空購物車要給「去看看菜單」，不是只顯示 0 項

C-07｜送出成功

/order/submitted ・勾勾描邊 0.6 秒後停住

規格

  • 大型勾勾動畫、「第 2 單已送出」、「廚房已收到，請稍候」
  • 兩顆按鈕：繼續點餐（主）／查看本桌訂單

注意

  • 2 秒後自動跳 C-08，按鈕是給想提早走的人
  • 這一頁刻意沒有服務鈴——做完就走的任務畫面，回 C-04 只要一下

C-08｜本桌訂單與出菜進度

/order/tickets ・多裝置同步的展示舞台

規格

  • 頂部摘要：桌號、人數、用餐時間、目前金額
  • 依點餐單分組的卡片，每個品項用圖示＋文字標出餐狀態
  • 底部：繼續加點（主）／我要結帳

注意

  • WebSocket 即時更新；新單從上方滑入＋高亮 2 秒，讓「同步」看得見
  • 斷線顯示「連線中斷，正在重新連線…」，重連後要自動重抓一次完整資料
  • 狀態不能只靠顏色，圖示與文字都要有

C-09｜結帳明細

/checkout ・小計 → 服務費 10% → 合計

規格

  • 品項清單可摺疊；合計字級 32px 粗體
  • 顯示均分每人多少
  • 非會員：「這筆可以累 156 點，要登入才留得住」＋登入按鈕 → C-12

注意

  • 這是最後一次能登入的地方，付款完成後就補不回來了
  • 頂部要提示「已進入結帳，這桌不能再加點了」
  • 下面補一行「不想登入也可以直接付款，點數就不留了」，不要把人卡死

C-10｜付款方式選擇

/checkout/pay ・模擬付款・95% 成功

規格

  • 三顆大按鈕，各自的品牌樣式（Apple Pay 黑底、Google Pay 白底、LINE Pay 綠底）
  • 按下後按鈕轉處理中、全頁遮罩、2 秒動畫

注意

  • 一定要明顯標註「教學專題，付款為模擬流程，不會產生實際交易」
  • 處理中禁止重複點擊；失敗要有錯誤提示與重試

C-11｜付款完成

/checkout/done ・電子收據

規格

  • 勾勾動畫、交易編號、金額、獲得點數
  • 「感謝光臨，歡迎再來」

注意

  • 這裡沒有任何登入或註冊入口。 用餐都結束了才叫人註冊，點數也補不回來， 只是在關門的時候硬塞一張表單

C-12｜會員登入／註冊

/auth ・登入與註冊同一條路

規格

  • 只問手機號碼，不設密碼；每次登入都發一次驗證碼
  • 主按鈕「傳送驗證碼」→ C-12b，說明「第一次來也是按這裡」
  • 次要按鈕「先不登入，繼續」

注意

  • 不讓客人先選「登入」還是「註冊」——他記不得自己註冊過沒有，一半的人會選錯
  • 三個入口進得來（C-00、C-09、C-16），完成後都要回到原本那一頁

C-12b｜輸入驗證碼

/auth/otp ・從 C-12 送出手機號碼後進來

規格

  • 6 格數字、顯示送到哪支號碼、「改號碼」可回 C-12
  • 倒數「04:32 後失效」與「重新傳送（52 秒）」

注意

  • 教學專題直接把驗證碼顯示在畫面上，不串真實簡訊閘道
  • 驗證通過後後端查這支號碼：有 → 直接登入；沒有 → C-13 補資料

C-13｜會員註冊補資料

/auth/register ・手機驗證通過後才會到這頁

規格

  • 手機欄位唯讀並標「已驗證」
  • 怎麼稱呼你、性別、生日三欄，都不是必填
  • 同意保存消費紀錄的勾選＋條款連結
  • 次要按鈕「跳過，只留手機就好」

注意

  • 多一欄就多一批人放棄，所以只留累點真的用得到的
  • 生日只用來判斷生日當月送甜點，不顯示在任何地方

C-14｜會員中心

/member ・卡片底用木桌紋理（弱化）

規格

  • 會員卡：姓名、手機、入會年資、可用點數、累積消費次數
  • 三個入口：消費紀錄、我的預約（帶出最近一筆）、個人資料
  • 底部規則：每 10 元累積 1 點、生日當月送季節甜點

注意

  • 木桌紋理要弱化到不影響文字對比（≥ 4.5:1）
  • 「消費紀錄」入口是進階 A1（C-15）；不做就整列拿掉，其餘照常
  • 「我的預約」要顯示筆數；沒有預約時顯示空狀態，不要整塊藏起來

C-15｜消費紀錄

/member/history ・進階 A1

規格

  • 每次用餐一張卡片：日期、桌號、品項摘要、金額、獲得點數
  • 「看明細」開 C-09 的唯讀版，含交易編號與付款方式

注意

  • 空資料：鍋子線稿＋「還沒有消費紀錄」＋主按鈕「看看菜單」
  • 載入中用 3 張卡片骨架屏，不要轉圈圈
  • 進階 A1（M8 8.8、8.9）：不做的話 C-14 少一個入口，點數照樣累

C-16｜線上訂位入口

/reserve ・訂位前先問要不要用會員身分

規格

  • 兩張卡片各帶自己的按鈕，會員那張放上面並標「建議」
  • 用會員訂：姓名電話自動帶入、可在我的預約自己取消與先點餐、當天用餐累點
  • 直接訂不註冊：留姓名與手機就好 → C-16b

注意

  • 不強迫註冊才能訂位——擋在門口要人先註冊會直接流失一批客人
  • 登入完成後回到這一頁繼續訂位，已填的不會不見
  • 會員的優勢是「換裝置也找得到、還能累點」，不是「能不能改」，文案要照這個講

C-16b｜匿名訂位填資料

/reserve/guest ・姓名與手機必填，信箱選填

規格

  • 姓名（到店叫號用）、手機（店家唯一的聯絡管道）、信箱（只寄確認信）
  • 底部次要按鈕「改用會員身分訂」，隨時可以切回去

注意

  • 不問生日、性別、地址——訂位用不到，會員註冊時再問
  • 建立訂位時後端發 accessToken 存在這支手機的 localStorage，靠它就能回來改與取消
  • 只有換手機或清掉瀏覽資料才要打電話，提示文案要寫清楚

C-16c｜選日期時段人數

/reserve/when ・送出即訂位成立

規格

  • 月曆（明天起 30 天內）→ 時段按鈕（客滿的顯示「已額滿」且不可點）→ 人數步進器
  • 選完顯示「將為您安排 4 人桌」
  • 底部主按鈕「確認訂位」，右側附所選的「9/21（一）18:00・4 位」

注意

  • 這一頁送出，訂位就成立了。 沒有下一步、不收錢，先點餐是訂到位之後的加值選項
  • 拿掉頂部的步驟指示器——只有一步，就不要假裝有三步
  • 客滿回 409 SLOT_UNAVAILABLE：留在本頁，該時段即時標成「已額滿」並提示重選

C-18｜訂位完成

/reserve/:id/done ・動線的轉折點

規格

  • 上半：大勾勾、「訂位完成」、預約編號（大字可複製）、日期時段、人數、桌號
  • 「加入行事曆」次要按鈕（.ics，進階 7.E8）
  • 下半一張卡片問「要先點餐嗎？」：先點餐 → C-17／到店再點
  • 取消政策 infobox；匿名訂位多一行「這支手機記住了你的訂位」

注意

  • 順序不能顛倒：先讓客人確定訂到了，才問要不要先點餐
  • 沒有金額欄位、沒有「已付」——訂位不收錢
  • 問句卡片上要標「現在不用付款，餐點金額到店結帳時一起算」
  • 「要先點餐嗎」整張卡片是進階 A2；不做就只留上半的訂位成功

C-17｜預先點餐／調整餐點

/reserve/:id/preorder ・進階 A2

規格

  • 頂部訂位摘要條＋「可修改到 9/20（日）20:00」
  • 主體完全重用 C-04、C-05、C-06，不另外做一套
  • 底部按鈕：第一次「送出預先點餐」；已有內容「更新餐點」＋ ghost「清空預點」

注意

  • 進到這一頁就代表客人已經選了要先點，不要再問一次「要先點餐嗎」
  • 金額一律寫「預估 NT$ 1,340」；送出後不進付款頁，回 C-19 顯示 toast
  • 鍋底在這裡不強制，「每桌至少一份」是送正式單時才擋
  • 過了期限直接開網址進來：整頁唯讀＋來電提示
  • 進階 A2（M7 7.E1～7.E3、M4 4.8）：不做的話 C-18 不問「要先點餐嗎」、C-19 少一顆按鈕

  • 取消的二次確認：「沒有款項需要退還，餐點還沒結帳」

注意

  • 沒有「改期」這個功能，要換時間就是取消後重訂，全站文案不要再出現「改期」
  • 「預先點餐」／「調整餐點」那顆按鈕是進階 A2；不做就只剩「取消訂位」
  • 金額一律寫「預估」，不寫「已付」

S-02d｜開桌・預約

同一個路由的第三個頁籤

  • 每列顯示時間、姓名、電話末四碼、人數、預點狀態（「已預先點餐 4 項」或「未預點」）
  • 頂部暖黃警示條：這張桌 19:30 有預約，預計用餐到 21:25

  • 開桌後不要去改 reservation.table_id，實際坐哪桌記在 dining_session；本專題不做換桌
  • 「稍後有預約」只是提醒，不擋開桌
  • 忘了把 reservation.status 轉 SEATED，那筆會繼續出現在別張桌的開桌清單上

  • 不要用轉圈圈；不給客人看英文錯誤碼
  • 空狀態的那顆按鈕要真的有地方去，不能只是好看

DS-08｜店家端元件

1280 × 1200 ・桌況三色與 KDS 卡片狀態

規格

  • 桌位磚三種桌況（空桌／用餐中／待清理）＋超時態
  • 統計條、服務鈴通知卡、出菜看板卡

注意

  • 超過 100 分鐘自動轉紅框；顏色之外一定有文字標籤
  • 出菜看板卡是全站唯一的深色介面，色票另外一組
  • 手動「保留」（--table-held）是延伸功能 M2 的 2.E5，基礎不畫
