12 AI UI 工具與提示詞

你問的兩件事：哪些 AI 工具做 UI 很強，以及怎麼不要有 AI 感。 第二個問題的答案在 11-設計系統.md §7，這裡講的是「怎麼把那份設計系統餵給 AI，讓它照做」。

1. 核心觀念：AI 是執行者，不是決定品味的人

AI 生成的介面之所以一眼看得出來，不是因為 AI 畫得醜，而是因為你沒有給它決定。沒有指定字體、色票、版面原則時，模型會退回訓練資料裡最常見的那一組——也就是靛紫漸層、Inter 字體、三張並排的圓角卡片。

所以正確的順序是：

① 先定設計系統（已完成 → 11-設計系統.md）
        ↓
② 把設計系統當成「憲法」寫進每一段提示詞
        ↓
③ 讓 AI 生成第一版視覺
        ↓
④ 挑一個定調，整理成 Figma 元件與樣式
        ↓
⑤ 前端「手寫」Tailwind 實作，AI 產出的程式碼只當參考

第 ⑤ 步請務必照做。 詳見 §5 的警告。

2. 工具比較

工具 最擅長 輸出 費用 給你們的建議
Figma Make 從一段文字產出可互動的原型，能把既有 Figma 元件貼進提示詞當參考 Figma 內的 React 原型，可視覺編輯 Figma 付費方案含額度 主力工具。你們已經要用 Figma，一條龍最省事
Figma AI / First Draft 把生成結果整理成正規的設計稿與元件庫 Figma 圖層 同上 搭配 Make 使用，定調後用它整理元件
Google Stitch 免費、可多方案快速比較 HTML / CSS / Tailwind / React 免費 比稿用。同一段提示詞跑 3 次挑最好的
Vercel v0 產出乾淨的 React + Tailwind + shadcn 程式碼 React 程式碼 免費額度 / $20 月 當程式碼參考書，不要整包貼進專案（見 §5）
Uizard 多畫面原型、手繪稿轉數位 互動原型 免費 / $12 月 時間不夠時用來快速鋪幾十個畫面的骨架
Motiff 內建 Material / Ant / shadcn 設計系統 React / CSS 免費 / $20 月 備選，生態較小

給你們的推薦組合

  1. Figma Make（主力）— 生顧客端菜單頁與店家端桌況頁，挑一個定調
  2. Google Stitch（免費比稿）— 同一段提示詞多跑幾次，看有沒有更好的版面想法
  3. Figma 本體 — 把定調結果整理成色票樣式、文字樣式、元件，其他 41 張畫面照著畫
  4. 手寫 Tailwind — 前端實作，v0 產出的程式碼只在卡住時當參考

不要同時用超過兩個生成工具。 每個工具的風格偏好不同，混用會讓 43 張畫面看起來不像同一個產品。

3. Figma Make 提示詞的五條規則

  1. 第一段就把細節講完。 補問越多次，偏離越遠。任務、情境、設計元素、行為、限制，一次寫清楚。
  2. 一次只做一個畫面。 「幫我做整個點餐系統」會得到一堆平庸的東西；「做菜單主頁」才會得到有細節的結果。
  3. 用具體數值，不要用形容詞。 寫「品項列高度 96px、照片 80×80」，不要寫「卡片大一點」。
  4. 把色票與字體寫死在提示詞裡。 這是壓制 AI 預設風格最有效的手段。
  5. 明確列出禁止事項。 「不要紫色漸層」「不要三張並排卡片」——負面指令對這類模型很有效。

另外：把參考圖貼進提示詞（Unsplash 找的台式火鍋店照片、你們畫的手稿）比任何文字描述都有效。

4. 可直接複製的提示詞

4.1 【設計系統區塊】— 每一段提示詞都要貼上這段

【設計系統 — 必須嚴格遵守】

語言：繁體中文（台灣用語，例如「加入購物車」不是「添加到购物车」）
產品：台灣中高價位、多人共鍋的火鍋店手機點餐系統（視覺走台式老店的親切感）

色彩（只能用這些）：
- 頁面底色 #FBF7F0（暖米白，絕對不要用純白 #FFFFFF）
- 卡片底色 #FFFFFF，邊框 1px #E6DED2
- 主色（主按鈕、價格、重點）#C8442E，按下時 #A63522
- 輔色（推薦徽章、標籤）#E8A33D
- 文字：主要 #2B211C／次要 #6B5D54／弱化 #9C8E84
- 成功（已出餐）#3F7A4E／警告 #D98324／錯誤與售完 #B3261E
- 嚴禁使用：任何紫色、靛藍、藍紫漸層、冷灰色

字體：
- 標題用 "Noto Serif TC"（思源宋體），字重 700–900
- 內文與按鈕用 "Noto Sans TC"（思源黑體），字重 400/500/700
- 內文最小 16px，品項名 18px，價格 20px 粗體，按鈕文字 18px
- 中文行高 1.75

形狀與陰影：
- 卡片與照片圓角 12px，按鈕與輸入框圓角 8px，標籤圓角 999px
- 卡片陰影只用 0 1px 2px rgba(43,33,28,.06), 0 4px 12px rgba(43,33,28,.05)，非常淡，不要發光效果
- 不要所有東西都用同一個大圓角

版面：
- 手機優先，畫布寬 375px
- 頁面左右留白 16px
- 主要按鈕高度 52px，所有可點擊區至少 44×44px
  （例外只有兩個：數量步進器與菜單列的「+」是 28×28 圓形按鈕；菜單列進詳情的箭頭是 32×32）

嚴格禁止：
- 三張等寬圓角卡片並排的區塊
- 用 emoji 當圖示
- 細線條通用圖示當主視覺（主視覺必須是食物照片）
- 任何漸層背景（照片上的深色遮罩除外）
- Inter 字體
- 空泛文案。要寫具體的句子，例如「厚切 3mm，涮 8 秒最好吃」
  而不是「精選優質食材，帶來極致享受」

4.2 菜單主頁（最重要，先做這頁定調）

（先貼上 4.1 的設計系統區塊）

【任務】
設計火鍋店手機點餐的「菜單主頁」，畫布 375×812。

【畫面結構，由上到下】
1. 固定頂欄，高 56px：左側返回箭頭 + 「A03 桌」，下面一行小字「2 大 1 小　18:32 入座」
   右側一顆服務鈴按鈕——櫃檯上按的那種鈴（半圓鈴身＋底座），不是通知鈴鐺，不掛紅點
2. 搜尋框，高 44px，placeholder「搜尋菜色」，左側放大鏡圖示
3. 分類頁籤列，高 48px，可橫向捲動：推薦／鍋底／肉品／海鮮／蔬菜／火鍋料／主食／飲料
   選中的頁籤文字 #C8442E 粗體並有 2.5px 底線，未選中 #6B5D54
4. 「今日推薦」區塊：標題是一塊木紋底的小木牌，旁邊小字「本店人氣 TOP 5」；
   下面是橫向捲動的卡片，每張寬 168px，包含食物照片（16:9，圓角 12px）、品名、價格
   ★ 這一塊、「推薦」頁籤與「人氣」膠囊是進階 A7（人氣推薦）。定調時照畫，實作不做 A7 就一起拿掉
5. 分類標題「肉品」，使用思源宋體 22px 粗體
6. 品項列表，列與列之間間距 12px，每列是白底、1px #E6DED2 邊框、圓角 12px、內距 16px，高度至少 96px，左圖右文：
   - 左：食物照片 80×80，圓角 12px
   - 右：品名 18px 粗體（旁邊可放 #E8A33D 的「人氣」膠囊徽章）、描述 14px 灰字最多兩行
   - 右欄最後一列固定高 32px：左邊價格 20px 粗體 #C8442E，最右邊圓形「+」按鈕 28×28，底色 #C8442E 白色加號
7. 其中一列要示範「售完」狀態：照片灰階、品名與描述變淡、價格加刪除線、
   品名旁 #B3261E 的「售完」膠囊標籤、照片上斜蓋一個紅框印章「售完」、「+」按鈕變灰
8. 固定底欄：白底、上方 1px #E6DED2 分隔線，裡面一條高 56px、圓角 8px 的 #C8442E 購物車列（白字），
   左側「購物車 6 項」，右側「$1,420」與箭頭，整條可點

【內容範例，請用這些真實感的文案】
- 美國牛五花／厚切 3mm，涮 8 秒最好吃／$280
- 特選梅花豬／油花均勻，適合小朋友／$220
- 紐西蘭羊肉／（這項設為售完）／$320
- 手打花枝漿／每日現打／$160
- 帶殼鮮蝦／宜蘭現撈／$260

【照片】
使用真實的台式火鍋食材照片風格（生肉片捲、火鍋料拼盤），
暖色調、有質感、不要 3D 渲染感、不要歐美 fusion 風格。

4.3 品項詳情與選項

（先貼上 4.1 的設計系統區塊）

【任務】
設計「品項詳情頁」，畫布 375×812，示範多種選項群組。

【畫面結構】
1. 頂部食物大圖，16:9 滿版，左上角半透明圓形返回按鈕
2. 品名「美國牛五花」思源宋體 28px；價格「$280」20px 粗體 #C8442E
3. 描述「美國安格斯牛五花，厚切 3mm。下鍋涮 8 秒起鍋，油花剛好化開。」
4. 選項群組一「份量」，標題右側有 #B3261E 的「必選」小標籤
   兩個大型單選卡片，高 56px：
   - 「半份」（無價差）
   - 「全份」右側顯示「+$80」
   選中的卡片：底色 #FBE8E3、邊框 1.5px #C8442E、右側打勾
5. 選項群組二「熟度偏好」，必選，三個單選卡片：原味／炙燒 +$20／厚切 +$40
6. 選項群組三「加點配料」，標題右側灰字「可選，最多 5 項」
   四個大型複選卡片，左側 24×24 方形勾選框：
   加蔥花 +$10／加蒜泥 +$10／加香菜 +$10／加白蘿蔔泥 +$15
7. 數量步進器：減號、數字、加號，各 28×28 圓形（整組膠囊外框）
8. 備註輸入框，placeholder「有特別需求嗎？例如不要蔥」，右下角顯示「0/50」
9. 固定底欄：全寬主按鈕高 52px，文字「加入購物車 · $740」

4.4 本桌訂單與出菜進度

（先貼上 4.1 的設計系統區塊）

【任務】
設計「本桌訂單」頁，畫布 375×812。這頁要讓客人知道每道菜出了沒。

【畫面結構】
1. 頂欄：「A03 桌」+「用餐 38 分鐘」
2. 摘要卡片：3 位用餐者、已點 6 項、目前金額 $1,420（沒有任何點數或優惠券）
3. 依「點餐單」分組的卡片，每張卡片：
   - 卡片標題列：「第 1 單」粗體 + 「18:32 送出」灰字
   - 品項列，每列有狀態圖示 + 文字：
     已出餐用綠色打勾圖示 + 綠字「已出餐」
     製作中用沙漏圖示 + 橘字「製作中」
   - 品項下方用 14px 灰字顯示已選選項，例如「全份・加蔥花」
   - 狀態絕對不能只用顏色區分，一定要同時有圖示和文字
4. 顯示兩張卡片：第 1 單全部已出餐，第 2 單混合狀態
5. 固定底欄：
   主按鈕「繼續加點」（紅底白字，高 52px）
   按鈕下方一行 14px 灰字「用餐完畢請到櫃檯結帳」
   ★ 客人預設到櫃檯結帳。「我要結帳」是進階 A5（手機線上付款），
     要畫的話放在主按鈕旁、次要樣式（白底紅框紅字）；不做 A5 就整顆拿掉

4.5 店家端 — 桌況總覽

（先貼上 4.1 的設計系統區塊，但改為桌機版）

【調整】畫布改為 1280×800，這是店家平板／電腦用的後台（橫式，≥ 1024px）

【任務】
設計餐廳櫃檯的「桌況總覽」頁。

【畫面結構】
1. 左側固定側邊欄寬 212px，淺色 #F5EFE5 底、右側 1px #E6DED2 分隔線：
   頂部店名（思源宋體）；選單項目每列高 44px、圖示＋文字：
   桌況總覽／出菜看板／預約管理／候位管理，
   小標「菜單」下：菜單管理／選項群組／庫存管理，小標「設定」下：座位管理／報表；
   最底下員工名稱「小美・外場」
   選中項目：底色 #FBE8E3、文字 #A63522 粗體（不要用深色側欄、不要用實心紅底）
2. 頂欄高 60px，白底：頁面標題「桌況總覽」、日期小膠囊、綠色「即時同步中」狀態、右上角通知鈴鐺
3. 主區頂部統計列：一條白底圓角橫條，裡面六組數字用細直線隔開（不是六張卡片並排）——
   空桌 3｜用餐中 5｜待清理 2｜預約保留 2｜待報到預約 4｜3 組候位中
   數字用思源宋體 26px 粗體，後面接 13px 灰字標籤；不要放營收數字
4. 主區桌位網格，每排 4 張、間距 12px，每張桌卡圓角 12px、內距 12px 16px、高度至少 106px：
   - 左上角一顆白色半透明膠囊文字標籤（空桌／預約保留／用餐中／待清理）
   - 桌號 24px 粗體（A01、A02…）
   - 用餐中的桌多兩行 13px 小字：「2 大 1 小・47 分」與「NT$ 1,420」
   - 待清理的桌一行「19:02 結清」
   - 預約保留的桌一行「18:30 陳○君 4 位」
5. 四種顯示各至少出現一張（只有這四種，沒有「結帳中」）：
   - 空桌：底色 #E6DED2，標籤「空桌」
   - 預約保留：底色 #FCF0DC、1.5px #E8A33D 內框、深色字，標籤「預約保留」
     （線上訂位在用餐前 30 分鐘起鎖住配到的桌；不要畫成實心黃底，那是另一個延伸功能）
   - 用餐中：底色 #C8442E 白字，標籤「用餐中」
   - 待清理：底色 #9C8E84 白字，標籤「待清理」
6. 有一張用餐中的桌顯示「112 分」並帶 3px #B3261E 內框，代表超過 100 分鐘的超時提醒
7. 網格下方一張候位摘要卡：「候位中 3 組・平均等 22 分」＋三顆號碼膠囊＋「去候位管理」
8. 主區右側一欄寬 300px 的服務鈴通知面板：卡片堆疊，每張是桌號＋呼叫類型（加湯／呼叫服務生／換鍋撈渣）
   ＋幾分鐘前＋「已處理」小按鈕；沒有「我要結帳」這一類
9. 狀態一定要同時有顏色和文字標籤，不能只靠顏色
10. 頂欄不要放「櫃檯開桌」按鈕——開桌的入口是點空桌，或從預約／候位那一列報到

4.6 店家端 — 出菜看板 KDS（全站唯一深色頁）

【任務】
設計廚房用的「出菜看板」，畫布 1920×1080（固定橫式大螢幕，不做 RWD）。
這是全系統唯一使用深色背景的頁面，因為廚房光線強、需要遠距離辨識。

【色彩，本頁專用】
- 背景 #241C18，頂欄 #1B1512
- 卡片底 #33261F，分隔線 #4A3A31，卡片圓角 12px
- 文字 #F3EAE0，選項小字 #A8968A
- 強調色維持 #C8442E 與 #E8A33D；等太久的紅框用 #B3261E
- 已出餐的勾選框 #3F7A4E 底白勾

【畫面結構】
1. 頂欄高 76px：「出菜看板」+ 目前時間 + 「待出 7 單」
2. 卡片式看板，每排 5 張、間距 24px（每張約 350px 寬）：
   - 卡片頂部：桌號「A03」32px 特粗白字 + 「第 2 單」+ 右側等待時間「3 分鐘」
   - 分隔線
   - 品項列，每列左側 40×40 的大型方形勾選框：
     「美國牛五花 ×2」20px 白字
     下方 15px 灰字顯示選項「全份・加蔥花」
     已勾選的品項：勾選框變綠底白勾，文字淡化並加刪除線
   - 卡片底部全寬按鈕「整單出完」，高 52px
3. 特殊狀態要各出現一張：
   - 一張有金色 #E8A33D 邊框 + 左上角「預約優先」金色標籤，排在最前面
   - 一張等待時間 18 分鐘，紅色 #B3261E 邊框，時間文字紅色（超過 15 分鐘就轉紅）
4. 整體字級要大，廚房站在兩公尺外也要看得清楚

4.7 選日期時段人數（C-16c）

注意：這一頁送出訂位就成立了，不要畫步驟指示器。 舊版提示詞裡有「① 選時間 ─ ② 先點餐 ─ ③ 完成」，流程已經改掉，別再生成那個元件。

（先貼上 4.1 的設計系統區塊）

【任務】
設計線上訂位的「選擇日期、時段與人數」頁，畫布 375×812。
這是訂位流程唯一的一步，按下底部按鈕訂位就成立，不要有步驟指示器。

【畫面結構】
1. 頂欄「線上訂位」+ 返回箭頭
2. 月曆，可選明天起 30 天內：
   今天標示為「今天」但不可選
   可選日期為一般樣式，選中的日期為 #C8442E 圓形底白字
   不可選日期降低不透明度
3. 時段選擇，5 個並排的方形按鈕，每 30 分鐘一格
   選中為 #C8442E 底白字
   其中一個顯示「已額滿」，虛線框、灰色且不可點
4. 人數選擇：大人與小孩兩組大型步進器，按鈕 56×56 圓形（1.5px #C8442E 框），數字 40px 思源宋體
5. 資訊卡片：「將為您安排 4 人桌，用餐時間 100 分鐘」
6. 取消政策小字：「訂位時間前 30 分鐘都可以在『我的預約』取消；之後請來電」
7. 固定底欄主按鈕「確認訂位」，高 52px，
   右側附帶已選的「9/21（一）18:00・4 位」

4.8 訂位完成，並在這裡問要不要先點餐（C-18）

（先貼上 4.1 的設計系統區塊）

【任務】
設計訂位成功頁，畫布 375×812。
這一頁有兩個任務：先讓客人確定訂位成功，然後才問要不要先點餐。
順序不能顛倒，成功訊息被選項擠到下面，客人會不確定到底訂成功沒有。

【畫面結構】
1. 置中的淺綠圓底綠色勾勾，直徑 96px
2. 大標「訂位完成」+ 一行小字「到店時報預約編號或手機號碼就可以」
3. 卡片：預約編號（等寬字、放大、字距加寬）、日期時段、人數、桌號
   ★ 不要有任何金額欄位。訂位不收錢
4. 一張 #C8442E 邊框的卡片，標題「要先點餐嗎？」
   一段說明：先點的餐到店報到後廚房直接開始做，在出菜看板排最前面
   主按鈕「先點餐」（實心 #C8442E，高 52px）
   次要按鈕「到店再點」（ghost 樣式）
   底下一條淺色提示條：「現在不用付款。餐點金額到店結帳時一起算，之後也可以隨時改」
5. 次要按鈕「加入行事曆」，帶日曆圖示
   ★ 放在「要先點餐嗎」卡片的後面，不然兩顆主要按鈕會被擠到摺線下
6. 淺色資訊框「取消與修改」：訂位時間前 30 分鐘都可以在「我的預約」取消訂位；之後請來電。
   先點的餐可以改到用餐日前一天 20:00，都沒有任何費用。
   最後一行：「訂位保留 10 分鐘，逾時視同未到，需現場候位」
   ★ 不要出現「遲到 15 分鐘」、「改期」、任何點數或優惠券字樣
7. 固定底欄次要按鈕「查看我的預約」

5. ⚠️ 給前端的重要警告

不要把 AI 生成的 React 程式碼整包貼進專案。

原因：

  1. 你們看不懂它寫了什麼。 出 bug 的時候，五個人都不知道從哪裡改起——這在 demo 前一天是災難。
  2. 它會帶進一堆你們沒學過的東西：自訂 hooks、Context 巢狀、複雜的泛型工具、你們沒裝的套件。
  3. 面試會問。 「這段程式碼為什麼這樣寫？」答不出來比沒寫還糟。
  4. 風格會分裂。 每次生成的命名與結構都不一樣，43 張畫面會變成 43 種寫法。

正確用法：

用途 做法
定調視覺 ✅ 用 AI 生成，看畫面就好
版面靈感 ✅ 生 3 版比較，挑最好的結構
卡住時參考寫法 ✅ 看它怎麼處理某個佈局，然後自己重寫
直接當產品程式碼 ❌ 不要
產生 Tailwind class 字串 ⚠️ 可以，但要逐行看懂再用

折衷做法（推薦）：AI 生成後，看著它的畫面，自己用 Tailwind 重寫一次。速度只慢 20%，但程式碼完全是你們的，而且過程中真的學會了 React。

6. 工作流程建議

週次 設計工作
W1 用 §4.2 的提示詞在 Figma Make 生 3 版菜單主頁 → 全組投票挑一版定調 → 在 Figma 建立色票樣式與文字樣式
W1 末 用定調版本建立 10 個基礎元件（Button、Card、MenuItemRow、Notify、Stepper、OptionCard、Badge、InfoBox、Toast、三態），見 11-設計系統.md §5
W2 生顧客端基礎的其餘頁面（§4.3、§4.4）；結帳付款頁 C-09～C-11 是進階 A5，有空再生
W3 生店家端（§4.5、§4.6），店家端可以粗一點，重點在資訊密度；S-03 櫃檯結帳是基礎唯一的結帳路徑，要先做
W4 預約與會員頁面（§4.7、§4.8）；C-20 點數與優惠券是進階 A6，有空再生
W5 一致性檢查：把 43 張畫面並排看，統一間距、字級、圓角、按鈕樣式
W6 只修不加。截圖做簡報素材、錄操作 GIF

一致性檢查（W5）是最容易被跳過、但最影響觀感的一步。 把所有畫面放在同一張 Figma 畫布上並排看，10 分鐘就能抓出「這頁按鈕 48px、那頁 52px」這類問題。

7. 快速自檢：這個畫面有 AI 感嗎？

完成任何一張設計稿後，問自己這五題。答錯任何一題就回去改。

  1. 頁面底色是不是純白？→ 應該是 #FBF7F0
  2. 有沒有出現紫色或藍紫漸層？→ 應該完全沒有
  3. 標題是不是無襯線字體？→ 應該是思源宋體
  4. 有沒有「三張等寬卡片並排」？→ 應該改成列表或不等寬排列
  5. 文案是不是空泛的四字詞？→ 應該是具體的、有人味的句子
