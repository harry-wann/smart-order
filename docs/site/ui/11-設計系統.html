11 設計系統

這份文件是「所有畫面長什麼樣」的唯一標準。 在動手畫任何一張設計稿、寫任何一行 CSS 之前，先讀完這份。 先定設計規範，再製作畫面。畫面流程與交接順序見 12 UI 設計流程。

1. 設計概念

關鍵字：熱氣、紅湯、白瓷、木桌、鐵鍋、台式老店的親切

不是：科技感、未來感、極簡北歐、深色儀表板

一句話：像一本印得不錯的紙本菜單被搬到手機上，而不是像一個 SaaS 後台。

1.1 中高價位共鍋，為什麼還是走台式感

我們的餐廳定位是中高價位、多人共鍋，但視覺維持台式親切感，不走冷調精緻路線。

理由是客群：共鍋店的主力是家庭與朋友聚餐。詹記就是最好的例子——價位不低，但視覺非常台、非常鮮明。而且我們的設計原則裡有「長輩兒童友善」，暖色調的台式感本來就更貼合。

中高價位和路邊店的差別在執行精準度，不在色票。 所以色票、字體、圓角全部維持，只做三個微調：

微調 具體做法
留白放大一級 卡片內距 16 → 20px、區塊間距 24 → 32px
照片統一打光與色溫 混用不同色溫的素材是最掉價的地方，全部挑暖色調、同一種打光風格
價格呈現保持乾淨 不用刪除線、不用「原價／特價」的促銷感排版

2. 色彩

2.1 色票

@theme 裡每宣告一個 --color-*，Tailwind 就自動長出對應的 class： --color-brand-600 → bg-brand-600／text-brand-600／border-brand-600。 半透明用 opacity modifier，不另開 token：遮罩 bg-ink-900/50、桌況標籤 bg-white/70。

設計稿那一側用的是另一套名字。 docs/ui/mockups/_shared.css（43 張設計稿吃這份） 寫的是沒有 --color- 前綴的舊名，其中五個因為會跟 Tailwind 的 class 撞名而改過： --bg→paper、--border→line、--text-900/600/400→ink-900/600/400。 只有維護設計稿時才需要管這個，完整對照見 14-色彩Token §9。

2.2 在 React 專案裡怎麼用

色票的落地方式全部寫在 14-色彩Token，這裡不重複。 一句話版本：

  • 顏色寫在 frontend/src/styles/tokens.colors.css，用 Tailwind v4 的 @theme
  • 元件裡一律用 bg-brand-600、text-ink-600 這類 class，不准出現 #hex
  • 只有一個畫面用得到的顏色（S-04 出菜看板、C-10 付款品牌色）放該畫面旁邊，不進共用檔

命名跟上面 §2.1 的色票幾乎一樣，只有兩個為了避開 Tailwind 撞名而改過： --text-* → ink-*（否則 class 會變成 text-text-900）、--border → line（否則是 border-border）。 完整對照表在 14-色彩Token §9。

注意版本：專案裝的是 Tailwind v4，沒有 tailwind.config.js，設定寫在 CSS 裡。 網路上大多數教學是 v3，照做會失敗，判斷方法看 39-Tailwind「你會遇到的坑 ⑤」。

圓角寫在 frontend/src/styles/tokens.space.css，七個值各有名字： rounded-card(12) / rounded-btn(8) / rounded-check(6) / rounded-stamp(4) / rounded-notify(14) / rounded-sheet(20) / rounded-pill(999)，對照 §4.2。 不要改用 Tailwind 內建的 rounded-lg／rounded-xl——數值雖然碰巧一樣， 但 §4.2 有七個值，內建刻度只對得上其中兩個，混用會讓另外五個變成寫死的 rounded-[14px]。

字體與字級寫在 frontend/src/styles/tokens.type.css。 字體家族是 @theme 的 --font-sans / --font-serif（備援有點名中文字型，理由見該檔註解）； §3.2 的十個字級則是 @utility，用法 <h1 className="type-h1">：
type-display type-h1 type-h2 明體（Serif）
type-h3 type-body type-body-sm type-caption type-price type-button type-kds-table 黑體（Sans）

字級不拆成 text-[28px] leading-[1.4] font-bold font-serif 四件事分開寫—— 一個 type-* 就把字體、大小、行高、字重一次套上，漏寫其中一項的情況不會發生。

2.3 顏色使用規則

情況 用什麼
主要行動按鈕 brand-600 底 + 白字
次要按鈕 白底 + brand-600 邊框與文字
文字按鈕 ink-600，hover 變 brand-600
價格 brand-600，粗體
推薦／預約優先徽章 accent-500 底 + ink-900

紅色是主色，所以錯誤色要用更暗的紅（#B3261E）才分得出來。 這是常見的陷阱。

2.5 桌況色塊（S-02、DS-08）

桌況總覽一格一張桌，顏色之外一定要有左上角的文字標籤（白色半透明膠囊）。

顯示 底色 邊框 文字 標籤
空桌 --table-available #E6DED2 無 ink-900 空桌
預約保留 accent-100 #FCF0DC accent-500 #E8A33D 1.5px ink-900 預約保留
用餐中 --table-occupied #C8442E 無 白字 用餐中
待清理 --table-cleaning #9C8E84 無 白字 待清理
超時（疊在用餐中上） 同用餐中 danger 3px 內框 白字 用餐中
  • 預約保留是 2026-09-16 加的第四種顯示：空桌在訂位前 30 分～後 10 分被這筆訂位鎖住（10-UI-UX規格.md S-02）。 格內第二行寫「18:30 陳○君 4 位」。邊框用 inset 陰影畫（_shared.css 的 .tt-rs），桌卡尺寸不變，也跟超時的 3px 紅框分得開
  • 只有訂位會鎖桌：桌位沒有其他「保留」狀態、也沒有另外的保留色票，候位也不鎖桌。 所以「還空著但開不了」的桌只有預約保留這一種樣式；櫃檯代客取消那筆訂位後，桌格就地變回空桌
  • 淺黃底上的文字用 ink-900，對比度夠；不要用 accent-600 當字色（在 accent-100 上不到 4.5:1）

2.4 唯一的深色例外

出菜看板 KDS 用深色背景（#241C18）+ 白字。理由：廚房光線強、距離遠，深底高對比最清楚。其他所有頁面一律亮色。

KDS 專用的四個色票（_shared.css 的 --kds-*）：背景 #241C18、卡片 #33261F、分隔線 #4A3A31、文字 #F3EAE0。 強調色沿用主色與輔色：預約優先卡片 accent-500 邊框、等太久的卡片 danger 邊框、勾完的勾選框 success 底。

3.1 選用

4. 間距、圓角、陰影

4.1 間距（8px 基準）

4 / 8 / 12 / 16 / 24 / 32 / 48 / 64

用途 值 備註
頁面左右留白（手機） 16px
卡片內距 20px 例外 1，見 §4.1.1。§1.1「留白放大一級」的值
列表列內距（MenuItemRow 等） 16px 列不是卡片，維持 16
卡片之間 12px
區塊之間 24px §1.1 說可放大到 32px，目前未套用，見下方註
大區塊之間 48px 原本寫 40px，不在基準刻度上，改 48
表單欄位之間 16px

這張表原本跟 §1.1 打架。 原值是「卡片內距 16px、區塊之間 24px、大區塊之間 40px」， 但 §1.1 的「留白放大一級」要求卡片內距 16 → 20、區塊間距 24 → 32。 現在的處理是：卡片內距採 §1.1 的 20px（列表列仍是 16px）， 大區塊之間 40 → 48px（40 不在刻度上，48 才是）。

§1.1 的「區塊間距 24 → 32px」目前沒有套用在 docs/ui/mockups/ 的設計稿上（43 張畫面＋8 張元件總表）。 原因是手機畫框只有 375 × 812，每個區塊多 8px 會把主要操作推出第一屏 （C-05 的數量步進器、C-16 的人數步進器都已經在邊緣）。 真要放大，建議只放大店家端（1280 × 800 空間夠），顧客端維持 24px。

4.1.1 ★ 基準的四個例外

基準管的是版面間距（margin / padding / gap）。 下面四類是刻意不遵守的，實作時照這裡寫的值，不要順手改成 8 的倍數：

# 例外 值 為什麼
1 卡片內距 20px §1.1 中高價位定位，留白放大一級。16 太擠、24 在 375px 的卡片上太空
2 膠囊標籤內距 2px 10px（售完印章 2px 8px） §5.6 Badge、§5.3 售完印章。12px 的字要貼得緊，上下放到 4px 會變胖一圈
3 按鈕左右內距 lg 24px / md 20px / sm 14px §5.1 尺寸表。跟按鈕高度成比例，這是元件尺寸不是版面間距
4 元件內的光學對齊 1–2px 圖示對文字基線、勾選框對行高。這是對齊不是間距

除了這四類，其他所有 margin / padding / gap 都必須落在基準刻度上。

實作：基準刻度不用自訂，Tailwind 預設的 --spacing 就是 4px， 生出來的 p-1/p-2/p-3/p-4/p-6/p-8/p-12/p-16 剛好是 4/8/12/16/24/32/48/64。 frontend/src/styles/tokens.space.css 只額外命名了例外 1（p-card 20）、 列表列（p-row 16）與幾個語意間距（px-page、mt-section 24、mt-section-lg 48）。 例外 2、3 直接寫刻度即可：膠囊 px-2.5 py-0.5、售完印章 px-2 py-0.5、 按鈕 px-6／px-5／px-3.5。

實作時可以用這段掃自己的 CSS：

# 列出所有不在 4/8/12/16/24/32/48/64 上的間距宣告
grep -oE '(margin|padding|gap)[a-z-]*:[^;}]+' src/**/*.css | \
  grep -oE '[0-9]+px' | sort -un | \
  grep -vE '^(0|4|8|12|16|24|32|48|64)px$'

docs/ui/mockups/ 最早的 33 張設計稿照這條規則掃過一次：169 條不合格 → 修到剩 20 條，全部屬於上表四類。 之後每次跑 tools/figma_prep.py 都會自動重掃（例外清單在它的 SPACING_EXCEPTIONS）， 結果列在 dist/lint-report.md 的「間距例外」表，那張表裡的每一條都要對得回上表四類。

4.3 陰影

--shadow-pop:  0 8px 24px rgba(43,33,28,.12);

只有兩級，而且都很淡。陰影用暖黑（43,33,28）不要用純黑或藍黑。 禁止：彩色光暈、發光效果、大面積模糊陰影。

5. 元件規範

設計稿上的元件總表在 Figma 的 01 Design System 那一頁（DS-01～DS-08，1280×1200）。 八張板子把下面每個元件的各種狀態都攤開畫出來：色票與字級、按鈕四變體三尺寸含停用、 輸入與步進器、選擇元件、標籤與容器、品項列與通知、三態與回饋、店家端元件。 總表跟畫面吃同一份 _shared.css —— 不然總表上的按鈕會跟真正畫面上的按鈕慢慢長成兩個東西。

前端只需要自己寫這 10 個元件（Button、Card、MenuItemRow、Notify、Stepper、OptionCard、Badge、InfoBox、Toast、三態），其他都由它們組合而成。指定一位維護者（工作分配定案後指派），放在 src/components/。

白底、1px line、12px 圓角、shadow-card、20px 內距（§1.1 留白放大一級，見 §4.1.1 例外 1）。 可點擊的卡片 hover 時陰影升到 shadow-pop。

注意：列表列（§5.3 MenuItemRow）不是卡片，內距維持 16px。 卡片是「一塊獨立資訊」，列是「一串同類項目裡的一筆」，兩者的呼吸感不一樣。

5.3 MenuItemRow（菜單品項列）★最常出現的元件

  • 高度 ≥ 96px
  • 左：照片 80×80、圓角 12px、object-fit: cover
  • 中：名稱（h3）、描述（body-sm，最多 2 行省略）、價格（price）
  • 右：+ 圓形按鈕 28×28，或數量步進器（見 §5.4 的例外說明）
  • 價格那一列固定 32px 高。這一列會放三種不同的控制項（步進器 30、+ 圓鈕 28、 進入詳情的箭頭 32），高度若跟著控制項走，同一排卡片會一張一張不一樣高， 右欄文字的垂直位置也跟著飄 —— 看起來就像每個品項的留白都沒對齊。 32 是裝得下最高控制項的 8 的倍數。
  • 售完態：照片 filter: grayscale(1) opacity(.55)、名稱與描述轉 ink-400、價格劃線、 名稱旁 danger 膠囊標籤「售完」、照片上斜蓋紅框印章「售完」（§7.2）、+ 鈕變灰、整列 pointer-events: none

5.3b Notify（同桌通知條）

共鍋是一桌好幾支手機同時點餐。別人加了什麼、送出了沒有，不能只靠自己去翻購物車。

  • 從畫面上方滑下、蓋在 appbar 上，停 4 秒自己收回，不用客人關掉
  • 內容一行標題一行說明：誰＋做了什麼、品項＋數量／金額，右側一個相對時間
  • 說明行固定一行，放不下就在尾端截斷加「…」（text-overflow: ellipsis）： 加購物車是「安格斯霜降牛五花 ×1・全份」（有選項才用「・」接 optionSummary），送出訂單是「王大明 送出 3 項・NT$ 460」（N 是份數加總）
  • 資料來源：加購物車是 CART_UPDATED（只有 ADDED 才跳，改數量與刪除不跳），送出訂單是送單事件 NEW_TICKET； 「誰」是同桌的顯示名稱（會員暱稱，沒登入是「客人 1」「客人 2」；櫃檯代客加點是「櫃檯」）
  • 自己做的不跳：事件帶 byGuestId，跟這支手機的 guest id 相同就只更新畫面，不出通知條
  • 左側 32×32 圓形頭像：加購物車用 brand-100／brand-600，送出訂單用 success-bg／success
  • 底部一條 32×3 的 grip，暗示「可以往上滑掉」
  • 後來的蓋掉前一則，不堆疊。 一桌四個人同時點，堆疊會把整個畫面吃掉
  • 出現在所有點餐畫面（C-04、C-05、C-06、C-08）；C-09 付款頁（進階 A5）不放，整桌結清（SESSION_CLOSED）後就不再出現
  • 這個元件取代了原本掛在服務鈴上的紅點。 紅點只說「有事」，還要客人點開才知道是什麼； 通知條直接說誰做了什麼。服務鈴從此只有一個意思：我要叫人

5.4 Stepper（數量步進器）

★ 這一節低於「可點擊區 ≥ 44×44px」那條規則，是刻意的取捨。 44×44 的步進器在 375px 的品項列上佔 124px，超過整列寬度的三分之一， 視覺重量壓過品項名稱與價格。整組縮過兩次：44 → 36 → 28， 品項列上的寬度從 124px 降到 80px。 代價是觸控區明顯小於建議值 —— 但步進器左右都是空白， 實際可按範圍比 28px 大，誤觸風險低。 28 是這個元件的下限，再往下就真的按不到了； 其他所有主要行動按鈕維持 52px，這個例外不擴散。

  • − 與 + 為 28×28 圓形按鈕，數字區寬 32px 置中（列表列內用 24px）
  • 菜單列上直接加入的 + 圓形按鈕同樣是 28×28，與步進器成套
  • 第二個例外：有必選選項的品項，價格列最右邊是進詳情的箭頭 32×32（.mi .foot .iconbtn）。 整列本來就可點（10-UI-UX規格.md C-04），箭頭只是提示，所以不放大到 44
  • 數量為 0 時 − 變成垃圾桶圖示
  • 按下有輕微縮放回饋
  • 開桌頁的現場頁籤（S-02b）與訂位人數（C-16c）用的是大型步進器：按鈕 56×56、數字 40px 宋體，不受上面這條例外影響

5.5 OptionCard（選項選擇）

  • 單選：整張卡片可點，選中時 brand-100 底 + brand-600 1.5px 邊框 + 右側勾勾
  • 複選：左側方形勾選框 24×24（圓角 6px）；單選的圓點也是 24×24
  • 右側顯示價差，0 元不顯示
  • 高度 ≥ 56px

膠囊形、12px 字、padding: 2px 10px

5.6b InfoBox（提示框）

一行圖示＋一段說明，padding: 12px 16px、8px 圓角、14px 字。五種語氣，要跟內容對得上，不要什麼都用警告色：

語氣 樣式 用在哪
成功 ib-ok success-bg 底、深綠字 「這桌櫃檯已經開好了，直接開始點就可以」
警告 ib-warn warning-bg 底、深橘字 「這張桌保留給 陳怡君 18:30（4 位）。客人來電取消的話，請到預約管理取消訂位」、「剛剛有人加點，金額更新了」
強烈提醒 ib-danger danger-bg 底、深紅字 #7A1B15、1.5px danger 內框、danger 警示圖示 只用在開桌衝突：「A06 在 19:30 有訂位（陳小姐 4 位）。現在開桌，客人可能還沒吃完訂位就到了。」
資訊 ib-info info-bg 底、深藍字 教學專題聲明、模擬簡訊驗證碼
安靜 ib-quiet surface-2 底、ink-600 字 取消政策、訂位保留 10 分鐘這類規則說明
  • ib-danger 的用法：開桌時這張桌 115 分鐘內有別筆訂位（S-02b／S-02c／S-02d 頂部）。它只提醒、不擋， 但比暖黃的一般提醒醒目；出現時開桌主按鈕改成「仍要開桌」，按下再跳一次確認框。不要拿它當錯誤訊息（錯誤用 Toast 或欄位下的紅字）
  • 同一件事在選桌清單（S-07b／S-10b）的卡片上是紅字＋警示圖示「19:30 有訂位」（_shared.css 的 .t-clash，13px 粗體 danger），卡片排在沒衝突的桌後面

5.7 Toast

畫面上方滑入、3 秒後自動消失、最多同時 1 個。成功綠、錯誤紅、一般深色，8px 圓角。不要用瀏覽器的 alert()。

5.8 EmptyState / Skeleton / ErrorState

三態元件（見 10-UI-UX規格.md §1）。骨架屏用 surface-2 色塊 + 呼吸動畫，不要用轉圈圈。

對話框不另列元件。 待清理確認框（S-02）、選桌開桌（S-07b／S-10b）、付款倒數（S-03b）都是 .scrim 壓暗背景＋一張 Card＋Button 組起來的，所以上面的元件數仍然是 10 個。付款倒數多四條規則：

  • 倒數數字用宋體、tabular-nums，比 display 再大一級（建議 64px），每秒換一次；prefers-reduced-motion 時只換數字不做動畫
  • 倒數中只有一顆 ghost「取消」，沒有 primary——倒數到 0 會自己送出，不需要再按
  • 現金、信用卡、條碼都用同一個對話框、都倒數 5 秒，只換標題：現金「收款中，請把現金放進收銀機」、信用卡「信用卡付款中」、條碼「條碼付款中」。 現金的標題最長（13 個字）：h1 28px × 13＝364px，設計稿對話框寬 440、內距 32，內寬 376px 剛好一行放得下，不要縮字級
  • 成功態沿用 DS-07 的「完成」（勾勾描邊 0.6 秒後停住）＋「結帳完成」，約 1.5 秒後自動關閉，不放關閉按鈕；教學專題聲明用 caption 小字，不用 InfoBox

6.4 ★ 圖片佔位一定要標註「放什麼圖」

設計稿和 HTML 草稿裡，不准出現沒有說明的灰色方塊。每一個要放圖的位置，都必須當場寫清楚三件事：

要寫什麼 例子

尺寸與比例 1600×900・16:9
建議搜尋關鍵字 taiwanese hotpot restaurant interior

為什麼要做到這個程度：

  1. 實作的人不用猜。 拿到設計稿的人照著標註去 Unsplash / Pexels 搜，十分鐘就能把圖補完，不用回頭問。
  2. 沒標註的空框會被當成留白。 實作時很容易被直接無視，或隨手塞一張不對調性的圖——這是整個畫面掉價最快的方式。

7. ★「不要有 AI 感」檢查表

這是本文件最重要的一節。每張設計稿完成後逐條檢查。 AI 生成的介面之所以一眼就看得出來，是因為模型在沒有明確指示時，會退回訓練資料中最常見的那組預設值——而那組預設值就是 2019 年之後大量 Tailwind 教學文章的樣子。

7.1 十一個必檢項目

# ❌ AI 感來源 ✅ 我們的做法
1 頁面底色用純白 #FFFFFF 用暖米白 #FBF7F0
2 中性色用 Tailwind 預設的 gray / slate（偏冷偏藍） 用暖灰 #E6DED2 / #6B5D54 / #2B211C
3 靛藍到紫的漸層（最經典的 AI 標記） 全站禁用紫色與藍紫漸層；漸層只出現在照片上的深色遮罩
4 標題用 Inter 或系統預設無襯線 標題用 Noto Serif TC（明體）
5 「三張等寬圓角卡片並排」的功能區塊 菜單用左圖右文的列表；推薦區用橫向捲動；避免對稱三欄
6 所有元素同一個大圓角（rounded-2xl） 卡片 12px、按鈕 8px、標籤 999px，分層級
7 細線條通用 icon 當主視覺 主視覺用真實食物照片；icon 只在次要位置且統一用 lucide
8 空泛的文案（「輕鬆點餐，美味享受」） 具體：「掃桌號就能點，不用等服務生」「厚切 3mm，涮 8 秒最好吃」
9 AI 生成的食物插圖 Unsplash / Pexels 的真實照片
10 用 emoji 當 icon（🍲🔥✨） 用 lucide 圖示或自製 SVG。emoji 在不同裝置長得不一樣
11 沒有說明的灰色佔位方塊，或乾脆不留放圖的空間 每個佔位都標註「放什麼圖 + 尺寸 + 搜尋關鍵字」，見 §6.4

7.2 額外加分：三個「只有這家店有」的細節

AI 不會主動想到這些，加進去立刻有人味：

  1. 手寫感的「今日推薦」木牌：在菜單推薦區用木紋底 + 手寫字體的小標題
  2. 鍋子形狀的載入動畫：火鍋冒泡泡，不是通用轉圈
  3. 售完的「印章」效果：斜蓋在照片上的紅色方框印章「售完」，不是灰化了事

7.3 一句話原則

先做完設計決定，再打開 AI。 AI 是執行你的決定的工具，不是幫你決定品味的人。 製作 Figma 畫面前，先用這份文件核對色票、字級、元件和可讀性。

8. 給前端的實作備忘

// src/components/Button.jsx — 範例，其餘元件比照辦理
const styles = {
  primary:   'bg-brand-600 text-white hover:bg-brand-500 active:bg-brand-700',
  secondary: 'bg-white text-brand-600 border-[1.5px] border-brand-600 hover:bg-brand-100',
  ghost:     'bg-transparent text-ink-600 hover:text-brand-600',
  danger:    'bg-danger text-white hover:opacity-90',
};
const sizes = {
  lg: 'h-[52px] text-[18px] px-6',
  md: 'h-11 text-base px-5',
  sm: 'h-9 text-sm px-3.5',
};

export default function Button({
  variant = 'primary', size = 'lg', loading = false,
  disabled, className = '', children, ...rest
}) {
  return (
    <button
      disabled={disabled || loading}
      className={[
        'rounded-btn font-medium transition-all active:scale-[.98]',
        'disabled:opacity-40 disabled:cursor-not-allowed disabled:active:scale-100',
        'focus-visible:outline focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-brand-600',
        styles[variant], sizes[size], className,
      ].join(' ')}
      {...rest}
    >
      {loading ? '處理中…' : children}
    </button>
  );
}

三個容易忘的細節

  1. active:scale-[.98] 讓按鈕有「按下去」的手感，成本一行
  2. focus-visible 的外框是鍵盤操作的必要，不要用 outline-none 砍掉
  3. disabled 時要同時關掉 hover 與 active 效果，否則看起來像還能按
