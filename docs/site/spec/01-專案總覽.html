01 專案總覽

1. 專案定位

一句話：一套給中高價位、多人共鍋的台式火鍋店用的線上點餐系統。顧客掃桌上的 QR code 就能自己點餐、加點、按服務鈴，用餐完畢到櫃檯結帳（手機線上結帳是進階）；店家端有桌況、候位、出菜看板與庫存。

專案代號：smart_order

系統定位：店家的半輔助工具，不是完整 POS。 我們管「點什麼、出到哪、坐多久」，不管「錢怎麼進抽屜」。

2. 目標與非目標

目標

  1. 做出一條從掃碼到結帳完整走得通、不會壞的顧客點餐流程
  2. 店家端能即時看到桌況與出菜進度，並管理菜單、庫存、候位與訂位
  3. 用對的技術解決對的情境（WebSocket 做即時、排程做定時、區間重疊做訂位），而不是繞路
  4. 專案可作為五位成員的求職作品：有線上 demo、有 README、每人能講出一個技術故事

非目標

不做 原因
真實金流與簡訊串接 需商家申請與正式網域，對評分無幫助
找零、交班、日結、稽核、發票 系統定位是半輔助工具
外帶／外送、多分店 範圍控制
吃到飽計價 需額外的時限與加點規則
個人鍋 本店是共鍋形式
原生 App 手機瀏覽器足夠

3. 使用者角色

角色 代號 裝置 說明

7. 名詞定義（Glossary）

這張表非常重要。 程式碼命名、API 路徑、資料表名稱、口頭討論一律以本表為準。五個人對同一個東西用五個名字，是團體專題最常見的溝通災難。

中文 程式碼 定義
用餐紀錄／帳單 DiningSession 一桌從開桌到結帳的完整一次。結帳、集點、消費紀錄都以此為單位
購物車 CartItem 整桌共用、存在後端（cart_item）。同桌每支手機看到同一份，誰都能增減、刪除；每列記下是誰加的
同桌客人 DiningSessionGuest 同一次用餐裡的「誰」：前端產生的裝置 UUID（X-Device-Id）＋顯示名稱（會員暱稱，或依加入順序「客人 1」「客人 2」）。只用來標示誰加的，不是身分驗證；同桌通知靠它的 id（byGuestId）判斷「是不是我自己」，自己的動作不通知自己
點餐單 OrderTicket 一次「送出整桌點餐」＝整份購物車變一張＝出單機印一張。一次用餐可以有多張
單品 OrderItem 點餐單裡的一個品項 + 數量 + 選項
N 項（數量） quantity 加總 N 項＝份數加總，不是列數。白飯 ×2 算 2 項。購物車角標（totalQuantity）、C-06「小計 N 項」、C-04c「送出 N 項」（NEW_TICKET 的 quantity）、C-07 每張單的件數、S-03「小計 N 項」、預點的「已預先點餐 N 項」全部這樣算；畫面文字維持「項」
品項 MenuItem 菜單上的一道菜
分類 MenuCategory 鍋底／肉品／海鮮／蔬菜／火鍋料／主食／飲料／酒（與 03 種子資料一致）
選項群組 OptionGroup 一組可選規格（份量、辣度、加點），有最少／最多選幾個
選項 OptionValue 群組裡的一個選擇，可帶價差
鍋底 Soup Base is_soup_base = true 的品項。每桌至少一份（共鍋）。在 C-04 是一個分類頁籤，送出訂單時沒有鍋底回 400 SOUP_BASE_REQUIRED
鴛鴦鍋 — 一個品項掛兩個 min=1 max=1 群組（左鍋／右鍋）
免費續加 Refill price = 0 且 track_inventory = false，但仍要出單
桌位 DiningTable 實體的一張桌子
用餐權杖 sessionToken 顧客端的 API 憑證，結帳後立刻失效
服務鈴 ServiceCall 呼叫服務生／加湯／換鍋撈渣（沒有結帳，結帳請到櫃檯）
候位 Waitlist 現場排隊取號
訂位 Reservation 線上預訂某時段某桌；只能訂明天起 30 天內，當天不接線上訂位
預約保留 displayStatus = RESERVED 訂位配到的桌，在訂位時間前 30 分～後 10 分顯示「預約保留」，不能開給別人；要解開就是櫃檯代客取消那筆訂位（沒有「只解除保留」的功能）。查桌況時算出來的，不存在 dining_table.status、不靠排程（M7 7.10）。只有訂位會鎖桌，候位不鎖桌
代客取消 cancel_source = STAFF 客人來電說不來了，櫃檯在 S-07／S-02d 幫他取消訂位（M7 7.18）。隨時可以取消，不受期限；單向，取消後無法恢復。客人自己線上取消只到訂位時間前 30 分鐘（cancel_source = CUSTOMER）
開桌強烈提醒 upcomingOnThisTable 要開的桌在「現在～現在 + 115 分」內有別筆訂位要開始，開桌頁顯示醒目警示、主按鈕改「仍要開桌」並再確認一次；只提醒不擋
清桌緩衝 Buffer 訂位的 end_time 已包含的 15 分鐘
出菜看板 KDS 廚房看的畫面
已結清 — 櫃檯標記收款完成（現金／信用卡／條碼，按下後倒數 5 秒的模擬流程），dining_session 轉 PAID。基礎的結帳就是這個
金額比對 expectedTotal 結清／付款時帶上畫面看到的合計，後端重算不一樣就回 409 BILL_CHANGED。取代舊的「結帳中」鎖定
訂位保留時間 — 訂位時間後 10 分鐘。逾時視同 NO_SHOW，只能現場候位；配到的桌的預約保留也到這時為止
最早報到 — 訂位時間前 30 分鐘。更早按報到回 409 RESERVATION_TOO_EARLY；預約保留也從這時開始
