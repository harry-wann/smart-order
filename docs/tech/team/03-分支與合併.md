# 分支、合併與衝突

**難度** ★★★☆☆　**用在哪些模組** 全員　**哪幾週** 全程

## 一句話

分支就是**開一條平行時空**，你在裡面亂搞都不會影響到別人。

## 想像一下

五個人一起寫同一份報告。如果大家都直接改同一個檔案，會發生什麼事？

A 改到一半、B 也在改、C 存檔的時候把 A 的東西蓋掉了。一團亂。

**分支的做法是**：每個人先「複製一份」出來改。

- A 複製一份叫「A的新章節」，在裡面寫
- B 複製一份叫「B的圖表」，在裡面畫
- 各改各的，完全不會互相影響
- 誰做完了，再把自己那份**合併**回主要版本

複製出來的那一份就叫**分支**，合併回去叫 **merge**。

## 我們的分支規則

```
main          ← 隨時可以拿去部署的乾淨版本
  └ develop   ← 大家的東西先合併到這裡
      ├ feature/menu-crud          ← B 的菜單功能
      ├ feature/order-submit       ← B 的點餐功能
      ├ feature/customer-cart      ← D 的購物車
      └ fix/kds-polling-bug        ← 修 bug
```

三條鐵律：

1. **絕對不要直接在 `main` 或 `develop` 上寫程式**（GitHub 上會設定擋住）
2. 每做一個功能，開一條 `feature/xxx` 分支
3. 做完了發 Pull Request，讓隊友看過再合併

## 日常操作

```bash
# 1. 先確保你的 develop 是最新的
git checkout develop
git pull

# 2. 從 develop 開一條新分支
git checkout -b feature/menu-crud

# ... 寫程式、commit 好幾次 ...

# 3. 推上去
git push -u origin feature/menu-crud

# 4. 去 GitHub 發 Pull Request（見下一頁）
```

## 什麼是衝突

**衝突（conflict）不是壞事，也不是你做錯了。** 它是 Git 在跟你說：

> 「你跟隊友改了同一個檔案的同一行，我不知道該留誰的，你決定。」

衝突長這樣：

```java
<<<<<<< HEAD
    private BigDecimal serviceFee;      ← 你的版本
=======
    private BigDecimal serviceCharge;   ← 隊友的版本
>>>>>>> develop
```

處理方式：

1. **打開那個檔案**，找到 `<<<<<<<` 的地方
2. **決定要留哪個**（或兩個都留、或重寫）
3. **把 `<<<<<<<`、`=======`、`>>>>>>>` 這三行刪掉**
4. `git add` 那個檔案 → `git commit`

就這樣。真的沒有比較複雜。

**但如果衝突很大你看不懂，去找那個跟你衝突的隊友一起看。** 這不是丟臉的事，這是正確做法——因為只有他知道他為什麼那樣改。

## 怎麼減少衝突

| 做法 | 為什麼有用 |
|---|---|
| **每天早上先 `git pull`** | 落後越久，衝突越大 |
| **一條分支只做一件事** | 動到的檔案少，撞到的機會就少 |
| **共用檔案指定唯一負責人** | `schema.sql` 只有 A 能改，其他人開 issue 請他改 |
| **功能做完馬上合併** | 分支活越久越危險 |

## 15 分鐘動手小練習

故意製造一次衝突，然後解掉它：

1. 在練習專案裡建 `test.txt`，寫「你好」，commit
2. `git checkout -b branch-a`，把內容改成「早安」，commit
3. `git checkout main`（或 master），把內容改成「晚安」，commit
4. `git merge branch-a` ← 這裡會衝突
5. 打開 `test.txt`，你會看到 `<<<<<<<` 那一串
6. 決定要留哪個，刪掉那三行記號
7. `git add test.txt` → `git commit`

**自己製造一次衝突再解掉，比看十篇文章有用。** 而且以後真的遇到就不會慌。

## 你會遇到的坑

**① 在錯的分支上寫程式**
寫了一小時才發現自己在 `develop` 上。
→ 動手前先 `git branch` 確認自己在哪。

**② `git push -f`（強制推送）**
這會把隊友的東西直接抹掉。**在共用分支上是絕對禁止的。**

**③ 分支活太久**
一條分支開了三個星期沒合併，合的時候會爆炸。
→ 一條分支最好三天內合併掉。

**④ 看到衝突就慌**
衝突是正常的日常，不是災難。

## 常見錯誤訊息對照

| 你會看到 | 中文意思 | 怎麼修 |
|---|---|---|
| `CONFLICT (content): Merge conflict in xxx` | 檔案衝突了 | 照上面的四步驟處理 |
| `Your local changes would be overwritten` | 你有沒存檔的東西會被蓋掉 | 先 commit，或用 `git stash` 暫存 |
| `fatal: refusing to merge unrelated histories` | 兩邊沒有共同祖先 | 通常是 repo 建錯了，找組長 |
| `error: failed to push some refs` | 遠端有你沒有的東西 | 先 `git pull` 再 push |

## 術語對照表

| 白話 | 正式名稱 |
|---|---|
| 平行時空、複製一份 | 分支 branch |
| 合併回去 | merge |
| 撞在一起了 | 衝突 conflict |
| 切換到某個分支 | `git checkout` / `git switch` |
| 請求把我的合併進去 | Pull Request（PR） |
| 主線 | main / develop |
