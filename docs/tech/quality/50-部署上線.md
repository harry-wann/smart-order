# 部署上線

**難度** ★★★★☆　**用在哪些模組** 技術地基 L0　**哪幾週** 第 5 週（★不能拖到第 6 週）

## 一句話

把你們電腦上跑的東西，搬到一個**任何人都連得到的網址**上。

## 為什麼這是本專題最重要的一件事

> **面試官不會 clone 你的 repo、裝 MySQL、開 Docker、跑起來看。**

沒有線上連結，這個專案在履歷上的價值大概打三折。

**有一個能點開就操作的網址**，加上一個測試帳號，威力完全不同。

## 三個部分要各自安家

```
顧客端 React  →  靜態主機（Vercel / Netlify）
店家端 React  →  靜態主機（Vercel / Netlify）
Spring Boot   →  應用主機（Render / Railway / Fly.io）
MySQL         →  雲端資料庫（Railway / Aiven 免費方案）
```

## 前端：Vercel（最簡單）

1. 用 GitHub 帳號登入 [Vercel](https://vercel.com)
2. Import 你的 repo
3. 設定：
   - **Root Directory**：`frontend-customer`
   - **Build Command**：`npm run build`
   - **Output Directory**：`dist`
4. 環境變數：`VITE_API_BASE` = 你的後端網址
5. Deploy

**之後每次 push 到 `main` 就自動重新部署。** 店家端再做一次同樣的步驟。

**一定要設 SPA 重寫規則**，否則在 `/order/menu` 按重新整理會 404。建 `vercel.json`：

```json
{
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}
```

## 後端：Render 或 Railway

**用 Dockerfile 部署最穩：**

```dockerfile
# backend/Dockerfile
FROM maven:3.9-eclipse-temurin-17 AS build
WORKDIR /app
COPY pom.xml .
RUN mvn dependency:go-offline
COPY src ./src
RUN mvn clean package -DskipTests

FROM eclipse-temurin:17-jre
WORKDIR /app
COPY --from=build /app/target/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

然後在平台上：

1. 連結 GitHub repo，Root Directory 設 `backend`
2. 設定環境變數（見下）
3. Deploy

## 環境變數清單（一定要用環境變數，不要寫死）

| 變數 | 值 |
|---|---|
| `SPRING_PROFILES_ACTIVE` | `prod` |
| `SPRING_DATASOURCE_URL` | 雲端 MySQL 的連線字串 |
| `SPRING_DATASOURCE_USERNAME` | |
| `SPRING_DATASOURCE_PASSWORD` | |
| `SMARTORDER_JWT_SECRET` | 32 字元以上的隨機字串 |
| `SMARTORDER_CORS_ORIGINS` | 你的兩個 Vercel 網址 |

**絕對不要把這些 commit 上 GitHub。**

## 你一定會遇到的四個坑

### ① CORS（100% 會遇到）

正式環境的前端網址沒加進 `allowedOrigins`。

```java
.allowedOrigins(corsOrigins.split(","))   // 從環境變數讀
```

→ 看 [CORS 跨來源問題](../web/11-CORS跨來源.md)

### ② 前端重新整理變 404

SPA 路由問題，見上面的 `vercel.json`。

### ③ WebSocket 連不上

兩個原因：

- **平台不支援協定升級** → Render / Railway 支援，某些免費 CDN 不支援
- **HTTPS 頁面用了 `ws://`** → 必須用 `wss://`

```js
const WS_URL = import.meta.env.VITE_WS_URL;   // wss://your-api.onrender.com/ws
```

### ④ 免費方案會「睡著」

Render 免費方案在 15 分鐘沒人用之後會休眠，**下次有人訪問要等 30～50 秒才醒來**。

Demo 當天的對策：**開始前 5 分鐘先打開網站叫醒它**。這件事寫進你們的 demo 檢查清單。

## 資料庫怎麼上

1. 在 Railway 或 Aiven 開一個免費的 MySQL
2. 把連線資訊填進後端的環境變數
3. **第一次啟動時 [Flyway](../database/29-Flyway.md) 會自動建表**
4. 種子資料另外跑一次（可以做一支只有管理員能呼叫的 API，或手動匯入 SQL）

## 部署檢查清單

第 5 週完成部署後，逐項確認：

- [ ] 顧客端網址打得開
- [ ] 店家端網址打得開
- [ ] 後端 `/actuator/health` 回 `UP`
- [ ] Swagger 打得開（demo 時建議開著）
- [ ] 櫃檯點空桌開桌 → 手機掃碼 → 加進購物車 → 送出整桌點餐 → 櫃檯結清（付款倒數跑完），整條路通
- [ ] **兩支手機同一桌，即時同步有作用**（WebSocket 通了）：一支加進購物車，另一支的購物車角標跟著變、跳出「誰加了什麼」（加的那支自己不跳）
- [ ] 店家端登入、桌況、KDS 正常
- [ ] 在 `/order/menu` 按 F5 不會 404
- [ ] 手機實機測過（**iOS Safari 一定要測**）
- [ ] 種子資料有進去（菜單、桌位都有；有做進階 A7 人氣推薦或 A4 報表的話，推薦和報表也不是空的）
- [ ] 測試帳號寫進 README

**「第一次開啟可能需要 30 秒」這句話一定要寫**，不然面試官會以為你的網站壞了。

## 15 分鐘動手小練習

**不要等到第 5 週。第 2 週就做一次技術驗證：**

1. 用 Vercel 部署一個只有「Hello」的 React 頁面
2. 用 Render 部署一個只有 `/api/hello` 的 Spring Boot
3. 讓前端成功打到後端（這步就會遇到 CORS）
4. 記下整個流程花了多久、卡在哪

**提前知道會卡什麼，第 5 週才不會慌。**

## 你會遇到的坑

**① 拖到最後一週才部署**
**這是每年最多組翻車的地方。** 第一次部署一定會卡住，留三天以上的緩衝。

**② 把密碼 commit 上去**
一旦推上 GitHub，歷史紀錄裡永遠都在。

**③ 沒測手機實機**
在 Chrome 的手機模擬器上好好的，真的 iPhone 上破版。

**④ Demo 當天沒叫醒服務**
評審看到轉圈圈 50 秒。

**⑤ 沒有備援**
網路掛掉就什麼都演不了。
→ **錄一段 3 分鐘的完整操作影片**，放在簡報裡當備案。

## 常見錯誤訊息對照

| 你會看到 | 中文意思 | 怎麼修 |
|---|---|---|
| 前端一片空白，Console 說 `Failed to load module` | 打包路徑錯 | 檢查 `base` 設定 |
| `CORS policy` | 正式網址沒加進白名單 | 更新 `allowedOrigins` |
| 重新整理 404 | SPA 路由沒設 | 加 `vercel.json` rewrites |
| `Mixed Content: ... ws://` | HTTPS 頁面用 ws | 改 `wss://` |
| 後端 502 / 一直轉 | 服務睡著了，或啟動失敗 | 等一下，或看平台的日誌 |
| `Communications link failure` | 連不到資料庫 | 檢查連線字串和防火牆設定 |
