# 依賴注入

**難度** ★★★☆☆　**用在哪些模組** 所有後端工作　**哪幾週** 第 1 週（L0）、第 3 週

## 一句話

依賴注入就是**你不用自己去 `new` 東西，Spring 會把你需要的東西放到你手上**。

## 想像一下

你在餐廳當廚師，需要一把刀。有兩種做法：

**做法一：自己做刀**
你每次要切菜，就自己去打一把刀。
- 你得懂打鐵
- 刀子壞了你要自己修
- 餐廳換用陶瓷刀，你要重學

**做法二：跟餐廳要**
你跟餐廳說「我需要一把刀」，餐廳給你。
- 你只要會用刀
- 刀哪來的、怎麼保養，不關你的事
- 餐廳想換成陶瓷刀，你完全不用改

**做法二就是依賴注入。** 你宣告你需要什麼，別人（Spring）給你。

## 程式碼上的差別

**自己 new（做法一）**

```java
public class MenuService {
    private MenuRepository repo = new MenuRepository();  // 自己做刀
}
```

問題：
- `MenuRepository` 需要資料庫連線，那連線又要自己 new，然後連線又需要設定……一路 new 到天荒地老
- 測試的時候沒辦法換成假的 Repository

**依賴注入（做法二）**

```java
@Service
public class MenuService {

    private final MenuRepository menuRepository;

    // 建構子裡宣告「我需要一個 MenuRepository」
    public MenuService(MenuRepository menuRepository) {
        this.menuRepository = menuRepository;
    }
}
```

Spring 啟動時看到 `@Service`，就知道要建立 `MenuService`。看到它的建構子需要 `MenuRepository`，就去找一個給它。**整條鏈自動串好。**

## 那些標籤在幹嘛

```java
@Component    // 通用：這個類別交給 Spring 管
@Service      // 商業邏輯層（本質上就是 @Component，只是語意更清楚）
@Repository   // 資料存取層
@RestController // API 控制器
@Configuration  // 設定類別
```

**貼上這些標籤 = 跟 Spring 說「這個東西你幫我保管一份」。** Spring 保管的物件叫 **Bean**。

## 三種注入寫法，只用一種

```java
// ✅ 建構子注入 —— 我們統一用這個
@Service
public class MenuService {
    private final MenuRepository repo;
    public MenuService(MenuRepository repo) { this.repo = repo; }
}

// ⚠️ 欄位注入 —— 很多舊教學這樣寫，但不推薦
@Service
public class MenuService {
    @Autowired
    private MenuRepository repo;
}
```

**為什麼用建構子注入？**

1. 可以用 `final`，代表這個東西建立後不會被換掉
2. 寫測試時可以直接 `new MenuService(假的Repository)`，不需要啟動整個 Spring
3. 如果某個依賴找不到，**啟動時就會失敗**，而不是跑到一半才 NullPointerException

**Lombok 小技巧**：加上 `@RequiredArgsConstructor`，Lombok 會自動幫你產生那個建構子：

```java
@Service
@RequiredArgsConstructor          // 自動產生建構子
public class MenuService {
    private final MenuRepository menuRepository;   // 只要宣告成 final 就好
    private final InventoryService inventoryService;
}
```

**我們專案統一用這個寫法。**

## 在我們的專案裡

```java
@RestController
@RequiredArgsConstructor
public class OrderController {
    private final OrderService orderService;      // Spring 給我
}

@Service
@RequiredArgsConstructor
public class OrderService {
    private final OrderTicketRepository ticketRepo;   // Spring 給我
    private final InventoryService inventoryService;  // Spring 給我
    private final SimpMessagingTemplate messaging;    // Spring 給我（WebSocket 用）
}
```

**你從頭到尾沒有 `new` 過任何一個。** 這就是依賴注入。

## 15 分鐘動手小練習

在你的 Hello 專案裡：

1. 建一個 `GreetingService`：

```java
@Service
public class GreetingService {
    public String greet(String name) {
        return "歡迎光臨，" + name + "！";
    }
}
```

2. 在 Controller 裡注入它：

```java
@RestController
@RequiredArgsConstructor
public class HelloController {
    private final GreetingService greetingService;

    @GetMapping("/hello")
    public String hello(@RequestParam String name) {
        return greetingService.greet(name);
    }
}
```

3. 打開 `http://localhost:8080/hello?name=Harry`
4. **然後把 `GreetingService` 上面的 `@Service` 刪掉，重跑。** 看它怎麼噴錯——這個錯誤訊息你以後會看到很多次，先認識一下。

## 你會遇到的坑

**① 忘記貼 `@Service`**
Spring 不知道要管這個類別，注入時找不到。
→ 錯誤訊息：`required a bean of type ... that could not be found`

**② 自己 `new` 了 Service**
`new MenuService()` 出來的物件裡面的依賴全是 null，一用就 NPE。
→ **在 Spring 專案裡，需要注入的東西一律不要自己 new。**

**③ 循環依賴**
A 需要 B，B 又需要 A。Spring 會轉不出來。
→ 通常代表你的分層有問題，把共用的邏輯抽成第三個 Service。

**④ 同一種型別有兩個實作**
Spring 不知道要給哪個。
→ 用 `@Qualifier("名字")` 指定，或 `@Primary` 標一個預設。

## 常見錯誤訊息對照

| 你會看到 | 中文意思 | 怎麼修 |
|---|---|---|
| `required a bean of type 'X' that could not be found` | 找不到可以注入的 X | X 的類別上貼 `@Service`／`@Component` |
| `The dependencies of some of the beans form a cycle` | 循環依賴 | 重新設計分層，抽出共用邏輯 |
| `expected single matching bean but found 2` | 有兩個候選 | 用 `@Qualifier` 或 `@Primary` |
| `NullPointerException` 在一個注入的欄位上 | 你自己 new 了這個物件 | 改用注入 |

## 術語對照表

| 白話 | 正式名稱 |
|---|---|
| 我不用自己做，別人給我 | 依賴注入 DI（Dependency Injection） |
| 控制權交出去 | 控制反轉 IoC（Inversion of Control） |
| Spring 保管的物件 | Bean |
| Spring 的倉庫 | 容器 Container / ApplicationContext |
| 用建構子拿到依賴 | 建構子注入 constructor injection |
