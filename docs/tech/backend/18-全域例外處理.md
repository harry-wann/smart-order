# 全域例外處理

**難度** ★★☆☆☆　**用在哪些模組** 技術地基 L0　**哪幾週** 第 1 週

## 一句話

在一個地方**統一接住所有錯誤**，翻譯成前端看得懂的格式。

## 想像一下

沒有全域例外處理的時候，前端收到的錯誤長這樣：

```json
{
  "timestamp": "2026-09-13T18:30:00.000+00:00",
  "status": 500,
  "error": "Internal Server Error",
  "trace": "java.lang.NullPointerException: Cannot invoke \"com.smartorder.menu.MenuItem.getPrice()\" because \"item\" is null\n\tat com.smartorder.order.OrderService.calculateTotal(OrderService.java:87)\n\tat com.smartorder.order.OrderService.submitOrder(OrderService.java:45)\n\t... 還有 80 行 ...",
  "path": "/api/dining-sessions/me/orders"
}
```

前端看到這個，只能顯示「發生錯誤」。使用者完全不知道發生什麼事。

**而且**：那串 `trace` 把你的套件結構、檔案名稱、行號全部告訴外面的人了，這是安全問題。

## 我們要的效果

```json
{
  "timestamp": "2026-09-13T18:30:00+08:00",
  "status": 409,
  "code": "ITEM_SOLD_OUT",
  "message": "部分品項已售完，請調整後重新送出",
  "path": "/api/dining-sessions/me/orders",
  "details": [
    { "field": "menuItemId", "message": "美國牛五花 庫存不足（剩 1）", "value": 12 }
  ]
}
```

前端拿到這個，就能：
- 看 `code` 決定要做什麼（`ITEM_SOLD_OUT` → 標紅品項）
- 把 `message` 直接顯示給使用者
- 用 `details` 標出是哪一項出問題

## 怎麼做

**第一步：定義統一的錯誤格式**

```java
public record ApiError(
    String timestamp,
    int status,
    String code,
    String message,
    String path,
    List<FieldError> details,
    @JsonIgnore Map<String, Object> extra     // 少數錯誤要多帶的資料（例如 BILL_CHANGED 的 bill）
) {
    public record FieldError(String field, String message, Object value) {}

    // 大部分錯誤沒有額外資料，用這個六個參數的版本就好
    public ApiError(String timestamp, int status, String code, String message,
                    String path, List<FieldError> details) {
        this(timestamp, status, code, message, path, details, Map.of());
    }

    @JsonAnyGetter                             // 把 extra 攤平成同一層的欄位，前端直接讀 err.bill
    public Map<String, Object> extraFields() { return extra; }
}
```

**第二步：定義自己的例外**

```java
public class BusinessException extends RuntimeException {
    private final String code;
    private final HttpStatus status;
    private final Map<String, Object> extra = new LinkedHashMap<>();   // 要多帶給前端的資料

    public BusinessException(String code, String message, HttpStatus status) {
        super(message);
        this.code = code;
        this.status = status;
    }

    // 串起來用：throw new BusinessException(...).with("bill", billDto);
    public BusinessException with(String key, Object value) {
        extra.put(key, value);
        return this;
    }
    // getter ...（含 getExtra()）
}
```

**第三步：一個類別接住全部**

```java
@RestControllerAdvice          // ← 關鍵：這個標籤讓它接住所有 Controller 的例外
public class GlobalExceptionHandler {

    // 我們自己丟的業務例外
    @ExceptionHandler(BusinessException.class)
    public ResponseEntity<ApiError> handleBusiness(BusinessException e, HttpServletRequest req) {
        return ResponseEntity.status(e.getStatus())
            .body(new ApiError(now(), e.getStatus().value(), e.getCode(),
                               e.getMessage(), req.getRequestURI(), List.of(),
                               e.getExtra()));            // with() 掛上去的資料一起帶出去
    }

    // 欄位驗證沒過（@Valid 失敗）
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ApiError> handleValidation(MethodArgumentNotValidException e,
                                                     HttpServletRequest req) {
        var details = e.getBindingResult().getFieldErrors().stream()
            .map(f -> new ApiError.FieldError(f.getField(), f.getDefaultMessage(), f.getRejectedValue()))
            .toList();
        return ResponseEntity.badRequest()
            .body(new ApiError(now(), 400, "VALIDATION_FAILED",
                               "請檢查輸入的資料", req.getRequestURI(), details));
    }

    // 其他所有沒被接住的例外
    @ExceptionHandler(Exception.class)
    public ResponseEntity<ApiError> handleUnexpected(Exception e, HttpServletRequest req) {
        log.error("未預期的錯誤", e);                      // ← 完整堆疊寫進日誌
        return ResponseEntity.internalServerError()
            .body(new ApiError(now(), 500, "INTERNAL_ERROR",
                               "系統發生錯誤，請稍後再試", req.getRequestURI(), List.of()));
    }
}
```

**最後那個是關鍵**：完整的錯誤堆疊寫進**日誌**（給你們 debug 用），前端只收到一句友善的中文。

## 在 Service 裡怎麼用

```java
if (session.getStatus() != SessionStatus.OPEN) {
    throw new BusinessException("SESSION_CLOSED", "這桌已經結帳，不能再加點", HttpStatus.CONFLICT)
        .with("reason", session.getStatus().name());   // PAID 或 CANCELLED：前端靠它決定顯示「已結帳」還是直接回首頁
}

if (affectedRows == 0) {
    throw new BusinessException("ITEM_SOLD_OUT",
        item.getName() + " 已售完", HttpStatus.CONFLICT);
}

// 要多帶資料的錯誤：用 with() 掛上去（結清時金額對不上，附最新帳單）
if (amount.total().compareTo(req.expectedTotal()) != 0) {
    throw new BusinessException("BILL_CHANGED", "金額有變動，請重新確認", HttpStatus.CONFLICT)
        .with("bill", toBillDto(session, amount));
}
```

`SESSION_CLOSED` 也一樣，回應多一個 `"reason": "PAID"`（或 `"CANCELLED"`），跟 WebSocket 的 `SESSION_CLOSED` 同一個值。
`BILL_CHANGED` 的回應會在統一格式上多一個 `bill`，前端直接 `setBill(err.bill)` 重畫（見 [04-API 規格](../../spec/04-API規格.md) §1.2）：

```json
{ "status": 409, "code": "BILL_CHANGED", "message": "金額有變動，請重新確認", "details": [],
  "bill": { "subtotal": 1560.00, "serviceFee": 156.00, "total": 1716.00 } }
```

**Service 只管丟例外，不管怎麼變成 HTTP 回應。** 那是 GlobalExceptionHandler 的事。

## 為什麼這是投報率最高的 0.5 天

| 沒有它 | 有它 |
|---|---|
| 前端每支 API 都要猜錯誤格式 | 所有錯誤長一樣，前端寫一次處理邏輯 |
| 使用者看到英文堆疊 | 看到中文說明 |
| 洩漏內部結構 | 不洩漏 |
| debug 時翻遍程式碼找錯誤 | 日誌統一，一眼看到 |

**A 花半天寫這個，可以省下全隊十幾個小時。** 第 1 週就要做好。

## 15 分鐘動手小練習

1. 在 Hello 專案加上 `GlobalExceptionHandler`（照上面貼）
2. 在 Controller 裡故意丟一個例外：

```java
@GetMapping("/boom")
public String boom() {
    throw new BusinessException("TEST_ERROR", "這是測試錯誤", HttpStatus.BAD_REQUEST);
}
```

3. 打開 `/boom`，看到你自己定義的格式
4. 再試 `throw new RuntimeException("沒接住的")`，看它變成 500 但訊息是友善的
5. 去看 IntelliJ 的 console，完整堆疊在那裡

## 你會遇到的坑

**① 在 Controller 裡到處 try-catch**
這就是全域處理要取代的東西。**Controller 裡不要有 try-catch。**

**② 把例外吞掉**
```java
catch (Exception e) { }   // ❌ 什麼都不做
```
錯誤消失了，但問題還在，而且你永遠找不到。

**③ 錯誤訊息寫給工程師看**
「NullPointerException at line 87」——使用者看不懂。訊息要寫給使用者看，技術細節寫進日誌。

**④ 忘記記錄日誌**
只回友善訊息但沒記日誌，出事時你什麼線索都沒有。

## 常見錯誤訊息對照

| 你會看到 | 中文意思 | 怎麼修 |
|---|---|---|
| 前端收到一大串 `trace` | 全域處理沒生效 | 檢查 `@RestControllerAdvice` 有沒有被掃描到 |
| `Ambiguous @ExceptionHandler` | 兩個方法都說要處理同一種例外 | 只留一個 |
| 自訂例外還是變成 500 | `@ExceptionHandler` 沒對到型別 | 檢查括號裡的類別寫對沒 |

## 術語對照表

| 白話 | 正式名稱 |
|---|---|
| 統一接住所有錯誤 | `@RestControllerAdvice` |
| 我負責處理這種錯誤 | `@ExceptionHandler` |
| 我們自己定義的錯誤 | 自訂例外 / BusinessException |
| 錯誤發生的完整路徑 | stack trace 堆疊追蹤 |
| 欄位驗證 | Bean Validation |
