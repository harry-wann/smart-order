# 模組 8：會員

**難易度** ★★★☆☆　**里程碑** 第 4 週

## 這個模組在做什麼

讓客人可以註冊、登入、看自己的消費紀錄。**但不強迫**——匿名也能點餐、也能訂位。

會員的價值在於：個人化推薦需要它、集點需要它、而且「匿名轉會員」是一個很打動人的小功能。

## 難易度為什麼是三顆星

註冊登入本身是標準流程。難的是：

1. **[JWT](../../tech/backend/21-JWT.md) 的觀念**——無狀態、內容是公開的、沒辦法主動作廢
2. **[Spring Security](../../tech/backend/20-SpringSecurity.md) 的設定**——兩套認證機制並存（用餐權杖 + JWT）
3. **匿名轉會員**——要把已經存在的 `dining_session` 綁到會員身上

## 問題思考與解決思路

### 問題 1：沒有簡訊服務怎麼做手機驗證

**情境**
規格要求手機號碼 + 簡訊驗證碼。但我們沒有簡訊服務。

**做法 A：跳過驗證，直接用手機號碼註冊**
最省事，但流程不完整，面試時講不出東西。

**做法 B：完整流程，只 mock 掉簡訊閘道** ← 我們選這個

> `verification_code` 表照常建、驗證碼照常有 5 分鐘效期、照常驗錯 3 次鎖定、照常限流——**只是不寄簡訊**。
> 開發／demo 模式下，驗證碼直接回在 API 回應裡並顯示在畫面上（標註「測試模式」）。

```java
public OtpResponse request(String phone) {
    checkRateLimit(phone);                              // 限流

    String code = String.format("%06d", random.nextInt(1_000_000));
    redis.opsForValue().set("otp:" + phone, code, Duration.ofMinutes(5));   // 自動過期

    smsGateway.send(phone, "您的驗證碼是 " + code);     // ← 唯一被 mock 的東西

    return devMode
        ? OtpResponse.withCode(code)                    // 測試模式回傳驗證碼
        : OtpResponse.sent();
}
```

**面試時可以說**：「簡訊閘道是整個系統唯一 mock 掉的外部依賴，換成真的 Twilio 只要改一個 `SmsGateway` 的實作。」——**這比「我沒做驗證」好講太多。**

### 問題 2：驗證碼存哪裡

**做法 A：MySQL 的 `verification_code` 表**

需要：建表、寫查詢、**還要寫一個排程去清過期的**。

**做法 B：[Redis](../../tech/realtime/44-Redis.md)** ← 建議

```java
redis.opsForValue().set("otp:" + phone, code, Duration.ofMinutes(5));
```

**一行，而且 5 分鐘後自己消失。** 不用建表、不用寫清理排程。

驗證碼天生就是「短期、會過期、掉了也還好」的資料，這正是 Redis 的典型用途。

**這是 Redis 在我們專案裡最自然的切入點**——不是為了炫技，是真的比較好。

（如果第 5 週還沒導入 Redis，先用 MySQL 也可以，但要記得寫清理排程。）

### 問題 3：匿名客人點完才想集點

**情境**
一桌客人匿名點餐，結帳時想累積點數。

**直覺會這樣寫**
「不好意思，要先註冊會員才能集點」——然後客人就放棄了。

**正確做法：結帳頁輸入手機號碼就綁定**

```java
@Transactional
public void attachMember(String sessionToken, String phone) {
    DiningSession session = sessionService.validate(sessionToken);

    if (session.getMemberId() != null) {
        throw new BusinessException("ALREADY_ATTACHED", "已綁定會員", CONFLICT);
    }

    Member member = memberRepo.findByPhone(phone)
        .orElseGet(() -> memberRepo.save(Member.createMinimal(phone)));   // 沒有就建一個最小的

    session.setMember(member);
    // 點數在付款成功後才給
}
```

**體驗上的差別很大**：客人不用離開結帳流程、不用填暱稱生日，輸入手機就好。之後他真的想看紀錄時再補資料。

**成本大約半天，但這是 demo 時很打動人的一個小功能。**

### 問題 4：客人按了登出，token 立刻失效嗎

**情境**
客人在公用平板上登入，用完按登出。

**很多人以為**
前端刪掉 `localStorage` 的 token 就等於登出了。

**實際上**
那張 JWT **在過期前仍然有效**。如果有人在登出前複製了那串 token，他還是能用。

**為什麼？** 因為 JWT 是無狀態的——伺服器不記得發過哪些 token，它只驗簽章和過期時間。

**三種處理方式**：

| 做法 | 說明 | 我們做嗎 |
|---|---|---|
| **A：縮短效期** | 設短一點（員工 12 小時） | ✅ |
| **B：黑名單** | 登出時把 token 存進 Redis 黑名單，效期到期為止 | ⚠️ 進階 |
| **C：Refresh Token 輪替** | 完整但複雜 | ❌ 不做 |

**我們的決定**：做 A，並在文件說明 B 是進階項。

**但一定要知道這件事**，因為面試很可能問「JWT 怎麼登出」。答「刪掉 localStorage」會被追問。

---

### 問題 5：前端把按鈕藏起來就安全了嗎

**情境**
廚房人員的畫面上沒有「修改菜單」的按鈕。

**不安全。**

他只要打開 Postman，直接打 `POST /api/admin/menu/items`，如果後端沒擋，他就改得了。

**正確做法：每一支 admin API 都要有角色檢查**

```java
@PreAuthorize("hasAnyRole('COUNTER', 'MANAGER')")
@PostMapping("/api/admin/tables/{id}/open")
public void openTable(@PathVariable Long id) { ... }

@PreAuthorize("hasRole('MANAGER')")
@PostMapping("/api/admin/menu/items")
public MenuItemDto create(@RequestBody CreateMenuItemRequest req) { ... }
```

**驗收方式**：用 Postman 拿廚房帳號的 token 去打菜單管理 API，**必須回 403**。

這是 [02-需求規格](../02-需求規格.md) 的非功能需求之一，要實際測過。

## 常見卡關

| 卡點 | 解法 |
|---|---|
| **加了 Security 之後全部 401/403** | 預設全擋，要明確 `permitAll()` 開放路徑 |
| **Swagger 打不開** | 放行 `/swagger-ui/**` 和 `/v3/api-docs/**` |
| **CORS 突然失效** | SecurityConfig 加 `.cors(Customizer.withDefaults())` |
| **POST 全部 403** | CSRF 擋的，前後端分離要 `.csrf().disable()` |
| **帶了 token 還是 401** | filter 沒把身分放進 `SecurityContext` |
| **`The signing key's size is not secure enough`** | JWT 密鑰太短，要 32 字元以上 |
| **密鑰被 commit 上 GitHub** | 放 `application-local.yml` 並加進 `.gitignore` |

## 驗收 Demo 腳本

1. 匿名點餐 → 結帳頁輸入手機號碼 → **顯示「將為您累積點數」**
2. 註冊流程：輸入手機 → **畫面顯示測試模式的驗證碼** → 輸入 → 補暱稱性別生日 → 登入成功
3. 會員中心看得到剛剛那次消費紀錄
4. 故意輸錯驗證碼 3 次 → 顯示「驗證碼已失效，請重新取得」
5. 連續要 4 次驗證碼 → 第 4 次顯示「請 10 分鐘後再試」
6. 店家端用 `kitchen` 帳號登入 → 側邊欄看不到「菜單管理」
7. **用 Postman 拿 kitchen 的 token 打菜單管理 API → 回 403**（這一步一定要演，展示你們懂權限）
