# 模組 6：結帳

**難易度** ★★☆☆☆　**里程碑** 第 3 週

## 這個模組在做什麼

算清楚這桌總共多少錢，收款，然後把桌子放回可用狀態。

**這裡要記得我們的定位：半輔助工具。** 系統管的是「點什麼、出到哪、坐多久」，**不管錢怎麼進抽屜**。所以我們**不做**找零、交班、日結、稽核、發票、折讓——那些留給店家原本的收銀機。

## 難易度為什麼只有兩顆星

沒有併發問題、沒有複雜演算法、沒有即時推播的難點。主要是：

- 金額計算要正確（用 `BigDecimal`）
- 狀態轉移要鎖好（結帳中不能加點）
- 付款是模擬的，不串接任何真實金流

**唯一要小心的是「不要把範圍做大」。** 結帳很容易越做越像 POS 系統。

## 問題思考與解決思路

### 問題 1：結帳到一半有人加點

**情境**
你在結帳頁看金額，朋友在另一支手機上又加了一盤肉。

**如果不處理**
你看到的是 1420，實際帳單變成 1700。**付了錢金額卻不對。**

**正確做法：結帳時鎖定**

```java
@Transactional
public CheckoutDto requestCheckout(String token) {
    DiningSession session = sessionService.validate(token);

    if (session.getStatus() != SessionStatus.OPEN) {
        throw new BusinessException("ALREADY_CHECKING_OUT", "已在結帳中", CONFLICT);
    }

    session.setStatus(SessionStatus.CHECKOUT_PENDING);   // ← 鎖定
    session.recalculate();

    messaging.convertAndSend("/topic/session/" + session.getId(),
        new WsEvent("SESSION_LOCKED", null));            // 通知同桌其他裝置

    return toCheckoutDto(session);
}
```

然後在送出點餐時擋：

```java
if (session.getStatus() != SessionStatus.OPEN) {
    throw new BusinessException("SESSION_LOCKED", "結帳中無法加點", CONFLICT);
}
```

**同桌其他手機會即時看到「結帳中」的提示**，不用等到送出才發現。

**要能解鎖**：客人可能看完金額想再點一份甜點。提供「取消結帳」回到 `OPEN`。

### 問題 2：金額算出來差一塊錢

**情境**
小計 1420，服務費 10%，合計應該是 1562。但系統顯示 1561.9999999。

**原因**
用了 `double` 或 `float`。電腦的浮點數沒辦法精確表示 0.1。

```java
System.out.println(0.1 + 0.2);   // 0.30000000000000004
```

**正確做法：從頭到尾用 BigDecimal**

```java
public CheckoutAmount calculate(DiningSession session) {
    BigDecimal subtotal = session.getTickets().stream()
        .filter(t -> t.getStatus() != TicketStatus.CANCELLED)
        .flatMap(t -> t.getItems().stream())
        .filter(i -> i.getStatus() != ItemStatus.CANCELLED)
        .map(OrderItem::getLineTotal)
        .reduce(BigDecimal.ZERO, BigDecimal::add);

    BigDecimal fee = subtotal.multiply(SERVICE_FEE_RATE)
                             .setScale(2, RoundingMode.HALF_UP);

    return new CheckoutAmount(subtotal, fee, subtotal.add(fee));
}
```

三個重點：

1. **資料庫欄位用 `DECIMAL(10,2)`**，不要 `FLOAT`
2. **建立 BigDecimal 用字串**：`new BigDecimal("0.10")` 不是 `new BigDecimal(0.10)`
3. **每一步都 `setScale(2, HALF_UP)`**，明確指定進位規則

**比較兩個 BigDecimal 要用 `compareTo`**，`equals` 會認為 `142.0` 和 `142.00` 不相等。

### 問題 3：模擬付款的界線在哪

**情境**
規格寫「模擬 Apple Pay / Google Pay / LINE Pay」。

**如果不寫清楚會發生什麼**
一定會有組員跑去研究真的串接文件。LINE Pay 要商家申請、Apple Pay 要開發者帳號 + 正式網域——**浪費三到五天，而且做不出來。**

**明確定義（請貼進群組）**

> 付款 = 一個假的付款畫面 → 客人選一種方式（三顆按鈕，只是圖示不同）→ 前端顯示 2 秒處理動畫 → 後端建立一筆 `payment` 紀錄，隨機 95% 成功／5% 失敗 → 回傳交易編號。
> **不串接任何真實金流 API。不申請任何開發者帳號。**

```java
public PaymentDto pay(Long sessionId, PayMethod method) {
    DiningSession session = ...;
    boolean success = random.nextInt(100) < 95;      // 95% 成功

    Payment payment = Payment.of(session, method, session.getTotal(),
        success ? PayStatus.SUCCESS : PayStatus.FAILED,
        "MOCK-" + LocalDate.now().format(BASIC_ISO_DATE) + "-" + nextSeq());

    if (!success) {
        paymentRepo.save(payment);
        throw new BusinessException("PAYMENT_FAILED", "銀行端驗證失敗，請重試或更換付款方式", UNPROCESSABLE_ENTITY);
    }
    // 成功：改三個狀態
    session.markPaid();
    session.getTable().setStatus(TableStatus.CLEANING);
    return toDto(paymentRepo.save(payment));
}
```

**為什麼要留 5% 失敗？** 因為 demo 時可以展示錯誤處理。一個「永遠成功」的付款流程看不出你有沒有想過失敗的情況。

**付款頁要明確標示「本系統為教學專題，付款為模擬流程，不會產生實際交易」。** 誠實，而且評審會欣賞。

### 問題 4：人數不進帳單計算，那收集人數幹嘛？

**情境**
我們的計價是「一鍋一價 + 單點」、無低消。所以：

```
小計 = Σ(品項 × 數量)
服務費 = 小計 × 10%
合計 = 小計 + 服務費
```

**人數完全不參與金額計算。**

**那為什麼還要輸入大人／小孩人數？** 四個用途：

| 用途 | 說明 |
|---|---|
| **座位安排** | 櫃檯配桌、訂位的 best-fit |
| **分帳均分** | 顯示「每人約 $521」（即使不做分帳功能，顯示參考值也有用） |
| **兒童友善推薦** | 有小孩時把辣度 0 的品項排前面 |
| **客單價統計** | 營收 ÷ 人數 |

**這點一定要寫進文件**，不然組員會問「為什麼要收集人數卻不用」，或者更糟——**自己加一個人頭費的計算進去**。

## 常見卡關

| 卡點 | 解法 |
|---|---|
| **金額差一塊錢** | 檢查有沒有用 `double`；檢查 `setScale` 的進位規則 |
| **BigDecimal 比較不相等** | 用 `compareTo` 或 `isEqualByComparingTo`，不要用 `equals` |
| **取消的品項也被算進去** | 計算時要 `filter` 掉 `CANCELLED` |
| **付款成功但桌位沒轉狀態** | 三個狀態要在同一個 `@Transactional` 裡改 |
| **客人連按付款兩次** | 前端 `disabled={submitting}` + 全頁遮罩 |

## 驗收 Demo 腳本

1. 點三樣東西（含一個有選項價差的）→ 按「我要結帳」
2. 帳單頁顯示：品項明細、小計、服務費 10%、合計、每人約多少
3. **同桌另一支手機想加點** → 顯示「結帳中無法加點」
4. 按「取消結帳」→ 另一支手機可以加點了
5. 再次結帳 → 選 LINE Pay → 2 秒動畫 → 成功畫面 + 交易編號
6.（重複幾次可以演到失敗）失敗時顯示原因並可重試
7. 付款成功後：桌況變「待清理」，**手機重新整理顯示「本次用餐已結束」**
