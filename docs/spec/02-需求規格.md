# 02 需求規格：基礎與進階功能總表

> 分層原則見 [00-架構分層與技術選型](00-架構分層與技術選型.md)。
> 每個模組的詳細規格、問題思考與六週切分，見 [modules/](modules/) 底下各頁。

## 1. 分層判準

- **基礎（核心細項）** = 拿掉它，這套系統就沒辦法讓一家店做生意 → **一定要做**
- **進階（延伸細項）** = 拿掉它，系統還能運作，只是比較笨 → **基礎全綠燈後才動工**

**八大模組全部在基礎層。** 分層是在模組「裡面」切，不是砍掉整個模組。

## 2. 推進方式：廣度優先

先把八個模組的核心細項各做最薄一層、串成一條營運閉環，再回頭一層層加厚。
**不是**做完模組 A 才做模組 B。

## 6. 狀態機

> 圖見 [06-圖表總覽](06-圖表總覽.md)。以下為文字版規則，實作以此為準。

### 6.1 用餐紀錄 `DiningSession.status`

| 狀態 | 意義 | 可轉移到 |
|---|---|---|
| `OPEN` | 用餐中，可繼續點餐 | `CHECKOUT_PENDING`、`CANCELLED` |
| `CHECKOUT_PENDING` | 已要求結帳，**鎖定不可點餐** | `PAID`、`OPEN` |
| `PAID` | 已付款 | （終態） |
| `CANCELLED` | 未消費即離開 | （終態） |

**只有 `OPEN` 可以建立新的 `OrderTicket`。** 進入終態時該桌所有用餐權杖立刻失效。

### 6.2 點餐單 `OrderTicket.status`

`PENDING` → `PREPARING` → `SERVED`，任何階段可 → `CANCELLED`（庫存回補）。

**狀態由旗下 `OrderItem` 自動推導，不手動設定。**

### 6.3 桌位 `DiningTable.status`

| 狀態 | 可轉移到 |
|---|---|
| `AVAILABLE` | `OCCUPIED`、`RESERVED` |
| `RESERVED`（訂位前 30 分鐘，由排程轉入） | `OCCUPIED`、`AVAILABLE` |
| `OCCUPIED` | `CLEANING` |
| `CLEANING` | `AVAILABLE` |

### 6.4 預約 `Reservation.status`

`PENDING` → `CONFIRMED` → `SEATED`，或 → `CANCELLED` / `NO_SHOW`（後兩者由排程或人工觸發）。

### 6.5 候位 `Waitlist.status`

`WAITING` → `CALLED` → `SEATED`，或 → `ABANDONED` / `EXPIRED`（叫號後 10 分鐘未到，排程自動）。

### 6.6 付款 `Payment.status`

`PENDING` → `SUCCESS` → `REFUNDED`；`PENDING` → `FAILED`（可建立新的 `PENDING` 重試）。

## 7. 非功能需求

| 項目 | 要求 | 驗證方式 |
|---|---|---|
| **效能** | 菜單頁首次載入 < 3 秒；一般 API < 500ms | Chrome DevTools Network |
| **即時性** | WebSocket 推播到畫面更新 < 1 秒 | 兩支手機並排測試 |
| **不超賣** | 最後一份被兩人同時點，只有一人成功 | **多執行緒測試 + Testcontainers** |
| **不重複訂位** | 兩人同時訂同一桌同時段，只有一人成功 | 同上 |
| **瀏覽器** | Chrome / Safari 最新版；**iOS Safari 必測** | 真機測試 |
| **RWD** | 顧客端 375px 起；店家端 1024px 起 | 實機 + DevTools |
| **可用性** | 內文 ≥16px、可點擊區 ≥48×48px、對比度 ≥4.5:1 | 見 [11-設計系統](../ui/11-設計系統.md) |
| **安全** | 密碼 BCrypt；JWT 簽章；SQL 一律參數化 | Code review |
| **權限** | 每支 `/api/admin/**` 都有角色檢查 | **用 Postman 拿低權限 token 測，必須 403** |
| **錯誤處理** | 所有錯誤回統一格式，前端有對應提示 | 斷網／關 DB 測試 |
| **資料** | 種子資料含過去 90 天約 5000 筆單品 | 第 1 週完成 |
| **可觀測** | 所有排程任務有日誌；例外有完整堆疊 | 看 console |
