單元 10D · VERIFY

實作四：手動驗收五種 API

先啟動服務，再按照順序執行。POST 產生的商品 id 會拿來測試 PUT、PATCH、DELETE。

curl預期狀態碼只刪自己的測試資料

安全提醒：不要拿原始 Northwind 商品做 PUT、PATCH 或 DELETE。請先 POST 一筆 Training Tea，最後只刪除那一筆。

本頁閱讀路線

01 · 啟動

先完成 後端環境建置：MySQL healthy、兩張表可查詢、backend/.env 已填好。以下 cd backend 假設你站在 repository 根目錄；若 VS Code 終端機已在 backend/，不要再執行一次。啟動後保持終端機開啟，另開終端機執行 curl。

以下 curl 範例使用 macOS／Linux 或 Windows 的 Git Bash 語法。Windows 若使用 PowerShell，可以改在 Swagger UI 依相同順序試呼叫，避免 PowerShell 把 curl 解析成別的命令。curl 的 -i 顯示狀態碼與標頭，-H 設定標頭，-d 提供 JSON 本文。

02 · GET：查詢清單與單筆

預期是 200 OK。清單回應包含 items、page、size、totalElements；單筆回應包含 id、productName、unitPrice、unitsInStock、discontinued、categoryId。

若清單是 items: []，回到 phpMyAdmin 查 Products 是否有資料。若連不上 8080，先看啟動終端機有沒有 Started SmartOrderApplication；若回 401／403，對照目前的 SecurityConfig 是否仍是教材設定。

03 · POST：新增自己的測試商品

預期是 201 Created，標頭有 Location: /api/products/...，本文有新商品的 id。請記下這個 id；每個人的數字可能不同。若回 400 且提到分類，先用 phpMyAdmin 確認 Categories 有分類 1。

下面所有含 $PRODUCT_ID 的命令都在同一個 curl 終端機執行；若換終端機，要重新設定變數。先用 GET /api/products/$PRODUCT_ID 確認那筆商品是你剛新增的 Training Tea，再進行修改。

04 · PUT：完整替換

預期是 200 OK。PUT 是完整替換；漏掉必要欄位會得到 400。不存在的 id 得到 404，而且不會偷偷新增。

回應中的 productName 應變成 Training Green Tea，unitPrice 應是 25，unitsInStock 應是 12。這三項一起核對，才能確認完整替換真的完成。

05 · PATCH：只改一個欄位

預期是 200 OK，名稱仍是 Training Green Tea，庫存仍是 12。PATCH 不接受本例沒有開放的欄位；傳入未知欄位會得到 400。

這次只有 unitPrice 應變成 26。若送空物件 {}，現有 Service 會回 400；本例把 null 視為「不修改」，沒有示範將欄位清空。
