01 · 資源與方法一起讀

上一頁只有「查固定商品」一條路徑。現在想新增商品、改價格、刪商品，先約定呼叫方式，再動手寫方法；這份約定就是 API 合約。

資源（Resource）是我們要操作的對象，例如商品；/api/products/1 指向編號 1 的商品。端點（Endpoint）在這裡指「HTTP 方法＋路徑」這個可呼叫的入口，例如 GET /api/products/1。

請求（Request）是呼叫端送來的要求；回應（Response）是伺服器的答覆。標頭（Header）放格式等資訊，本文（Body）放商品等資料，狀態碼（Status code）用數字告訴你結果。200 是成功、201 是建立完成、204 是成功但沒有本文。Location 是回應標頭，指出新增商品的位置。

REST 是 Representational State Transfer（表述性狀態轉移），是一種架構風格；RESTful 表示採用這種風格。API 是 Application Programming Interface（應用程式介面）。HTTP 是 Hypertext Transfer Protocol（超文字傳輸協定）。

本課採用業界常見、以資源與 HTTP 語意設計的 JSON API；JSON 是 JavaScript Object Notation（JavaScript 物件表示法）。只有 CRUD 並不代表滿足 REST 的全部架構限制。CRUD 是 Create、Read、Update、Delete（新增、讀取、更新、刪除）。

方法與路徑用途成功回應
GET /api/products?page=0&size=10查清單200 + 分頁資料
GET /api/products/1查單筆200 + 商品
POST /api/products新增商品201 + 商品 + Location 標頭
PUT /api/products/1替換 API 公開的全部可寫欄位200 + 更新結果
PATCH /api/products/1部分更新；只傳要改的欄位200 + 更新結果
DELETE /api/products/1刪除未被訂單引用的商品204，沒有內容

02 · PUT 與 PATCH 不要只換註解

目前的 ProductPatchRequest 允許 productName、unitPrice、unitsInStock、discontinued、categoryId 中任一個或數個欄位；上例只修改價格。至少要提供一個非 null 欄位；未知欄位會回 400。這是本專案自訂的 application/json 部分更新，不是 JSON Patch 操作陣列，也不是通用 JSON Merge Patch。

PUT 的「完整」以此 API 公開的可寫資源表示為準，不表示重寫資料庫裡所有欄位。本課不公開 SupplierID 等欄位，更新時會保留它們。

03 · 冪等：同一請求重送會怎樣？

Idempotent（冪等）是指重送同一請求，預期最終狀態相同。GET 不改資料；PUT 把資料設成指定值；DELETE 刪除指定資源，因此這些方法有冪等語意。第二次 DELETE 可以回 404，仍不違反冪等。

POST 重送可能新增兩筆；不要因網路逾時就無限制重試下單。PATCH 是否冪等取決於操作：設單價為 26 是冪等，每次加 1 則不是。

04 · 成功以外，也要約定錯誤

狀態碼情境
400 Bad Request名稱空白、負價格、無效 JSON 或頁數
401 Unauthorized缺少有效身分憑證
403 Forbidden已識別身分，但權限不足；也可能是 CSRF 檢查失敗
404 Not Found商品不存在
409 Conflict商品被訂單明細引用，無法刪除
500 Internal Server Error非預期的伺服器錯誤

Location 是新增後資源位置的回應標頭。Content-Type 說明傳送的資料格式。CSRF 是 Cross-Site Request Forgery（跨站請求偽造），安全單元會解釋。

05 · HEAD 與 OPTIONS 也給例子

這裡先閱讀命令，不需現在執行；對應的伺服器程式已在 backend/。curl 是傳送網路請求的命令列工具：-I 發出 HEAD，-i 顯示回應標頭，-X 指定方法。

HEAD 類似 GET，但回應不帶本文。OPTIONS 可用 Allow 標頭表示允許的方法；Spring MVC 可以自動處理。CORS 是 Cross-Origin Resource Sharing（跨來源資源共用）；瀏覽器的跨來源預檢還需要對應 CORS 設定，不是有 OPTIONS 就算完成。

TRACE 與 CONNECT 分別用於診斷與通道建立，不是商品 CRUD 的實作項目。單元 10 的完整程式涵蓋上述六個業務端點。HEAD／OPTIONS 由 Web 框架處理，這裡只用來認識 HTTP 方法；10D 的手動驗收集中在 GET、POST、PUT、PATCH、DELETE。
