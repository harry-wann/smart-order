單元 03 · NORTHWIND LAB

從 new 開始：一個物件為什麼需要另一個？

先用普通 Java 印出 Northwind 商品標籤。這一頁只觀察物件如何合作，以及把依賴傳進去的意思。

Spring Boot 4 主線有差異再看 Boot 35 個閱讀步驟

先備觀念：會讀 class、new、方法呼叫與建構子就足夠。這頁不需要資料庫或 Spring 設定。

讀完能做到：指出誰建立商品資料來源、誰使用它，並看懂建構子中的參數與欄位。

01 · 固定任務：印出「商品：Chai」

假設 Northwind 的商品 1 名稱是 Chai。我們需要兩個分工：NorthwindCatalog 負責找商品名稱，ProductLabel 負責組成顯示文字。Catalog 是目錄，Label 是標籤；這兩個類別名稱是我們自己取的，不是框架內建功能。

為了只觀察物件關係，這裡直接回傳已知的商品名稱，還沒有連資料庫。只示範編號 1；其他編號丟出 Java 的 IllegalArgumentException（不合法參數例外）。後面實作單元才會查真正的 Northwind。

NorthwindCatalog 是類別，像規格；new NorthwindCatalog() 依規格建立一個物件。變數 catalog 保存這個物件的參考，之後可以透過它呼叫方法。

02 · 原本：標籤物件自己建立資料來源

  • 執行 new ProductLabel()，建立標籤物件。
  • ProductLabel 的欄位初始化又執行 new NorthwindCatalog()，建立資料來源。
  • label.text() 使用資料來源查商品名稱，再加上「商品：」。

這就叫物件依賴：ProductLabel 要完成工作，必須使用 NorthwindCatalog。與 Maven 下載外部套件的「套件依賴」相關，但不是同一件事。

03 · 現在的限制，要用具體需求看

現在想做一個不依賴真實資料的測試，希望相同的標籤邏輯印出「商品：測試茶」。但 ProductLabel 已在自己內部固定選用 NorthwindCatalog。呼叫它的人只能 new ProductLabel()，沒有地方告訴它要換資料來源。

問題目前答案
誰組合「商品：」這段文字？ProductLabel
誰決定使用哪個資料來源？也是 ProductLabel
測試時只換來源，能在呼叫端完成嗎？目前不行，來源藏在 ProductLabel 的 new 裡面

小程式這樣寫可以正常運作。當同一段邏輯要搭配不同來源時，把選來源與用來源分開，才會比較好改。

04 · 第一個小改動：由建構子接收物件

先看改了什麼：欄位旁邊的 = new NorthwindCatalog() 不見了，改由 ProductLabel(...) 的參數取得物件。text() 完全沒有改，輸出也仍然是「商品：Chai」。

左邊 this.catalog 是目前這個 ProductLabel 物件的欄位；右邊 catalog 是呼叫端傳進來的參數。這行把同一個物件的參考保存下來，不是複製物件，也不是再建立一個來源。final 表示欄位設定後不能改指向別的來源。

05 · 做過一次，再給它名字：DI

DI = Dependency Injection，依賴注入。Dependency 是需要使用的另一個物件；Injection 是由外部把這個物件交進來。剛才透過建構子傳入 catalog，就是「建構子注入」。

目前參數仍限定 NorthwindCatalog，所以還不能傳入毫無關係的 TrainingCatalog。下一頁只處理這件事：用介面定義共同能力，再比較換來源後的輸出。

停一下，自己想想

版本 B 的建構子裡沒有 new NorthwindCatalog()，物件是從哪來的？

看解釋

呼叫端先 new NorthwindCatalog()，再用 new ProductLabel(catalog) 把同一個物件交進來。建構子只接收它。

停一下，自己想想

DI 是不是一定要加 Spring 註解？

看解釋

不是。版本 B 已經做了依賴注入，卻完全沒有 Spring。Spring 會在後面幫我們自動組裝。
