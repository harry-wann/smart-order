01 · 先看完成後的資料流

REST 是 Representational State Transfer（表述性狀態轉移），API 是 Application Programming Interface（應用程式介面）。瀏覽器或前端送出 HTTP（Hypertext Transfer Protocol，超文字傳輸協定）請求後，資料會依序經過下面幾層：

層白話責任本專案位置
Controller（控制器）接收 URL、JSON 與 HTTP 方法，決定回應狀態碼。controller/ProductController.java
Service（服務層）處理業務規則，例如分類是否存在、更新哪些欄位、交易何時完成。service/ProductService.java
Entity（實體）描述 Java 物件如何對應資料庫資料表。entity/Product.java
Repository（資料存取層）使用 Spring Data JPA（Java Persistence API，Java 持久化 API）讀寫資料庫。repository/ProductRepository.java

這就是 MVC（Model-View-Controller，模型－視圖－控制器）在 REST API 的簡化用法：這裡沒有 JSP 頁面，所以 View 通常改成 JSON 回應；Model 主要由 Entity 與資料存取組成。

02 · 目前專案與依賴

專案已經建立在 repository 根目錄的 backend。請用 VS Code 開啟這個資料夾，不要另外建立第二個 Spring Boot 專案。第一次操作先看 後端環境建置；這裡只重述單元 10 需要的步驟。

  • spring-boot-starter-webmvc：建立 Controller 與 REST API。
  • spring-boot-starter-data-jpa：用 Entity、Repository 操作資料庫。
  • spring-boot-starter-validation：檢查 POST、PUT、PATCH 的輸入。
  • MySQL Driver：讓 Java 能連到 MySQL。
  • Spring Security：本教學的 API 暫時允許本機測試，正式環境仍要加入登入與權限。

實際版本以 backend/pom.xml 為準：Spring Boot 4.1.1、Java 21。Maven Wrapper（Maven 專案版本包裝器）也已放在專案中，組員不必各自安裝不同 Maven。

Boot 3 對照

Boot 3 的核心 MVC、Service、JPA 寫法大多相同；常見差異是 Web 依賴通常寫成 spring-boot-starter-web，測試套件與部分測試 import 也不同。本專案以 Boot 4 為準，不要把 Boot 3 的 POM 直接貼進來。

03 · 準備 MySQL Northwind

本專案對齊團隊的 Docker 設定：MySQL 5.7 使用主機 3306，資料庫名稱是 northwind，phpMyAdmin 可從 http://localhost 開啟。先建立並編輯 backend/.env，再啟動 Docker；否則 Compose 讀不到帳密。

等 MySQL 顯示 healthy，接著用 phpMyAdmin 將老師提供的 MySQL 版 Northwind 匯入 northwind。Repository 沒附完整 Northwind；如果沒有匯入檔，可在全新空白資料庫匯入 最小練習資料 SQL。這份 SQL 只建兩張表與一筆商品，足夠完成本單元，不能當完整 Northwind；已匯入完整版本時不要再匯入。至少要確認 Products 與 Categories 存在，而且分類 1 存在。

SQL 是 Structured Query Language（結構化查詢語言）。這裡使用 MySQL 語法，因此是 LIMIT 5，不是 SQL Server 的 TOP (5)；資料表是 OrderDetails，不是 dbo.[Order Details]。

04 · 啟動專案

application.properties 與 Docker Compose 共用 backend/.env，並連到 127.0.0.1:3306/northwind。確認上一節兩句 SQL 查得到表，再在 backend/ 執行下面指令；Windows PowerShell 用 ./mvnw.cmd spring-boot:run。

看到 Started SmartOrderApplication 後，另開終端機瀏覽 http://localhost:8080/api/products，應看到包含 items 的 JSON。若遇到 Access denied 或找不到表，回到 環境建置的常見卡關 逐項檢查。接著依序閱讀 10A、10B、10C，最後到 10D 用自己新增的商品測試五種方法。
