單元 07B · QUERY LANGUAGE

HQL、JPQL 與 JPA 原生 SQL

先記一句：SQL 查資料表，JPQL／HQL 查 Entity。語法很像，但名稱與欄位的來源不同。

Product EntityProducts Table參數綁定

讀完能做到：用 Entity 屬性寫一筆 JPQL 查詢，再把相同條件改寫成 MySQL SQL。下方查詢是可選的練習，不是目前 ProductRepository 已有的方法。

01 · 三種語言差在哪

語言FROM 後面寫什麼欄位寫什麼
SQL表名，例如 Products資料庫欄位，例如 UnitPrice
JPQLEntity，例如 ProductJava 屬性，例如 unitPrice
HQLEntity，例如 ProductJava 屬性，例如 unitPrice

SQL 是 Structured Query Language（結構化查詢語言）；JPQL 是 Jakarta Persistence Query Language（Jakarta 持久化查詢語言）；HQL 是 Hibernate Query Language（Hibernate 查詢語言）。

02 · JPQL / HQL 查 Entity

注意 Product 是 Java Entity 名稱，unitPrice 與 discontinued 是 Java 屬性，不是 MySQL 的 Products、UnitPrice。

上面的 @Query 使用 JPQL，也能由底層 Hibernate 執行。HQL 是 Hibernate 的查詢語言，涵蓋常見的 JPQL 寫法，另有自己的擴充功能；這個商品條件查詢不需要為了使用 HQL 重寫一次。初學時先用 Repository 的 @Query，避免把表名 Products 和 Entity 名 Product 混淆。

03 · JPA 原生 SQL

Native SQL（原生 SQL）直接寫資料庫語法，適合使用 MySQL 特有功能或既有 SQL。要明確加上 nativeQuery = true。

這裡使用 MySQL 的 limit 10，欄位是 UnitPrice、Discontinued。如果換成 SQL Server，語法就不一樣；所以原生 SQL 會降低資料庫可攜性。

這筆原生 SQL 比上一節多了「最多 10 筆」的限制。要比較完全相同的結果，先把 limit 10 拿掉；兩種查詢都應保留 minPrice、停售條件及價格排序。:minPrice 是綁定參數，不要把使用者輸入直接拼進 SQL 字串。

04 · UPDATE 的注意事項

@Modifying 告訴 Spring 這不是 SELECT；寫入仍需要 Transaction（交易）。批次 UPDATE 可能繞過目前 Persistence Context 的物件狀態，執行後要注意清除或重新讀取。
