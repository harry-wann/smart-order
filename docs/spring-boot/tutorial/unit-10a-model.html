01 · 先看資料表

Northwind 的 Products 有很多欄位，但本次 API 先練習六個：主鍵、商品名稱、單價、庫存、是否停售、分類編號。不要一開始就把整張表所有欄位都搬進程式。

MySQL 欄位Java 欄位用途
ProductIDInteger id資料庫產生的商品編號。
ProductNameString productName商品名稱。
UnitPriceBigDecimal unitPrice金額不要用 double，避免小數誤差。
UnitsInStockInteger unitsInStock庫存數量。
DiscontinuedBoolean discontinued是否停售。
CategoryIDInteger categoryId關聯的分類編號。

JPA（Java Persistence API，Java 持久化 API）會依照 Entity 上的註解，把 Java 類別與資料表連起來；Hibernate 是背後真正執行映射與 SQL 的實作工具。

如果不熟主鍵和外鍵，先讀 SQL 入門；要看火鍋店品項的對照例子，讀 Entity 與 DTO。本單元只針對 Northwind 的實際欄位，兩份例子的表名不能直接互換。

02 · Entity 對應資料表

請開啟 backend/src/main/java/tw/ispan/smartorder/entity/Product.java。下面是最重要的部分：

@Entity 告訴 JPA 這是資料實體；@Table 指定表名；@Id 指定主鍵；@GeneratedValue 表示新增時由 MySQL 自動產生編號；@Column 將 Java 欄位對到實際欄位。完整欄位請直接看專案中的檔案。

CategoryID 在目前練習程式中先存成 Integer categoryId，Service 另用 CategoryRepository 檢查分類是否存在。這是先練習 ID 與外鍵的簡化寫法；未來要改成 @ManyToOne，再讀 JPA 關聯對應。上面的 Java 是節錄，缺少 import、無參數建構子和其餘欄位，請不要覆蓋現有檔案。

03 · DTO 保護 API 合約

DTO 是 Data Transfer Object（資料傳輸物件）。Entity 是資料庫模型，DTO 是 API 允許前端傳入或收到的格式，兩者不要混在一起。

Validation（驗證）註解會在 Controller 用 @Valid @RequestBody 接收 JSON 時執行。ProductUpdateRequest 用於 PUT，欄位全部必填；ProductPatchRequest 用於 PATCH，只提供想更新的欄位，至少要有一個非 null 欄位。這就是 PUT 與 PATCH 在本例的差別。ProductResponse.from(product) 則把 Entity 轉成回應 DTO，讓 JSON 欄位與內部資料模型分開。

04 · Repository 交給 Spring Data

extends 是「繼承」。繼承 JpaRepository 後，Spring Data 會提供 findById、findAll、save、delete 等常用方法。你不需要先自己寫一大段 JDBC（Java Database Connectivity，Java 資料庫連線 API）。

尖括號中的 Product 指操作哪種 Entity；Integer 是它的主鍵型別。ProductRepository 負責商品，CategoryRepository 負責確認分類。到這裡先不用自己寫 SQL，等 10B 再看誰呼叫這兩個介面。

因為 Entity 裡可能有主鍵、內部狀態或未來新增的欄位。用 DTO 可以明確限制「前端現在能寫哪些欄位」，避免 API 意外修改資料庫不該被修改的欄位。
