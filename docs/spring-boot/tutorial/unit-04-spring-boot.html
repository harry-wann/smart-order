Spring Boot：把物件管理接上 Tomcat

01 · 先分清楚兩個「管理」

角色你已知道的責任
Tomcat接收網路請求、管理 Servlet 的生命週期
Spring 容器組裝並管理應用內的物件，也就是前頁的 Bean
Spring Boot提供相容套件、常見預設與啟動整合，把上述工作接起來

Tomcat 容器與 Spring 容器不是同一個概念。這份應用會同時使用兩者：Tomcat 接請求，Spring 提供處理請求需要的物件。

02 · Boot 的 main 方法接手啟動

上一頁為了理解原理，手動建立 Spring 容器。Boot 專案一般讓 SpringApplication.run(...) 建立應用環境；若加入了 Web 套件，也會啟動內嵌 Tomcat。

@SpringBootApplication 是啟動類別上的標記，包含三件事：把類別當成設定、開啟自動設定，以及掃描元件。自動設定是依已安裝套件與設定值準備常用功能；掃描元件則是尋找前頁學過的 @Component 等標記。

套件（Package）用來組織 Java 類別。預設掃描從 com.example.northwind 開始，包含其子套件；所以把應用類別放在這個範圍裡。不要把啟動類別放到無套件的預設位置。

03 · 先從你熟悉的 Servlet 看一個請求

HTTP = Hypertext Transfer Protocol（超文字傳輸協定），瀏覽器與伺服器用它傳遞請求與回應。GET 是讀取資料的方法。假設瀏覽器用 GET 請求 /hello，傳統 Servlet 可以這樣回傳文字。

你已經把「何時呼叫 doGet」交給 Tomcat。Spring Web 的做法會在這條流程中加入一個統一分派請求的 Servlet。

04 · 再看 Spring 的處理類別

Controller（控制器）是接收與協調請求的類別。@RestController 讓它被 Spring 管理，並把方法回傳值寫入回應內容；@GetMapping("/hello") 指定這個方法處理 GET /hello。先知道兩個註解的目的，再讀程式。

  • 瀏覽器送 GET /hello 給 Tomcat。
  • Tomcat 把請求交給 DispatcherServlet（Spring 用來統一分派請求的 Servlet）。
  • DispatcherServlet 依路徑找到 HelloController.hello()。
  • 方法回傳 Northwind，框架把文字寫入 HTTP 回應。

你不必自己呼叫 hello()。也不必讓 HelloController 繼承 HttpServlet；Servlet 這層由 DispatcherServlet 處理。MVC = Model–View–Controller（模型、視圖、控制器），是這套 Web 框架的分工背景，下一頁再展開。

05 · JSP 畫面與資料回應有什麼不同？

JSP = JavaServer Pages，現稱 Jakarta Server Pages，通常由伺服器產生網頁。API = Application Programming Interface（應用程式介面），讓另一個程式按約定取得資料或執行操作。這份教材後面採資料 API，讓前端決定畫面怎麼顯示。

你熟悉的流程本課接下來的流程
Servlet 把資料放進 requestController 回傳 Java 資料物件
轉交 JSP 產生 HTML 網頁框架轉成 JSON 資料
瀏覽器顯示伺服器產出的畫面前端接收資料，再組成畫面

JSON = JavaScript Object Notation（JavaScript 物件表示法），常用鍵值對交換資料；例如 {"id":1,"productName":"Chai"}。下一頁先定義那個 Java 資料物件，再看自動轉換。

Spring 仍能回傳網頁，不是只能做資料 API。Boot 使用 JSP 時需另外確認 WAR 封裝等限制；本課的主線先不混入 JSP 部署設定。

06 · 已學技術與版本放回正確位置

Jakarta EE = Jakarta Enterprise Edition（Jakarta 企業版），是一組企業 Java 規格，不是單一伺服器。Persistence 是持久化規格，Validation 是資料驗證規格；分別到資料庫與驗證單元再學。Tomcat 實作部分 Web 規格，不是完整 Jakarta EE 平台。

選讀：Boot 3／4 的版本差異，第一次可先跳過

Jackson 是 Java 物件與 JSON 的轉換工具。本課使用框架的預設轉換，暫時不需要自行設定它。

停一下，自己想想

用了 Boot 以後，Tomcat 和 Servlet 是否都不見了？

看解釋

沒有。Tomcat 仍接收請求，DispatcherServlet 仍是 Servlet。你主要改寫 Controller 方法，而讓框架處理路徑分派與回應轉換。
