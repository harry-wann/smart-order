Maven：先認識專案怎麼取得套件與啟動

先把開發工具的位置弄清楚。這一頁只處理套件、目錄與建置，Spring 如何管理物件留到下一頁。

Spring Boot 4 主線有差異再看 Boot 34 個閱讀步驟

先備觀念：你曾把 Java Web 專案部署到 Tomcat，知道程式需要先編譯。

讀完能做到：看懂 pom.xml 的用途，分辨安裝套件、測試、打包與啟動。

01 · 為什麼需要 Maven？

如果專案需要外部套件，你可以手動下載檔案、挑版本，再讓編譯器找到它們。但團隊每台電腦都重做這件事容易出現差異。Maven 是建置工具，幫你按照同一份設定下載套件、編譯、測試與打包。

Dependency（依賴）在這裡指專案需要的外部套件。下一單元會談物件需要另一個物件的依賴；兩者不要混在一起。

02 · pom.xml 是這個專案的清單

POM = Project Object Model（專案物件模型）。pom.xml 記錄專案名稱、套件與建置設定。XML = Extensible Markup Language（可延伸標記語言），也就是這個檔案使用的標記格式。

設定意思
groupId套件所屬的組織
artifactId套件名稱
Starter預先組好的套件組合；此例提供處理網頁請求的能力與 Tomcat

WebMVC 是這個套件名稱的一部分，詳細分工到單元 05 再學。現在只要知道：加一項設定，就能取得開發 Web 功能需要的一組套件。

Boot 的 parent（父設定）會提供相容套件的版本清單，所以受管理的套件不必各自填版本。本課固定 Boot 4.1.1、Java 21；完整設定在單元 10。

Boot 3 對照

Boot 3 通常使用 spring-boot-starter-web；本課 Boot 4 使用 spring-boot-starter-webmvc。

03 · 編譯與打包，不是同一件事

編譯把 Java 原始碼轉成位元組碼（Bytecode）；JVM = Java Virtual Machine（Java 虛擬機器），負責執行它。打包則把編譯結果和需要的資源整理成可交付檔案。

名稱全名／用途
JARJava Archive，Java 封裝檔。本課用可執行 JAR 啟動應用
WARWeb Application Archive，Web 應用程式封裝檔。你可能用過把它放到 Tomcat 的部署方式

本課的 Boot 可執行 JAR 通常已內含 Tomcat，因此可以從 Java 程式啟動它。這是啟動方式的差別，不表示 Tomcat 不見了。

04 · 目錄與命令先認得，不急著執行

位置放什麼
src/main/java主要 Java 類別
src/main/resources設定與資源
src/test/java自動檢查程式是否正確的測試
targetMaven 產生的編譯與打包結果

Wrapper（包裝啟動器）讓專案取得指定版本的 Maven。檔名 mvnw 是 Maven Wrapper 的啟動檔，第一次使用通常需要網路；有它就不必另行全域安裝 Maven。

命令你會看到什麼
test執行測試，回報成功或失敗
package編譯、測試，並在 target 產生封裝檔
spring-boot:run啟動應用並持續顯示執行紀錄，直到你停止它
這三行不是要在目前的 HTML 教材資料夾執行。repository 的 backend/ 已有 pom.xml 與 mvnw。第一次啟動先照 後端環境建置 建立 .env、啟動 MySQL 並匯入資料；此頁先學命令用途。
