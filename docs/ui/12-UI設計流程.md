# 12 UI 設計流程

這頁說明如何從需求規格走到可實作的設計稿。畫面內容以 [UI / UX 規格](10-UI-UX規格.md) 為準，顏色、字級與元件以 [設計系統](11-設計系統.md) 和 [色彩 Token](14-色彩Token.md) 為準。

## 從哪裡開始

1. 先讀 [需求規格](../spec/02-需求規格.md) 的基礎與進階分界，確認本週要完成的功能。
2. 在 [UI / UX 規格](10-UI-UX規格.md) 找到對應畫面與前後流程，先畫出正常、空資料、錯誤三種狀態。
3. 從 [設計系統](11-設計系統.md) 取用現有色票、字體、間距與元件。若現有元件不夠，先定義新元件的用途與狀態，再放入畫面。
4. 在 Figma 依 [畫框註解](13-畫框註解.md) 標示畫面編號、觸發條件、資料來源與互動結果。前端實作時，畫框註解就是驗收依據。
5. 把設計稿與 HTML 畫面總覽一起檢查，再交給前端實作。

## 一張畫面要交付什麼

| 項目 | 要說清楚的事 |
|---|---|
| 畫面位置 | 從哪一頁進入、完成後到哪一頁；返回鍵回哪裡。 |
| 資料 | 每個欄位從哪個 API 或使用者輸入取得；資料為空時顯示什麼。 |
| 操作 | 按鈕何時可按、送出時如何避免重複操作、成功與失敗各顯示什麼。 |
| 狀態 | 載入中、空資料、驗證失敗、網路失敗、成功回饋。 |
| 尺寸 | 手機與桌面畫框尺寸、內容溢出時的捲動方式、點擊區大小。 |

例如菜單頁：先對照 [M1 菜單與品項](../spec/modules/M1-菜單與品項.md) 的商品欄位，再依 [畫框註解](13-畫框註解.md) 確認停售品項、分類切換與加入購物車的反應。只畫正常狀態，前端仍無法判斷停售或讀取失敗時該如何呈現。

## 設計稿檢查順序

1. **流程**：從掃碼、選餐、送單到查看訂單，能否一路走完？店家端能否從桌況進到相應處理頁？
2. **內容**：價格、桌號、狀態與按鈕文字是否符合規格；基礎與進階功能是否標清楚？
3. **一致性**：同一種按鈕、欄位、提示訊息是否共用相同元件與 token？
4. **可用性**：文字是否清楚可讀、觸控範圍是否足夠、錯誤訊息是否告訴使用者下一步？
5. **交接**：Figma 畫框註解與 [HTML 畫面總覽](mockups/index.html) 是否能讓實作者找到相同畫面？

設計內容變動時，先更新對應規格與畫框註解，再同步 Figma 與 HTML 畫面。這樣同一個畫面只需要維護一份決策。
