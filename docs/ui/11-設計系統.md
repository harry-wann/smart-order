# 11 設計系統

> 這份文件是「所有畫面長什麼樣」的唯一標準。
> **在動手畫任何一張設計稿、寫任何一行 CSS 之前，先讀完這份。**
> 先定規範再讓 AI 生成，是「不要有 AI 感」的關鍵——AI 是執行者，不是決定品味的人。

---

## 1. 設計概念

**關鍵字**：熱氣、紅湯、白瓷、木桌、鐵鍋、台式老店的親切

不是：科技感、未來感、極簡北歐、深色儀表板

**一句話**：像一本印得不錯的紙本菜單被搬到手機上，而不是像一個 SaaS 後台。

## 1.1 中高價位共鍋，為什麼還是走台式感

我們的餐廳定位是**中高價位、多人共鍋**，但視覺**維持台式親切感**，不走冷調精緻路線。

理由是客群：**共鍋店的主力是家庭與朋友聚餐**。詹記就是最好的例子——價位不低，但視覺非常台、非常鮮明。而且我們的設計原則裡有「長輩兒童友善」，暖色調的台式感本來就更貼合。

**中高價位和路邊店的差別在執行精準度，不在色票。** 所以色票、字體、圓角全部維持，只做三個微調：

| 微調 | 具體做法 |
|---|---|
| **留白放大一級** | 卡片內距 16 → 20px、區塊間距 24 → 32px |
| **照片統一打光與色溫** | 混用不同色溫的素材是最掉價的地方，全部挑暖色調、同一種打光風格 |
| **價格呈現保持乾淨** | 不用刪除線、不用「原價／特價」的促銷感排版 |

## 2. 色彩

### 2.1 色票

```css

  /* 主色 — 紅湯 */

  --brand-500: #DB5B42;  /* hover */
  --brand-100: #FBE8E3;  /* 淺底、選中背景 */
```

### 2.3 顏色使用規則

| 情況 | 用什麼 |
|---|---|
| 主要行動按鈕 | `brand-600` 底 + 白字 |
| 次要按鈕 | 白底 + `brand-600` 邊框與文字 |
| 文字按鈕 | `text-600`，hover 變 `brand-600` |
| 價格 | `brand-600`，粗體 |
| 推薦／預約優先徽章 | `accent-500` 底 + `text-900` |
| 已出餐 | `success` |
| 售完 | `danger` 文字 + 照片灰階 + 「售完」標籤 |
| 頁面底 | `bg`（`#FBF7F0`） |
| 卡片 | `surface` + `border` 1px |

> **紅色是主色，所以錯誤色要用更暗的紅（`#B3261E`）才分得出來。** 這是常見的陷阱。

### 2.4 唯一的深色例外

**出菜看板 KDS** 用深色背景（`#241C18`）+ 白字。理由：廚房光線強、距離遠，深底高對比最清楚。其他所有頁面一律亮色。

## 3. 字體

### 3.1 選用

| 用途 | 字體 | 字重 | 為什麼 |
|---|---|---|---|
| 標題、店名、價格 | **Noto Serif TC（思源宋體）** | 700 / 900 | 台灣餐廳招牌與紙本菜單大量使用明體。**這是脫離 AI 感最有效的一招**——AI 生成的介面幾乎清一色無襯線 |
| 內文、按鈕、表單 | **Noto Sans TC（思源黑體）** | 400 / 500 / 700 | 中文螢幕閱讀最穩的選擇 |
| 數字（金額、桌號、時間） | Noto Sans TC + `font-variant-numeric: tabular-nums` | 700 | 等寬數字，金額對齊才不會跳動 |

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Noto+Sans+TC:wght@400;500;700&family=Noto+Serif+TC:wght@700;900&display=swap" rel="stylesheet">
```

> **替代方案（想更親切、更兒童友善）**：標題改用圓體（`jf open 粉圓` 或 `Zen Maru Gothic`）。但中價位店家建議還是宋體，比較有「老店」的份量感。**兩者擇一，不要混用三種字體。**

### 3.2 字級階層

| 名稱 | 大小 / 行高 | 字體 | 用在哪 |
|---|---|---|---|
| `display` | 32 / 1.3 | Serif 900 | 結帳合計、付款完成金額 |
| `h1` | 28 / 1.4 | Serif 700 | 頁面主標題 |
| `h2` | 22 / 1.5 | Serif 700 | 區塊標題、分類名 |
| `h3` | 18 / 1.6 | Sans 700 | 品項名稱 |
| `body` | 16 / 1.75 | Sans 400 | **內文最小值，不得更小** |
| `body-sm` | 14 / 1.7 | Sans 400 | 已選選項、備註等次要資訊 |
| `caption` | 13 / 1.6 | Sans 400 | 時間戳、註腳。**僅用於非關鍵資訊** |
| `price` | 20 / 1.4 | Sans 700 tabular | 品項價格 |
| `button` | 18 / 1 | Sans 500 | 按鈕文字 |
| `kds-table` | 32 / 1.2 | Sans 900 | KDS 桌號 |

**中文行高一律 ≥ 1.6**（比英文需要更多呼吸空間）。

## 4. 間距、圓角、陰影

### 4.1 間距（8px 基準）

`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64`

| 用途 | 值 |
|---|---|
| 頁面左右留白（手機） | 16px |
| 卡片內距 | 16px |
| 卡片之間 | 12px |
| 區塊之間 | 24px |
| 大區塊之間 | 40px |
| 表單欄位之間 | 16px |

### 4.2 圓角

| 元素 | 圓角 |
|---|---|
| 卡片、圖片 | 12px |
| 按鈕、輸入框 | 8px |
| 標籤、徽章 | 999px（膠囊） |
| 底部彈出面板 | 上方 20px |
| 頭像 | 50% |

> **不要全部用同一個大圓角。** 「所有東西都 `rounded-2xl`」是 AI 生成介面的明顯特徵。

### 4.3 陰影

```css
--shadow-card: 0 1px 2px rgba(43,33,28,.06), 0 4px 12px rgba(43,33,28,.05);
--shadow-pop:  0 8px 24px rgba(43,33,28,.12);
```

只有兩級，而且都很淡。**陰影用暖黑（`43,33,28`）不要用純黑或藍黑。**
**禁止**：彩色光暈、發光效果、大面積模糊陰影。

## 5. 元件規範

前端只需要自己寫這 8 個元件，其他都由它們組合而成。**指定一位維護者**（工作分配定案後指派），放在 `src/components/`。

### 5.1 Button

| Variant | 樣式 |
|---|---|
| `primary` | `brand-600` 底、白字 |
| `secondary` | 白底、`brand-600` 1.5px 邊框與文字 |
| `ghost` | 無底、`ink-600` 文字 |
| `danger` | `bad` 底、白字 |

| Size | 高度 | 字級 | 左右內距 |
|---|---|---|---|
| `lg` | **52px** | 18px | 24px |
| `md` | 44px | 16px | 20px |
| `sm` | 36px | 14px | 14px |

- 主要行動一律用 `lg`（長輩友善）
- 全寬按鈕固定在底部安全區內（`padding-bottom: env(safe-area-inset-bottom)`）
- **狀態**：`hover` 加深 8%、`active` 縮放 0.98、`disabled` 降不透明度至 0.4 且游標 `not-allowed`、`loading` 顯示轉圈並停用

### 5.2 Card

白底、1px `border`、12px 圓角、`shadow-card`、16px 內距。可點擊的卡片 hover 時陰影升到 `shadow-pop`。

### 5.3 MenuItemRow（菜單品項列）★最常出現的元件

- 高度 ≥ 96px
- 左：照片 80×80、圓角 12px、`object-fit: cover`
- 中：名稱（h3）、描述（body-sm，最多 2 行省略）、價格（price）
- 右：`+` 圓形按鈕 44×44，或數量步進器
- **售完態**：照片 `filter: grayscale(1) opacity(.6)`、價格劃線、右上角 `danger` 膠囊標籤「售完」、整列 `pointer-events: none`

### 5.4 Stepper（數量步進器）

- `−` 與 `+` 為 44×44 圓形按鈕，數字區寬 48px 置中
- 數量為 0 時 `−` 變成垃圾桶圖示
- 按下有輕微縮放回饋

### 5.5 OptionCard（選項選擇）

- 單選：整張卡片可點，選中時 `brand-100` 底 + `brand-600` 1.5px 邊框 + 右側勾勾
- 複選：左側方形勾選框 24×24
- 右側顯示價差，0 元不顯示
- 高度 ≥ 56px

### 5.6 Badge

膠囊形、12px 字、`padding: 2px 10px`

| 類型 | 樣式 |
|---|---|
| 推薦／人氣 | `accent-500` 底、`text-900` |
| 預約優先 | `accent-500` 底 + 金色邊框 |
| 售完 | `bad` 底、白字 |
| 已出餐 | `ok` 底、白字 |
| 辣度 | 白底、`bad` 邊框與文字 + 辣椒圖示 |

### 5.7 Toast

畫面上方滑入、3 秒後自動消失、最多同時 1 個。成功綠、錯誤紅、一般深色。**不要用瀏覽器的 `alert()`。**

### 5.8 EmptyState / Skeleton / ErrorState

三態元件（見 `10-UI-UX規格.md` §1）。骨架屏用 `surface-2` 色塊 + 呼吸動畫，**不要用轉圈圈**。

## 6. 圖片

### 6.1 素材來源

| 來源 | 用途 | 授權 |
|---|---|---|
| [Unsplash](https://unsplash.com) | 店家形象、情境照 | 免費商用 |
| [Pexels](https://pexels.com) | 食材、菜色 | 免費商用 |
| [Foodiesfeed](https://foodiesfeed.com) | 食物特寫 | 免費商用 |

**搜尋關鍵字**：`hot pot`、`shabu shabu`、`taiwanese hotpot`、`beef slices`、`sliced meat platter`、`vegetable platter`、`asian restaurant interior`

> **注意**：要挑**亞洲／台式**的照片。搜 "hot pot" 會出現很多歐美 fusion 風格，用了會很出戲。

### 6.2 不要用 AI 生成食物照

AI 生成的食物圖在**筷子、蒸氣、湯汁反光、文字標籤**上幾乎一定會出錯，放大看就穿幫。真實照片免費且更好。
（AI 生成**背景紋理、圖示、插圖**是可以的。）

### 6.3 規格

| 用途 | 尺寸 | 比例 |
|---|---|---|
| 品項縮圖 | 320×320 | 1:1 |
| 品項詳情主圖 | 1200×675 | 16:9 |
| 分類封面 | 640×360 | 16:9 |
| 店家形象（首頁） | 1600×900 | 16:9 |

- 格式優先 WebP，退回 JPEG
- 縮圖 < 80KB、主圖 < 200KB
- 一律 `loading="lazy"`（首屏除外）
- **全部圖片要有 `alt`**

## 7. ★「不要有 AI 感」檢查表

> 這是本文件最重要的一節。每張設計稿完成後逐條檢查。
> AI 生成的介面之所以一眼就看得出來，是因為模型在沒有明確指示時，會退回訓練資料中最常見的那組預設值——而那組預設值就是 2019 年之後大量 Tailwind 教學文章的樣子。

### 7.1 十個必檢項目

| # | ❌ AI 感來源 | ✅ 我們的做法 |
|---|---|---|
| 1 | 頁面底色用純白 `#FFFFFF` | 用暖米白 `#FBF7F0` |
| 2 | 中性色用 Tailwind 預設的 `gray` / `slate`（偏冷偏藍） | 用暖灰 `#E6DED2` / `#6B5D54` / `#2B211C` |
| 3 | **靛藍到紫的漸層**（最經典的 AI 標記） | **全站禁用紫色與藍紫漸層**；漸層只出現在照片上的深色遮罩 |
| 4 | 標題用 Inter 或系統預設無襯線 | 標題用 **Noto Serif TC**（明體） |
| 5 | 「三張等寬圓角卡片並排」的功能區塊 | 菜單用**左圖右文的列表**；推薦區用**橫向捲動**；避免對稱三欄 |
| 6 | 所有元素同一個大圓角（`rounded-2xl`） | 卡片 12px、按鈕 8px、標籤 999px，**分層級** |
| 7 | 細線條通用 icon 當主視覺 | 主視覺用**真實食物照片**；icon 只在次要位置且統一用 lucide |
| 8 | 空泛的文案（「輕鬆點餐，美味享受」） | 具體：「掃桌號就能點，不用等服務生」「厚切 3mm，涮 8 秒最好吃」 |
| 9 | AI 生成的食物插圖 | Unsplash / Pexels 的真實照片 |
| 10 | 用 emoji 當 icon（🍲🔥✨） | 用 lucide 圖示或自製 SVG。emoji 在不同裝置長得不一樣 |

### 7.2 額外加分：三個「只有這家店有」的細節

AI 不會主動想到這些，加進去立刻有人味：

1. **手寫感的「今日推薦」木牌**：在菜單推薦區用木紋底 + 手寫字體的小標題
2. **鍋子形狀的載入動畫**：火鍋冒泡泡，不是通用轉圈
3. **售完的「印章」效果**：斜蓋在照片上的紅色方框印章「售完」，不是灰化了事

### 7.3 一句話原則

> **先做完設計決定，再打開 AI。** AI 是執行你的決定的工具，不是幫你決定品味的人。
> 這份文件存在的意義就是：讓你們在打開 Figma Make 之前，已經知道答案了。

## 8. 給前端的實作備忘

```jsx
// src/components/Button.jsx — 範例，其餘元件比照辦理
const styles = {
  primary:   'bg-brand-600 text-white hover:bg-brand-500 active:bg-brand-700',
  secondary: 'bg-white text-brand-600 border-[1.5px] border-brand-600 hover:bg-brand-100',
  ghost:     'bg-transparent text-ink-600 hover:text-brand-600',
  danger:    'bg-bad text-white hover:opacity-90',
};
const sizes = {
  lg: 'h-[52px] text-[18px] px-6',
  md: 'h-11 text-base px-5',
  sm: 'h-9 text-sm px-3.5',
};

export default function Button({
  variant = 'primary', size = 'lg', loading = false,
  disabled, className = '', children, ...rest
}) {
  return (
    <button
      disabled={disabled || loading}
      className={[
        'rounded-btn font-medium transition-all active:scale-[.98]',
        'disabled:opacity-40 disabled:cursor-not-allowed disabled:active:scale-100',
        'focus-visible:outline focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-brand-600',
        styles[variant], sizes[size], className,
      ].join(' ')}
      {...rest}
    >
      {loading ? '處理中…' : children}
    </button>
  );
}
```

**三個容易忘的細節**

1. `active:scale-[.98]` 讓按鈕有「按下去」的手感，成本一行
2. `focus-visible` 的外框是鍵盤操作的必要，不要用 `outline-none` 砍掉
3. `disabled` 時要同時關掉 hover 與 active 效果，否則看起來像還能按
