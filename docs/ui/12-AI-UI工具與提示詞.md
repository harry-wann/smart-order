# 12 AI UI 工具與提示詞

> 你問的兩件事：**哪些 AI 工具做 UI 很強**，以及**怎麼不要有 AI 感**。
> 第二個問題的答案在 `11-設計系統.md` §7，這裡講的是「怎麼把那份設計系統餵給 AI，讓它照做」。

---

## 1. 核心觀念：AI 是執行者，不是決定品味的人

AI 生成的介面之所以一眼看得出來，不是因為 AI 畫得醜，而是因為**你沒有給它決定**。沒有指定字體、色票、版面原則時，模型會退回訓練資料裡最常見的那一組——也就是靛紫漸層、Inter 字體、三張並排的圓角卡片。

所以正確的順序是：

```
① 先定設計系統（已完成 → 11-設計系統.md）
        ↓
② 把設計系統當成「憲法」寫進每一段提示詞
        ↓
③ 讓 AI 生成第一版視覺
        ↓
④ 挑一個定調，整理成 Figma 元件與樣式
        ↓
⑤ 前端「手寫」Tailwind 實作，AI 產出的程式碼只當參考
```

**第 ⑤ 步請務必照做。** 詳見 §5 的警告。

## 2. 工具比較

| 工具 | 最擅長 | 輸出 | 費用 | 給你們的建議 |
|---|---|---|---|---|
| **Figma Make** | 從一段文字產出可互動的原型，能把既有 Figma 元件貼進提示詞當參考 | Figma 內的 React 原型，可視覺編輯 | Figma 付費方案含額度 | **主力工具**。你們已經要用 Figma，一條龍最省事 |
| **Figma AI / First Draft** | 把生成結果整理成正規的設計稿與元件庫 | Figma 圖層 | 同上 | 搭配 Make 使用，定調後用它整理元件 |
| **Google Stitch** | 免費、可多方案快速比較 | HTML / CSS / Tailwind / React | 免費 | **比稿用**。同一段提示詞跑 3 次挑最好的 |
| **Vercel v0** | 產出乾淨的 React + Tailwind + shadcn 程式碼 | React 程式碼 | 免費額度 / $20 月 | **當程式碼參考書**，不要整包貼進專案（見 §5） |
| **Uizard** | 多畫面原型、手繪稿轉數位 | 互動原型 | 免費 / $12 月 | 時間不夠時用來快速鋪 20 個畫面的骨架 |
| **Motiff** | 內建 Material / Ant / shadcn 設計系統 | React / CSS | 免費 / $20 月 | 備選，生態較小 |

### 給你們的推薦組合

1. **Figma Make**（主力）— 生顧客端菜單頁與店家端桌況頁，挑一個定調
2. **Google Stitch**（免費比稿）— 同一段提示詞多跑幾次，看有沒有更好的版面想法
3. **Figma 本體** — 把定調結果整理成色票樣式、文字樣式、元件，其他 20 幾頁照著畫
4. **手寫 Tailwind** — 前端實作，v0 產出的程式碼只在卡住時當參考

**不要同時用超過兩個生成工具。** 每個工具的風格偏好不同，混用會讓 26 個畫面看起來不像同一個產品。

## 3. Figma Make 提示詞的五條規則

1. **第一段就把細節講完。** 補問越多次，偏離越遠。任務、情境、設計元素、行為、限制，一次寫清楚。
2. **一次只做一個畫面。** 「幫我做整個點餐系統」會得到一堆平庸的東西；「做菜單主頁」才會得到有細節的結果。
3. **用具體數值，不要用形容詞。** 寫「品項列高度 96px、照片 80×80」，不要寫「卡片大一點」。
4. **把色票與字體寫死在提示詞裡。** 這是壓制 AI 預設風格最有效的手段。
5. **明確列出禁止事項。** 「不要紫色漸層」「不要三張並排卡片」——負面指令對這類模型很有效。

另外：**把參考圖貼進提示詞**（Unsplash 找的台式火鍋店照片、你們畫的手稿）比任何文字描述都有效。

## 4. 可直接複製的提示詞

### 4.1 【設計系統區塊】— 每一段提示詞都要貼上這段

```
【設計系統 — 必須嚴格遵守】

語言：繁體中文（台灣用語，例如「加入購物車」不是「添加到购物车」）
產品：台灣中價位火鍋店的手機點餐系統

色彩（只能用這些）：
- 頁面底色 #FBF7F0（暖米白，絕對不要用純白 #FFFFFF）
- 卡片底色 #FFFFFF，邊框 1px #E6DED2
- 主色（主按鈕、價格、重點）#C8442E，按下時 #A63522
- 輔色（推薦徽章、標籤）#E8A33D
- 文字：主要 #2B211C／次要 #6B5D54／弱化 #9C8E84
- 成功（已出餐）#3F7A4E／警告 #D98324／錯誤與售完 #B3261E
- 嚴禁使用：任何紫色、靛藍、藍紫漸層、冷灰色

字體：
- 標題用 "Noto Serif TC"（思源宋體），字重 700–900
- 內文與按鈕用 "Noto Sans TC"（思源黑體），字重 400/500/700
- 內文最小 16px，品項名 18px，價格 20px 粗體，按鈕文字 18px
- 中文行高 1.75

形狀與陰影：
- 卡片與照片圓角 12px，按鈕與輸入框圓角 8px，標籤圓角 999px
- 陰影只用 0 1px 2px rgba(43,33,28,.06)，非常淡，不要發光效果
- 不要所有東西都用同一個大圓角

版面：
- 手機優先，畫布寬 375px
- 頁面左右留白 16px
- 主要按鈕高度 52px，所有可點擊區至少 48×48px

嚴格禁止：
- 三張等寬圓角卡片並排的區塊
- 用 emoji 當圖示
- 細線條通用圖示當主視覺（主視覺必須是食物照片）
- 任何漸層背景（照片上的深色遮罩除外）
- Inter 字體
- 空泛文案。要寫具體的句子，例如「厚切 3mm，涮 8 秒最好吃」
  而不是「精選優質食材，帶來極致享受」
```

## 5. ⚠️ 給前端的重要警告

**不要把 AI 生成的 React 程式碼整包貼進專案。**

原因：

1. **你們看不懂它寫了什麼。** 出 bug 的時候，五個人都不知道從哪裡改起——這在 demo 前一天是災難。
2. **它會帶進一堆你們沒學過的東西**：自訂 hooks、Context 巢狀、複雜的泛型工具、你們沒裝的套件。
3. **面試會問。** 「這段程式碼為什麼這樣寫？」答不出來比沒寫還糟。
4. **風格會分裂。** 每次生成的命名與結構都不一樣，26 個頁面會變成 26 種寫法。

**正確用法**：

| 用途 | 做法 |
|---|---|
| 定調視覺 | ✅ 用 AI 生成，看畫面就好 |
| 版面靈感 | ✅ 生 3 版比較，挑最好的結構 |
| 卡住時參考寫法 | ✅ 看它怎麼處理某個佈局，然後自己重寫 |
| 直接當產品程式碼 | ❌ **不要** |
| 產生 Tailwind class 字串 | ⚠️ 可以，但要逐行看懂再用 |

**折衷做法（推薦）**：AI 生成後，看著它的畫面，**自己用 Tailwind 重寫一次**。速度只慢 20%，但程式碼完全是你們的，而且過程中真的學會了 React。

## 6. 工作流程建議

| 週次 | 設計工作 |
|---|---|
| **W1** | 用 §4.2 的提示詞在 Figma Make 生 3 版菜單主頁 → 全組投票挑一版定調 → 在 Figma 建立色票樣式與文字樣式 |
| **W1 末** | 用定調版本建立 8 個基礎元件（Button、Card、MenuItemRow、Stepper、OptionCard、Badge、Toast、EmptyState） |
| **W2** | 生顧客端 P0 的其餘頁面（§4.3、§4.4）+ 結帳付款頁 |
| **W3** | 生店家端（§4.5、§4.6），店家端可以粗一點，重點在資訊密度 |
| **W4** | 預約與會員頁面（§4.7） |
| **W5** | 一致性檢查：把 26 個畫面並排看，統一間距、字級、圓角、按鈕樣式 |
| **W6** | 只修不加。截圖做簡報素材、錄操作 GIF |

> **一致性檢查（W5）是最容易被跳過、但最影響觀感的一步。** 把所有畫面放在同一張 Figma 畫布上並排看，10 分鐘就能抓出「這頁按鈕 48px、那頁 52px」這類問題。

---

## 7. 快速自檢：這個畫面有 AI 感嗎？

完成任何一張設計稿後，問自己這五題。**答錯任何一題就回去改。**

1. 頁面底色是不是純白？→ 應該是 `#FBF7F0`
2. 有沒有出現紫色或藍紫漸層？→ 應該完全沒有
3. 標題是不是無襯線字體？→ 應該是思源宋體
4. 有沒有「三張等寬卡片並排」？→ 應該改成列表或不等寬排列
5. 文案是不是空泛的四字詞？→ 應該是具體的、有人味的句子
